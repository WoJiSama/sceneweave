# AI 辅助与场景生成设计

本文保留 AI 与生成的设计基线。M0 几何版原型首轮验证完成；完整 M1 手工编辑器与 M2 AI 初稿/选区修改仍未开始。以下 AI 接口、限制和算法是后续实现要求，尚未实现或评测。产品范围见[产品定义](01-product.md)，文档及事务主定义见[场景文档契约](04-scene-document.md)。

M0 已有手工领域命令、严格校验、原子历史与本地保存，但 source=ai 明确拒绝；没有网关、provider、SceneBrief 编译器、生成器或 Worker。结构连通已校验，当前占地路径未实现，非空 pathChecks 或已设置的 minPathWidthMm 会拒绝。首轮证据见[M0 验证报告](13-m0-validation.md)，不能据此宣称本页 AI 质量用例通过。

AI 帮主持人提出布局、局部修改和备团文字；可编辑的完整 SceneDocument 始终是事实来源。AI 为可选能力，应用资源已可用时，离线创建、编辑、保存与 PNG 导出不依赖模型、网关或账号；断网冷启动另按 [技术架构](03-architecture.md) 验证。

## 1. M2 的三个任务

| 任务 | 输入与预期结果 | 实现边界 |
|---|---|---|
| 新场景初稿 | 根据描述提出房间用途、连接关系和摆设，生成可编辑地图 | 只向新场景或空场景生成；不覆盖已有地图 |
| 选区修改 | 修改选中的房间尺寸、连接、门位置、家具或文字 | 保持范围外对象与锁定内容，提交前展示差异 |
| 备团辅助 | 为指定地点生成线索、危险、互动点与描述 | 新文字默认仅主持人可见；不替主持人发布秘密 |

M2 不包含任意聊天代理、外部网页检索、代码执行、整本模组解析、自动执行连续改图循环、文生图或资产下载。自然语言任务需要超出当前操作范围时，返回清楚的原因与可用操作，不把需求伪装成已完成。

## 2. 模型、程序与主持人的职责

| 责任方 | 负责内容 | 产物 |
|---|---|---|
| 主持人 | 目标、选区、哪些约束必须满足、哪些内容能公开，以及是否采用建议 | 用户指令、固定约束、采用的依赖组 |
| 模型 | 解释自然语言、提出房间用途与关系、选择已提供的素材、撰写场景文字、解释建议 | SceneBrief 或领域操作提案 |
| 生成器 / 几何求解器 | 毫米坐标、房间边界、共享墙、门的归属、走廊与家具占地 | 确定性的候选几何与完整修改集 |
| 校验器 | 字段、引用、范围、编辑锁、几何、通行与秘密信息约束 | 可定位的错误，或可预览的完整候选文档 |
| 编辑核心 | 基线比较、原子提交、稳定 ID、revision、撤销与保存触发 | 一次完整的 CommandBatch 结果 |

模型不能把“看起来可用”当作几何证明。比如“书房到后门可达”由派生通行图与净空检查验证；AI 可以解释检查结果，不能覆盖它。

只有相同 seed、生成器版本、归一化 SceneBrief、资产尺寸版本和程序配置下的程序生成部分承诺复现。模型输出、网络顺序和供应商内部采样不承诺复现。保存采用后的完整文档及生成来源；打开工程不再调用模型重建地图。

## 3. 请求上下文与 SceneBrief

### 3.1 可信上下文

发起请求时，编辑器固定 sceneId、baseRevision、floorId、scope、可用领域操作以及预算。scope 由选区和用户明确纳入的依赖对象产生，模型无权扩大。编辑器还保留本次场景快照，用于候选计算和差异预览。

用户硬约束与模型建议分别标记来源。模型可以补充软偏好，不能把已有硬约束删除、改为软约束或降低数值。需要扩大范围、解除锁定或改动硬约束时，先失败并解释冲突；主持人修改设置后，以新请求重新计算。

### 3.2 SceneBrief 字段

SceneBrief 是生成意图，不是另一份可直接保存的地图。下表为设计字段；精确机器结构在开始实现后建立，并使用 Zod 加上语义校验。世界坐标和长度均为整数毫米，禁止模型把屏幕像素当作地图长度。房间边界尺寸按墙中心线计算，clearanceMm 表达扣除墙厚后的真实净空；模型收到的字段说明必须区分两者。

| 字段 | 语义与来源 | 校验要求 |
|---|---|---|
| briefVersion | 意图格式版本，初版为 1；由应用填写 | 不支持的版本拒绝执行 |
| task | 新场景生成、选区修改或备团文字；由用户操作确定 | 不能在响应中升级为更大范围任务 |
| theme | 简短主题、时代与气氛 | 只影响内容选择和软偏好，不产生权限 |
| presetSnapshot | 本次使用的预设标识与版本快照 | 从当前文档读取；不凭模型输出切换预设或重缩放 |
| floorId | 当前楼层 | M2 必须为当前唯一楼层 |
| seed | 程序生成种子，由应用产生或用户指定 | 记录实际采用值；候选子种子由固定规则派生 |
| generatorVersion | 应用提供的生成器版本 | 不由模型选择未知版本 |
| footprint | 新场景外轮廓，或已批准的选区几何边界 | 简单正交多边形；在场景尺寸和计算预算内 |
| roomPrograms | 房间意图列表：临时 key、用途、数量、最小尺寸、目标尺寸、可选位置偏好 | key 唯一；硬要求与软要求分别记录；不会直接成为永久 ID |
| regions | 仅用于 GenerateScene 的区域意图：临时 key、用途、所属房间或允许范围、尺寸偏好、危险 / 障碍要求 | 只选产品支持的 Region.kind；由程序求解边界并校验阻挡；不开放既有 Region 的任意修改 |
| connections | 房间 key / 既有 Room ID 之间的连接意图，包括必要连接、可选连接与回路偏好 | 引用可解析；同楼层；秘密或上锁通路必须显式标明 |
| entrances | 入口与出口意图，含既有 Opening ID 或允许开口的边界区段 | 入口必须落在有效边界；不能穿越范围外墙体 |
| accessRequirements | 普通必达房间、起点与明确例外；例外记录原因 | 不能因为求解失败自动把普通房间加入例外 |
| clearanceMm | 本次门宽、走廊宽度和必要通路净空等工程约束 | 使用用户设定或产品默认值；不冒充官方规则数值 |
| furnishing | 家具用途、密度偏好、单类数量与总数量上限 | 素材来自本次目录；不能堵住必须保留的通路 |
| narrativeHooks | 可选的线索、互动点、环境描述需求及其目标对象 | 默认只生成 gm 文字；不推导“玩家应已知道” |
| secrecyRequirements | 用户明确要求隐藏的新房间、通路、物件、区域和秘密门；使用临时引用及需求来源 | 应用核对来源，核心创建为对应 gm 几何或未揭示秘密门；不能用于修改既有可见性 |
| assetPalette | 本次允许的 AssetRef 及尺寸、标签摘要 | 由应用提供；模型不能添加 URL、文件路径或未知素材 |
| fixedAnchors | 既有入口、共享边、门窗位置、锁定物件等不可移动的锚点 | 从文档与选区派生；模型无权删除 |
| constraints | 每条含 constraintId、来源、硬 / 软级别、类型与参数 | 来源和硬约束由应用核对；错误必须指向具体 constraintId |
| budget | 候选数、房间 / 物件上限、计算时限、请求预算 | 由应用与用户设置确定；取应用上限与请求上限中的较小值 |

空缺的软偏好可以使用公开的产品默认值，并在提案中说明。缺少会决定可行性的输入，例如没有允许放置新房间的区域，应返回待补充条件；不能扩大地图范围来隐式补齐。

### 3.3 约束分层

| 层级 | 例子 | 失败处理 |
|---|---|---|
| 文档不变量 | 稳定引用、非自交房间、唯一共享墙、有效门归属、整数毫米 | 拒绝整个候选 |
| 用户与范围硬约束 | 六个主要房间、保留已有入口、选区边界、编辑锁、固定门宽、必达房间 | 有限重试后报告冲突；不降低要求 |
| 产品保密约束 | 不修改既有 visibility / Opening.revealed / Note.discovered / editLocked；新注记默认 gm | 拒绝相关提案，不能由“提高生成质量”覆盖 |
| 软偏好 | 厨房靠餐厅、走廊较短、书房远离入口、家具密度 | 用于候选评分；未满足项展示为取舍 |

门被上锁、密室尚未发现，与“墙体错误导致完全无入口”必须区分。校验器至少计算结构连接图与当前门状态下的可通行图：明确的上锁 / 秘密例外可以解释当前不可达，不能免除门确实存在、通道有净空等物理检查。

Room.accessExpectation 使用 unspecified、required、intentionalIsolation。手工新增房间默认 unspecified，允许还没画门的草稿；AI 生成的普通房间必须设为 required，并满足到任一指定入口的结构连通。明确的隔离区使用 intentionalIsolation 并记录原因；有真实连接的秘密或上锁房间可以保持 required，其当前不可通行例外另行说明。AI 不能把既有 required 改为 unspecified 或 intentionalIsolation 来躲避检查。

required 不要求默认处于 closed 的门自动打开。当前状态下可通行是独立的显式约束；家具 / Region 阻挡和通道净空也要单独检查。没有指定入口而声明了 required 房间的提案不合格，不能自行移除 required 来通过校验。

必要的具体路径检查记录为 constraints.pathChecks，包含端点、净宽和结构 / 当前通行模式。主持人可以明确允许检查时假设打开哪些门；该假设只影响检查，不修改 state 或 locked，模型不能自行扩大这一集合。

## 4. 领域操作白名单

操作表达业务意图，由本机编译成编辑核心支持的 CommandBatch。模型不能提交任意 JSON Patch、JavaScript、SQL、文件操作或网络调用。M2 不开放删除实体、全场替换、修改可见性、揭示秘密、修改编辑锁等操作。

每个操作具有 opId、operationType、params 和依赖信息。对新对象使用提案内临时引用，先校验唯一性和引用关系，再由编辑核心分配永久稳定 ID。既有对象使用当前快照中的稳定 ID，不能凭名称猜测。

| 操作 | 主要参数语义 | 编译及禁止条件 |
|---|---|---|
| GenerateScene | SceneBrief、新场景 / 空场景目标、模板偏好 | 只在没有既有几何或注记的目标生成；可已有 Floor、预设及素材目录；创建完整布局和 brief 内必要 Region；已有地图应另建场景 |
| AddRoom | 新房间临时 key、用途、尺寸约束、scope 内放置偏好、可选相邻房间引用 | 求解简单正交边界，复用共边；不与既有室内面积重叠；不得挤压范围外房间 |
| ResizeRoom | Room ID、目标宽深或边界偏移意图、固定边 / 固定点、需保留的 Opening ID | 校验共享顶点、相邻墙与开口；涉及邻室的实际修改必须在 scope 内；不允许隐式删除墙门 |
| ConnectRooms | 两端 Room 引用、连接方式、允许路线区域、最小净宽、开口宽度、必要 / 可选标志 | 相邻房间可建立开口；不相邻时可创建 purpose 为 corridor 的 Room 及两端开口；所有新增几何都在 scope 内 |
| MoveOpening | Opening ID、目标 Wall ID、offsetMm；widthMm 保持既有值 | offsetMm 从 Wall.startVertexId 量到开口近端；整个开口须位于墙段内；保留 kind、secret、revealed、state、locked 与 editLocked |
| PlaceProp | 素材目录中的 AssetRef、目标房间或位置意图、朝向、可选尺寸偏好 | 基于已批准的素材占地求解位置；不接受外部资源地址；校验家具之间及门前净空 |
| UpdateProp | Prop ID、位置 / 朝向 / 尺寸调整意图 | 只更新允许的变换；不能改变素材来源、可见性、编辑锁或碰撞语义以绕过检查 |
| AddNote | 目标 Room / Prop / Region / Opening 引用、注记用途、标题与正文 | 目标必须在 scope 内；创建 Note，线索使用 kind=clue；默认 gm；文字不执行为指令 |
| UpdateNote | 既有 gm Note ID、拟替换的标题与正文 | 显示逐项文字差异；保持 visibility、discovered、anchor、kind 与 editLocked；不能直接更新 public 注记 |

上述字段是领域语义约定，具体类型名和数据形状由 [场景文档契约](04-scene-document.md) 统一。模型返回未知操作或额外权限字段时，明确报错，不悄悄忽略后显示“已完成”。

GenerateScene 是受约束的组合操作，编译器可以依据 regions 生成必要的 Region，例如 SCN-02 的坍井危险 / 阻挡区；它不必把底层每个实体映射成一个开放给模型的独立工具。M2 仍只有上述 9 项操作，不增加 AddRegion、UpdateRegion 或任意区域补丁。已有场景的区域由手工编辑，或在局部 AI 操作中作为只读碰撞与通行约束使用。

ConnectRooms 对新门的连接意图可以包含用户需求中的秘密通路或上锁例外；核心负责按文档策略创建未揭示的秘密门，并保留必要的显示遮罩。模型不能改变既有门的 secret、revealed、state 或 locked。“编辑锁”使用 editLocked，“门被上锁”使用 Opening.locked，校验错误必须说明具体对象和限制。

普通新增 Room / Prop / Region 的几何默认 public；用户明确要求隐藏的新增房间或通路，由核心按 secrecyRequirements 创建为 gm，不能先按 public 创建再依赖秘密门遮蔽。放进 gm 房间的新增物件沿用 gm 保护，不因默认值显露内部布置。新秘密门为 secret=true、revealed=false；开启该门或后来揭示它都不改变关联房间和注记的可见性。必要的玩家遮罩仍按 [存储与导出](06-storage-and-export.md) 校验，不能仅靠模型一句“已隐藏”认定玩家图安全。

改写既有 public 注记时，模型只能通过 AddNote 提供新的 gm 草稿，主持人阅读后再明确发布。单纯保留 visibility 字段无法防止 gm 来源混入公开正文，因此 M2 的 UpdateNote 只接受原本就是 gm 的目标。

## 5. Proposal、依赖组与原子采用

### 5.1 Proposal 的内容

| 字段 | 要求 |
|---|---|
| proposalId | 由受信任的请求协调层分配；标识一次具体提案 |
| requestId | 本次用户发起请求的标识；取消、去重与响应归属均使用它 |
| sceneId / baseRevision | 请求时的场景与修订号；不接受模型篡改 |
| scope | 本次授权的实体集合与几何范围；不接受模型扩大 |
| operations | 仅来自白名单；包含 opId、参数与临时对象引用 |
| dependencyGroups | 由本机根据实际读写集合、临时引用与不变量推导，模型建议仅供参考 |
| explanation | 供主持人阅读的修改理由，不具有执行权限 |
| validationResult | 本机校验结果、约束错误与软偏好取舍；不能用模型自评替代 |
| generationMetadata | seed、生成器版本、程序参数摘要、provider / model 标识及来源；不含 API 密钥 |

### 5.2 依赖组选择

用户按可独立成立的依赖组采用建议。一个“新增通道”通常同时包含新 Room、墙、两端门及必要顶点关系；不能只选通道地面而遗漏出口。共享顶点、共享墙重挂和由此受影响的 Opening 必须处在同一原子依赖闭包内。

本机编译器负责以下步骤：

1. 解析临时引用，计算操作及隐含几何修改的读写集合。
2. 将互相依赖或共同维护不变量的修改合并为组，拒绝无法解释的循环引用。
3. 用户选择某组时，同时包含其前置组；界面显示将一并采用的内容。
4. 重新计算所选组合的整体几何、净空和连通性。两组单独通过不意味着合并后仍通过。
5. 根据实际组合生成最终差异预览。变更组合使旧预览失效，须等待重新校验。

GenerateScene 的结构布局是一个整体依赖组；可选装饰和文字只有在移除后仍满足全部硬约束时才能独立选择。缺少用户硬要求的初稿不能通过“取消勾选失败部分”成为可采用结果。

M2 一次 Proposal 只有一次采用：用户选择的组原子提交后，其余组随该 Proposal 关闭。若还要采用剩余建议，需要在新 revision 上重新生成并预览，避免把旧基线操作继续套用。

### 5.3 CommandBatch 提交

最终采用遵循 [场景文档契约](04-scene-document.md) 的 CommandBatch，包含 batchId、sceneId、baseRevision、operations、scope、source、origin 和 label。source 取 ai；origin 记录 requestId / proposalId；label 提供撤销描述。不能把请求对象塞入 source 枚举，执行路径与手工操作共用。

提交入口依次核对当前 sceneId 和 baseRevision、范围及编辑锁、完整文档不变量与已选组约束。然后以不可分割事务替换当前文档状态，并产生一次撤销记录。成功提交 revision 加一；任何一步失败都不留下部分房间、门或文字。

拖动暂态、AI 预览和流式文本不进入 SceneDocument。应用前发现空操作集时，只提示“没有需要应用的变化”，不制造一次提交。撤销 / 重做恢复对应文档内容，同时各自产生新的递增 revision；不能把 revision 改回旧值来复用提案。

## 6. 状态机、冲突与失败

正常流程为 requesting → proposed → validating → ready → applied。其余状态为 failed、cancelled、stale、rejected。状态属于本次请求及其 Proposal；新的用户重试产生新的 requestId。

| 状态 | 含义 | 后续处理 |
|---|---|---|
| requesting | 已固定基线与范围，正在等待模型响应 | 返回允许的结构后进入 proposed；网络错误进入 failed；可取消 |
| proposed | 获得结构化提案，但尚未证明可执行 | 进入 validating；此时不能点“采用” |
| validating | 正在编译、运行几何候选和计算差异 | 全部硬门槛通过后进入 ready；预算耗尽或违规进入 failed |
| ready | 所选依赖组已通过校验，显示了最终差异 | 主持人采用并再次核对基线后进入 applied；改选依赖组返回 validating |
| applied | 原子提交成功，revision 已增加 | 本次请求终结；撤销走编辑核心，不回退本状态 |
| failed | 连接、响应结构、生成预算或校验失败 | 显示原因与可调整项；手工编辑仍可用；重试为新请求 |
| cancelled | 用户取消，或离开场景 / 主动停止该任务 | 终止请求和 Worker；丢弃后到结果；现有文档不变 |
| stale | 当前 revision 已不同于 baseRevision | 旧提案不能采用；按当前文档重新生成 / 计算并展示新预览 |
| rejected | 主持人明确放弃建议 | 丢弃预览，本次请求终结；现有文档不变 |

在 applied 之前，取消可以使活动状态进入 cancelled；明确放弃提案可以从 proposed、validating、ready 进入 rejected。任何文档提交，包括手工修改、导入、撤销和重做，都使同一场景旧 baseRevision 的活动提案进入 stale。选择、平移、缩放等视图变化不递增文档 revision，也不自动废弃提案。

相同 sceneId 同时只允许一个活动 AI 请求。重新发起前取消旧任务。即使旧网络响应或 Worker 消息在取消后到达，也必须同时匹配 requestId、任务代号和当前非终结状态才会被处理。取消只能阻止本地采用，不能承诺供应商停止已发生的计费。

如果请求已应用后才收到重复采用信号，按已记录的 requestId / proposalId 返回现有结果，不重复修改；若用户已撤销，旧提案仍不能再次使用。应用入口的基线比较必须和提交处于同一同步事务，不能“先检查、稍后再写入”。

### 6.1 错误信息

错误应包含稳定的 errorCode、可读消息、相关 opId / constraintId / 实体 ID、可恢复性及下一步。典型错误包括范围不足、对象已锁定、共享墙依赖缺失、门超出墙段、必达房间不可达、预算耗尽、模型响应结构不符、供应商不可用和基线过期。

例如：“书房北墙与走廊共用；当前范围未包含走廊，无法向北扩展。可改为向书房内部调整，或重新选择书房和走廊后生成。”不要将这类失败归为笼统的“AI 出错”。错误内容只用于提出下一次修改建议，不能自行修改 scope。

### 6.2 有限重试

| 情况 | M2 默认策略 |
|---|---|
| 几何候选不满足硬约束 | 每次请求最多计算 3 个候选；选择满足硬约束者，再比较软评分 |
| 模型响应缺字段、未知操作或格式错误 | 本次失败；展示简短原因，用户可重新生成；不自动增加付费的“自我修复”轮次 |
| 连接在发送前失败，或明确收到可重试的限流 / 暂时不可用响应 | 在总期限与预算内最多 1 次网络重试；遵守供应商重试提示；候选与请求计数可见 |
| 已发送后超时、连接断开且无法确认供应商是否处理 | 不盲目重发；失败并说明结果未取得，用户决定是否发新请求 |
| 基线过期、范围或编辑锁冲突 | 不自动重试；基于当前场景新建请求并重新预览 |

网络最多 2 次发送、几何最多 3 个候选是两种独立上限，并共同受整次任务期限限制。自动重试不重置预算，不能通过循环嵌套突破限制。每个失败候选保留约束摘要用于解释，不把完整隐私内容写入日志。

## 7. 首版布局算法

### 7.1 房屋：用途模板与受约束的 BSP

首版从矩形或少量正交外轮廓起步，使用原创用途模板确定入口、交通空间、公共房间与私密房间的相对关系。模型建议房间用途和相邻关系，程序选择模板并完成具体布局。

1. 保留用户指定的外轮廓、入口、固定边与必要通路。
2. 根据硬性最小尺寸，给交通空间与重点房间分配保底区域。
3. 对可分割区域执行受约束的 BSP 切分；每次切分检查两侧房间的宽深和面积可行性。
4. 将房间用途映射到分区，按用途相邻性、采光边偏好、动静分区和走廊长度评分。
5. 建立共享顶点 / 墙，安排普通开口、明确的秘密连接与必要例外。
6. 放置家具并校验通路。若家具影响硬性通行，优先调整可选家具；不能移动锁定物件或缩小净宽。

程序不得把 BSP 任意切分当作有用住宅。厨房与餐厅的关系、主要空间是否被迫穿过卧室、入口是否直接撞到家具等，需成为可解释的约束或评分项。无法满足“六个主要房间 + 固定尺寸 + 当前外轮廓”时，应报告容量冲突。

### 7.2 地下城：房间、走廊与回路

先形成房间关系图，再在允许范围内放置房间。普通必达房间建立连通骨架；走廊采用占用栅格上的 A* 或同类确定性搜索，最后转换为整数毫米的正交多边形并执行精确几何校验。

新增回路以改善探索路线为软目标：从尚未相连的房间对中，优先选择能减少过长折返、且不穿越锁定 / 范围外区域的路线。先按固定排序选候选，再使用 seed 决定平分项；避免容器遍历顺序影响结果。回路数量受 SceneBrief 与预算限制，找不到可行路线时展示未满足的软偏好；如果用户将回路设为硬要求，整个候选失败。

走廊也是 Room，使用 corridor 用途标记，因此共享墙、开口、遮罩和保存逻辑与普通房间一致。不能只在图片上画一条线，并把它当成真实连通关系。

占用栅格用于寻路加速，不是最终空间真相。障碍应保守扩张到必要净空，最终再检查实际边界、门宽及转角。规划栅格精度无法表达本次最窄通路时，拒绝该配置或在预算内提高精度；不能缩小用户设定的净空来凑出路线。

### 7.3 装饰与文字

先放置决定用途的大物件，再放小装饰。素材包提供可信的毫米占地与允许变换，模型提供类别和用途偏好。放置时为门前净空、关键交互点与通行路径保留空间；首版不计算门扇扫掠碰撞。装饰密度不足属于软质量问题，堵住唯一出口属于硬错误。

文字挂接到稳定对象 ID。新生成的主持人线索、玩家描述草稿都先以 gm 注记保存；“玩家描述”是内容用途，不自动等于公开权限。实际发布与导出见 [存储与导出](06-storage-and-export.md)。

M2 优先支持房屋与地下城生成。开放营地在 M3 使用 Region、Prop 与既有编辑能力验证；自然洞穴生成、河流地形和城镇路网不在这一算法的承诺范围。

## 8. 已编辑场景的局部重生成

“重新生成书房”在 M2 的含义是：在批准范围内重新求解受支持的领域操作，保留已有稳定对象和必须保留的内容。M2 不提供删除并替换整片已有地图的能力，也不把某个 seed 的旧结果恢复为用户当前地图。

局部计算把区域分为修改内部、固定边界和只读邻接上下文：

- 修改内部：主持人选入且未锁定的对象，以及允许放置新实体的空间。
- 固定边界：选区外轮廓、必须保持的墙段 / 顶点、保留的门窗与连接锚点。
- 只读邻接上下文：为碰撞与连通检查读取的邻室边界、开口、必要通道；读到不代表允许修改。

涉及共享顶点、共享墙或 Opening 重挂时，先计算完整影响集合。任一实际修改落到范围外，候选失败；只有主持人重新纳入依赖后才可重算。不能复制一份共享墙来绕过范围限制。

对每个 ready 候选检查：范围外对象序列化内容不变，锁定对象不变，固定锚点不变，必要入口可达，原有注记目标引用有效。这里的“序列化内容不变”排除应用层新增的整体 revision 和明确的生成来源记录，其余对象字段不得悄悄重写。

无法通过 M2 白名单完成的请求，例如“删除所有家具重布置”或“彻底改变书房与走廊拓扑”，应明确说明当前限制，并给出可行的移动 / 增补建议。日后开放删除需要另行定义依赖迁移、秘密状态保护与撤销语义。

## 9. Worker 取消与计算预算

布局、通行图、批量碰撞与候选验证在 Web Worker 执行。主线程保留交互、临时预览与最终提交控制。Worker 只计算候选，不直接写 IndexedDB、操作文档状态或调用外部网络。

以下是 M0 / M2 拟验证的初始保护上限，属于配置和失败边界，不是性能实测结果：

| 项目 | 初始设计 |
|---|---|
| 活动生成任务 | 每个编辑会话最多 1 个；同场景请求串行 |
| 候选数 | 最多 3 个；同一请求共用预算 |
| 单次新增房间 | 最多 32 个，含走廊；用户更小上限优先 |
| 单次新增物件 | 最多 500 个；文本数量另设上限 |
| 寻路栅格 | 单候选最多 200 × 200 单元；精度须同时满足净宽约束 |
| 寻路搜索 | 单候选累计最多 200,000 次节点展开；到达即报告预算耗尽 |
| 计算时限 | 单候选最多 2.5 秒、整次 Worker 计算最多 8 秒；只统计本地计算阶段 |
| 取消检查 | 在有界循环批次检查任务代号与取消信号；每批最多 256 次搜索展开，并安排让出执行机会 |
| 强制终止 | 主线程取消后 500 毫秒内未确认，终止该 Worker 并新建空闲 Worker；超时兜底最迟 10 秒终止 |
| 临时数据 | 用固定栅格上限与对象数量限制分配；不依赖浏览器精确报告进程内存 |

实际时间由浏览器调度影响；计时和取消检查不能替代主线程 watchdog。预览结果必须包含 requestId、任务代号与 baseRevision；旧消息即使结构正确也丢弃。取消后，任务不能写入缓存以外的任何持久业务状态。

当预算不足时返回部分诊断与可调整建议，不把未完整校验的局部地图标为 ready。扩大预算需要新的明确设置，不能在当前任务中自行移除上限。

## 10. 模型供应商能力与选择

provider 适配层负责统一鉴权、结构化输出、取消、超时、用量、错误和响应解析。不会在领域模型中写死模型品牌或“最新模型”名称。M2 先接入一个通过固定场景评测的 provider；本地模型通过同一契约评估后加入。

| 能力 | M2 要求 | 缺失时 |
|---|---|---|
| 中文需求与对象引用 | 正确理解选区、保留条件、否定条件与场景用途 | 评测失败则不进入默认候选 |
| 受约束结构化输出 | 能稳定返回限定结构；本机仍完整校验 | 不将纯自由文本作为可执行提案 |
| 响应大小与输出限制 | 能设置 token 上限，网关额外限制字节数 | 超出即取消并失败 |
| 取消 / 超时 | 尽可能中断请求；结果仍受 requestId 门控 | 不支持远端取消时注明可能继续计费 |
| 用量与成本 | 优先返回 token 用量；成本依据已知费率估算 | 标记未知，不显示伪精确金额 |
| 错误类型 | 区分鉴权、限流、服务不可用、超时、结构错误 | 归一化为保守失败，不盲目重试 |
| 本地模型 | 满足同一操作、隐私和预算契约 | 不因运行在本机而降低校验标准 |

原生 tool calling 可用于传输白名单操作，但工具的效果仍是“返回提案”；不能把 provider 的工具调用直接连到编辑器 mutation。首版不要求模型自动使用多轮工具，也不要求使用隐式思维链或把其内容写入日志。

评测使用 [固定样例](08-test-scenarios.md) 中的 SCN-01 雾灯宅、SCN-02 灰井遗址与 SCN-03 风桥营地的备团文字 / 支持操作，以及 [质量计划](09-quality-plan.md) 的失败场景。M2 地形生成支持范围外的任务只评估其正确拒绝或转为支持操作的能力。

各候选模型使用相同提示、素材目录、约束和程序生成器。记录结构通过率、硬约束违规的拦截率、可采用率、局部修改命中率、人工修正次数、中文意图保留、延迟和用量。软质量由主持人盲评可玩性与用途合理性。硬违规被提交的次数必须为 0；不能把“模型第一次提出了违规建议”与“系统让违规改图生效”混为一个指标。

M0 先确定测量方法与支持的结构化输出方式，M2 再记录具体 provider、模型标识、日期、配置和重复次数。未有测试证据前，不声称某模型最适合本项目。

## 11. 最小本机网关契约

### 11.1 部署与信任边界

可选网关采用 Node.js + Hono，首版面向本机编辑器。仅绑定 127.0.0.1；需要 IPv6 时显式增加 ::1。禁止默认绑定 0.0.0.0、局域网地址或公网。端口与允许的编辑器 Origin 在本机配置中明确设定；协议、主机名、端口均精确匹配，不使用通配 Origin 或反射请求 Origin。

网关检查 Host 为允许的 loopback 主机名 / 字面地址及预期端口，阻止借任意域名访问本地服务。除最小健康检查外，浏览器请求同时要求允许的 Origin 与有效会话凭证。拒绝缺失 / null Origin 的浏览器业务请求；不把 CORS 当成唯一鉴权。预检只返回白名单方法和请求头。

首次配对在本机启动界面显示一次性配对码，由用户输入编辑器；配对码短期有效并限制尝试频率，不放进 URL、网页源码或日志。配对成功后发放随机会话令牌，编辑器仅放内存，通过 Authorization 请求头发送。会话闲置 30 分钟或绝对 8 小时失效，网关重启失效；重新加载编辑器需重新配对。首版不用浏览器持久化 token 或跨站 cookie。

首版 AI 支持范围为已验证的本机页面与本机网关组合。公网 HTTPS 页面访问 loopback 可能受到浏览器混合内容和私网访问策略限制，需未来独立验证，不指导用户关闭浏览器安全设置。可用的静态编辑器仍可在关闭 AI 时运行。

### 11.2 路由

| 方法与路由 | 输入 | 输出与行为 |
|---|---|---|
| GET /v1/health | 无业务数据；仍检查 Host | protocolVersion、可用状态；不暴露配置、provider 明细、密钥或路径 |
| POST /v1/session | 配对码、客户端协议版本；检查 Origin，限频 | 内存会话令牌与过期信息；配对码单次使用 |
| DELETE /v1/session | 当前会话令牌 | 注销会话，取消该会话未完成的请求 |
| GET /v1/providers | 会话令牌 | 已配置 provider / model 的显示标识、能力、可用性及可用预算；不返回密钥和完整私有配置 |
| POST /v1/proposals | 下表请求字段 | 校验后接收任务，返回 requestId 和 requesting；结构不合格直接报错 |
| GET /v1/proposals/{requestId} | 当前会话及所属请求 ID | requesting、proposed、failed 或 cancelled，以及响应字段；只读该会话的请求 |
| DELETE /v1/proposals/{requestId} | 当前会话及所属请求 ID | 尽力取消 provider 请求，记录 cancelled，后到响应丢弃；重复取消幂等 |

网关没有“应用地图”路由，也不能读写 SceneDocument 存储。网关的 proposed 只表示收到并初步检查了模型提案；validating、ready、stale、rejected、applied 由编辑器依据当前文档决定。M2 可以使用有上限的退避轮询读取结果；流式自然语言不作为执行输入。

### 11.3 请求字段

| 字段 | 校验与处理 |
|---|---|
| protocolVersion | 支持的网关协议版本，初版为 1 |
| requestId | 客户端产生；同会话内去重 |
| sceneId / baseRevision | 用于归属和返回核对；网关不据此访问文件或数据库 |
| providerId / modelId | 仅可选择本机预配置的条目；不接受调用方提供 endpoint、代理地址或凭据 |
| task | 三种 M2 任务之一 |
| instruction | 用户本次的自然语言需求，限制长度 |
| brief | 已有的结构化 SceneBrief 或用户明确给出的部分约束 |
| sceneContext | 经过发送预览的最小对象摘要、几何与素材目录，不是完整工程附件 |
| scope / fixedConstraints | 编辑器固定的修改范围与不可降低的约束；响应不得扩大 |
| allowedOperations | 客户端本次开放子集；与网关内置白名单取交集 |
| budget | 输出 token、响应大小、总期限与允许网络重试；与网关硬上限取较小值 |
| locale | 内容语言偏好，不影响鉴权与领域操作名称 |

同一会话重复提交同 requestId 且规范化请求内容一致时，返回已存在的任务，不再次发送 provider 请求；内容不同返回冲突。结果正文过期后仍保留该会话内的 requestId、请求摘要和终结状态，重复读取返回“结果已过期”，不能重新派发。这个保证只覆盖当前网关进程，不承诺 provider 端的跨重启幂等。任务被取消、超时或完成后，人工重试使用新的 requestId。

### 11.4 响应字段

| 字段 | 含义 |
|---|---|
| protocolVersion / requestId | 对应请求协议与任务 |
| status | requesting、proposed、failed 或 cancelled |
| proposalId | 由协调层生成的标识；proposed 时存在 |
| sceneId / baseRevision | 从原请求上下文复制，不能使用模型伪造值 |
| proposal | 结构化 SceneBrief / 领域操作、文字解释；还需编辑器完整校验 |
| providerId / modelId | 实际使用的标识，不接受模型自行报告 |
| usage | 供应商返回的输入 / 输出用量；未知字段省略或显式未知 |
| estimatedCost | 有费率依据时附金额、币种、费率日期；否则未知 |
| timing | 开始时间、持续时间及网络尝试次数 |
| error | 稳定错误码、脱敏说明、可重试性；不得包含凭据或整段供应商原始日志 |

初始网关限制设计为：请求体最多 1 MiB、模型响应累计最多 1 MiB、指令最多 16,000 个 Unicode 字符、单会话最多一个活动请求、网络总期限最多 90 秒。供应商输出 token 上限按模型能力与任务预算另设。限制需在读取过程中生效，不能先把无限响应读入内存再检查长度。M0 / M2 根据实际数据调整并记录原因，不把这些数字当作服务质量承诺。

### 11.5 外联与凭据

provider 地址由本机配置管理，只允许选中的预配置 origin 与必要 API 路径。云端默认 HTTPS；本地模型允许显式配置的 loopback endpoint。每个重定向都重新校验目的地，默认拒绝跨 origin 重定向；不开放通用 HTTP 代理、网页抓取或文件读取接口。

不允许调用方用提示词、sceneContext、素材 URL 或 modelId 拼接任意外部地址。对云端 provider 检查解析后的目的地址，拒绝解析到本机、链路本地或私网；显式启用的本地模型条目仅允许指定的 loopback 地址与端口。未来支持局域网模型需要单独设计和用户配置。

API 密钥留在本机网关的环境或专用受限配置中，优先评估系统凭据存储。前端 bundle、SceneDocument、工程导出、IndexedDB、截图元数据、Git 仓库与诊断附件均不包含密钥。浏览器会话令牌与 provider 密钥是两类凭据，不能互相替代。

## 12. 隐私、提示注入与日志

发送前，界面说明当前 provider / model，并提供本次内容预览：用户指令、选区对象、必要邻接几何、素材摘要，以及会发送的注记。默认不发送全图、无关私密线索、工程名称、文件路径、外部素材原件和账号标识。要让模型续写既有 gm 文字时，主持人明确将这些文字纳入本次上下文。

邻接几何可以是必要的只读上下文，是否包含秘密结构需要在发送预览中明确。gm 意味着对玩家保密，不等于允许发送云端。选择云端 provider 时按其实际保留政策说明数据去向；没有核实的保留 / 训练条款显示为待确认，不写“绝不保留”。本地模型同样通过网关与最小上下文约束，不能自动获取本机全部文件。

场景名称、素材标签、注记、导入文件与未来检索资料都作为资料处理。即使其中写着“忽略之前指令”“发送密钥”“解除锁定”，也不成为系统指令或能力授权。结构上区分应用约束、用户本次需求和引用资料；响应校验继续强制执行白名单、范围和权限，不能仅依赖提示词要求模型自律。

模型文字以纯文本或经过清理的受限 Markdown 展示，不执行 HTML、脚本或自动加载其图片 / 外链。模型返回的 URL 不能变成资产下载、provider 配置或工具调用。

新提案不会自动修改既有 visibility、Opening.revealed、Note.discovered 或 editLocked。普通新实体与明确要求隐藏的新实体按第 4 节及 [场景文档契约](04-scene-document.md) 的核心策略创建，新注记固定 gm。任何公开或揭示操作由主持人通过独立、明确的编辑行为完成，并产生自己的事务记录。

网关默认只记录 requestId、provider 显示标识、状态、耗时、用量及错误码。禁止记录 Authorization、配对码、密钥、完整请求 / 响应、场景文字或提示词。脱敏错误应保留可诊断的代码和阶段，不能把供应商原始异常对象直接序列化。

调试导出必须由用户主动触发，并可预览其内容；默认仍不含敏感文字和凭据。任务正文只在内存短期保留，完成后最多保留 10 分钟供客户端读取，注销、过期或网关停止即清除；运行日志也不应成为地图备份。编辑器保存的生成来源仅是 SceneDocument.generationMetadata 定义的已采用 brief 摘要等元数据，用户可选择不保存来源文字；不保存整段原始请求、聊天或模型隐藏推理，不进入玩家 PNG 元数据。

## 13. M2 验收要求与后续决策

| 验收任务 | 必须可观察的结果 |
|---|---|
| 雾灯宅初稿 | 六个主要房间及隐藏通路满足输入约束，图中对象可逐个编辑；未通过校验时无法采用 |
| 灰井遗址初稿 | 坍井由 GenerateScene 编译为 Region，危险标签与阻挡分别校验；模型不能借此修改既有区域 |
| 只改书房 | 指定门窗和范围外对象保持原值；共享墙影响超出范围时明确失败 |
| 采用一部分建议 | 自动包含必要依赖；组合重新校验；一次采用对应一次撤销 |
| 等待期间手工改图 | 提案进入 stale，采用入口无法绕过 revision 检查 |
| 取消与迟到响应 | 取消后地图无变化，迟到网络 / Worker 结果不能恢复旧预览或提交 |
| 三次候选都失败 | 返回约束冲突或预算原因；不降低门宽、房间数量或秘密保护 |
| 恶意注记或素材标签 | 只作为数据，不能扩大 scope、执行脚本、下载资源或泄漏凭据 |
| 改写玩家可见文字 | 生成 gm 草稿；UpdateNote 指向 public 目标时被拒绝，不把模型接触过的秘密自动写进公开正文 |
| 非授权网页访问网关 | Origin、Host、配对与会话检查生效，不能借本机网关使用密钥 |
| 保存、重开与撤销 | 完整采用结果往返保留；不依赖模型重新生成；revision 不倒退 |
| 关闭网关 | 手工编辑、保存和 PNG 导出保持可用 |

详细测试编排、数据规模和证据要求以 [质量计划](09-quality-plan.md) 为准。M0 核实几何、计算预算和协议边界，M2 确定具体 provider / model、模板与 BSP 的实际规模及生成参数；这些事项记录在 [决策与未决事项](11-decisions-and-open-questions.md)。文生图、检索规则、删除 / 替换式局部重生成和批量自动改图需要后续独立设计，不在 M2 验收中默认承诺。
