# AI 素材生成、同化与可选场景生成设计

状态：2026-10-21 文档方向调整。M1-C/C0已实现视口与有限性能基础，证据见[22](22-m1c-c0-validation.md)；C1a空白创作与单件放置已实现，证据见[23](23-m1c-c1a-validation.md)。C1b批量选择与有限批改/菜单已实现，适用验证归[24](24-m1c-c1b-validation.md)；图层、命名快照及局部恢复等后续手工能力仍按[07](07-roadmap.md)推进。**本页所有AI任务、provider、网关、生成与同化流程均未实现、未评测。** M0至C1b的手工工具证据不证明AI或其他新交互已通过。

本次将 AI 的主要价值调整为制作和统一素材外观：先修改或生成一个组件，确认风格后扩展到组合，再由用户逐步扩大到多个组合、选区或图层。原来的可选 A1 新素材制作并入 M2 主线；原 AI 地图布局、自动布景和备团文字保留为可选 M2-L，不阻塞 M3 团测与 M4 适配。AI 仍是用户可关闭的能力；参数调整路径无需调用模型，手工编辑、保存与 PNG 导出不依赖 AI 服务。

阶段和任务以[07](07-roadmap.md)为主，产品需求见[01](01-product.md)，视觉与素材规范见[14](14-visual-and-asset-system.md)。持久化字段、格式演进和恢复契约由[04](04-scene-document.md)、[06](06-storage-and-export.md)定义；本页的任务结构是设计语义，不允许把新增来源、图层或快照字段直接塞入当前严格 v1/v2。实施前须冻结所需版本与完整迁移。

## 1. M2 主线与职责

| 切片 | 用户任务与交付 | 范围边界 |
|---|---|---|
| M2-A：单素材生成与同化 | 生成新物件/可平铺材质，或基于默认/用户素材制作风格变体；对比、入库，再单独采用到选中对象 | 原素材及旧固定版本保留；只改变明确列出的外观字段；候选、入库与场景采用分别校验 |
| M2-B：组合同化 | 以已确认的单组件风格为基线，逐成员调整一个组合，预览成员差异并采用 | 保留组合和成员稳定身份、独立可编辑性及人工覆盖；不压成一张组合图片 |
| M2-C：渐进扩围 | 由用户明确选择下一组组合、选区或图层，分批采用统一风格 | 每批新 scope、新基线、新预览及快照；不沿邻接、同名素材或主题关系自动扩散 |
| M2-L：可选布局与文字 | 新地图结构、目录内自动布景、选区布局修改及备团文字 | 独立立项和验收；原 11 个地图操作仅在第9节适用，不授予素材模型结构编辑能力 |

M1-C 先提供可独立使用的参数变体、图层范围和恢复基础；M2 在同一事务与资源管线上接入图像候选。允许修改色调、线条、材质质感等视觉特征，不把换风格解释为修改真实尺寸、占地、支撑、高程、通行、门状态、秘密或编辑锁。新增素材的物理默认值由人工标定；既有实例的物理值不从新图像推断。

| 责任方 | 负责内容 | 不能代办的决定 |
|---|---|---|
| 用户 | 选源资产、参考、目标风格、允许修改字段、目标范围、预算、采用与扩围 | 预览确认不是授权模型继续修改邻域或共享目录 |
| 图像模型 / 参数引擎 | 在受限输入内产出图像候选或可复现的外观参数结果 | 不写场景、不发布素材、不猜测物理语义、不扩大权限 |
| 素材处理与入库器 | 解码、透明边缘/平铺检查、方向与色彩处理、hash、固定版本及来源依赖 | 入库不自动替换任何场景实例 |
| 本机校验器 | 候选与资源预算、来源、版本、范围、锁、人工覆盖、秘密及完整依赖 | 模型自评和图像观感不能替代校验 |
| 编辑核心 / 仓库 | 基线比较、原子采用、递增 revision、撤销、保存和局部恢复 | 旧提案不能覆盖新编辑；失败不留下半个组合或缺资源引用 |

模型生成结果不承诺凭 seed 再现。参数引擎只有在相同源资产 hash、参数、处理器版本与配置下才承诺确定结果。两条路径都持久化采用后的完整资源和结果；重开工程不再次调用模型、执行随机生成或跟随目录最新版本。

## 2. 素材请求与受限输入

### 2.1 发起前固定的上下文

本机固定请求标识、当前 sceneId/baseRevision（若面向场景）、源素材固定版本和 hash、输出类型、允许调整的视觉字段、候选数及字节/像素/期限预算。只做素材库制作也须固定源版本；没有场景目标不意味着获得全图权限。后续场景采用始终重新绑定当时的 sceneId、baseRevision 和明确对象范围。

发送预览应足以审阅以下内容，不要求用户阅读技术 JSON：

| 内容 | 用户可核对的含义 | 校验要求 |
|---|---|---|
| 任务与处理方式 | 新生成、从源素材派生；使用 AI 图像或本地参数 | 参数调整无需调用模型，也不偷偷转为云端任务 |
| 源资产 / 参考 | 默认或用户素材、固定版本、实际发送的裁图或参考图 | 只读取明确选入的资源；保留原件，核对可使用和可外发条件 |
| 目标风格 | 已确认的组件样本、色板、线条、视角、光照及风格版本 | 不是一句随时间变化的提示词；确定基线后扩围沿用固定参考 |
| 输出类型与边界 | 单物件、外观变体、可平铺材质；像素范围与透明背景要求 | 不接受整图烘焙冒充可编辑场景；模型不能改任务类型 |
| 允许变更字段 | 例如图片引用、色调/明度参数、已支持的装饰阴影 | 本机白名单；不含实体位置、物理尺寸、占地、支撑、结构、秘密或锁 |
| 保持内容 | 原锚点与真实比例、物理占地、实例变换、手工覆盖、秘密和编辑锁 | 图片处理不得自动紧裁剪或重标尺度；越界候选拒绝 |
| 目标范围与排除项 | 明确实例/成员清单、只读上下文、已锁定或保留的人工内容 | 选中图层只用于解析目标 ID，不按未来层成员动态扩大 |
| 预算与来源 | 实际 provider/model、次数/用量上限、参考条件与可分发性 | 缺失许可或未知费用显示待确认；不能伪造合法性或精确金额 |

新单件素材的预期尺寸、锚点和占地是待标定输入；必须经处理流程和用户确认才成为可放置定义。修改既有素材时默认保持这些值。需要改动轮廓映射或物理尺寸的候选应显示不兼容原因，转为独立手工校准/编辑；不能混在“统一风格”中提交。

### 2.2 协议边界

主线使用独立、带版本的素材请求/候选结构。模型输出限于本次允许的图像候选、必要处理建议和解释；固定 requestId、源引用、scope、预算、允许字段及来源归属由本机核对，不信任模型自报。

本地参数路径只接受应用实际支持的参数及有限取值；未知滤镜、脚本、插件指令和超界数值拒绝。图像输出不能携带任意 JSON Patch、JavaScript、SQL、文件操作、下载地址或地图领域操作。第9节的 GenerateScene、UpdateProp 等 11 个操作不会出现在素材模型的权限中。

需要记录的新素材来源、变体关系和风格基线由04/06确定格式；当前未冻结可执行图像接口或具体 provider。不同供应商的二进制/短期下载结果由专用适配器收取，不能把不受限图片塞进旧文本提案接口。

## 3. 候选、入库和场景采用

三道门分别完成，前一步成功不代替后一步：

| 阶段 | 允许动作 | 必须通过的检查 |
|---|---|---|
| 候选制作 | 产生有界图片或参数变体，建立并排/叠加预览 | 受控解码、实际像素/字节、透明底与边缘、俯视角、尺度/锚点保持、平铺或阴影要求；用户可拒绝 |
| 素材入库 | 将确认结果作为新固定版本持久化，保留规范化字节、hash、来源和适用许可 | 完整依赖和嵌入条件；源版本冲突、缺参考来源、处理失败或预算不足均停止；不修改打开的地图 |
| 场景采用 | 将已入库版本或受支持参数应用到明确对象/表面 | 当前基线、目标 ID、允许外观字段、锁、人工覆盖、完整资源与秘密检查；预览后走同一原子事务 |

默认素材属于共享目录内容；派生时建立用户变体的独立身份与固定版本，保留与原素材的来源关系。不能原地改写默认包，也不能按同一个 assetId/catalogId 批量替换所有引用者。用户素材的旧版本同样不可覆写。相同字节可去重，语义定义、来源、许可和受众不可因此合并。

场景采用仅开放明确的外观意图：对选中物件采用已验证外观版本/参数，对选中受支持表面采用已验证材质/参数，以及把相同操作组成有限批次。具体字段白名单由04与渲染支持共同决定；尚未支持的视觉特征拒绝采用和正式导出。应用只新增必要的固定定义/资产依赖并修改所列外观字段，不改变位置、旋转、真实尺寸、锚点、占地、通行、支撑、成员关系、注记、秘密或锁。换材质也不改变地形边界、高度或连接。

每份采用提案包含本机生成的 proposalId/requestId、sceneId/baseRevision、明确 scope、源与目标固定版本、实际读写集合、差异预览、依赖组、资源/许可检查和生成来源摘要。字段结构在实施时按04冻结，模型不能返回可直接写入的“完整新文档”。

用户可以只选可独立成立的成员/依赖组；本机重新计算组合结果、资源闭包与完整校验。一次采用只有一次原子提交和撤销记录，revision 加一。AI 候选采用按04标为 source=ai；纯本地参数编辑使用 manual，并保留可复现的来源参数。旧提案采用后关闭；下一批即使复用已经入库的图片，也必须在新 revision 上构造新提案和预览。

## 4. 单组件到组合再到局部的渐进同化

1. **先确认单组件。** 以一把默认椅子或用户素材为例，生成/调参若干有限候选，对照原件选择风格。确认的结果、参考资产和参数形成固定风格基线；只入库也可以结束本次工作。
2. **再预览一个组合。** 用户选择书桌组合，逐成员展示原外观与建议外观。桌、椅、纸张仍是可单独编辑的对象；不把整组压成 PNG，不重排成员，不补回人工删除的成员。人工外观覆盖默认保留，只有用户明确把某一覆盖纳入本批范围才可改动；编辑锁不能由同化任务解除。
3. **明确选择下一批。** 用户从其他组合、框选区域或某图层中挑选目标，界面先解析为稳定对象 ID，列出目标数量、排除项和依赖。相同素材的其他实例、相邻区域和未来加入该层的对象均不自动跟随。
4. **每批重新比较与采用。** 固定新的 scope/baseRevision、预算和快照边界，显示受影响成员/表面与未覆盖的素材。批内只提交已选择且完整通过的依赖组；两组分别通过仍须验证合并结果。改选目标或候选使旧预览失效。
5. **支持局部反悔。** 每批采用前先成功保存可追溯的命名/批次快照；快照失败则停止采用。需要回退时再按04/06从当前 revision 生成恢复提案。恢复所选对象的外观与必要固定资源，保留之后其他对象的编辑；缺失目标、锁、成员关系或依赖冲突时先给出差异与处置，不以整图回滚代替局部恢复。

命名快照和局部恢复由 M1-C 提供，是 M2 渐进同化的前置能力，区别于当前最近20次成功保存快照恢复为副本。C1d先覆盖独立物件与已支持外观属性，C2–C4随领域工具扩展恢复范围；M2只能使用已经验证的范围。快照保留源/采用资源的完整依赖，不能在清理候选或删除库版本时破坏恢复能力。新增快照格式与包内策略以06为准，不宣称当前v2已经支持。

外观恢复默认不会恢复位置、物理值、成员关系或公开状态；若以后支持这些字段，必须通过相应领域恢复策略重新校验。命名快照不是放宽编辑锁的通道，也不是无限保留全部历史的承诺。撤销与恢复都以新 revision 提交，不能回拨修订号以复用旧 AI 提案。

## 5. 状态、失败与资源预算

素材任务状态为 requesting → candidate → validating → ready；之后用户可拒绝或独立入库。入库成功得到固定版本，场景采用再产生独立的 validating → ready → applied 提案。没有场景目标的候选不伪造“地图已修改”状态。failed、cancelled、stale、rejected 均为明确终态；重新发起使用新 requestId。

| 情况 | 要求 |
|---|---|
| 等待时手工改图 / 导入 / 撤销 / 重做 | 场景采用提案基线失效；候选图像可保留供审阅，但采用须绑定新基线重新验证，不能直接覆盖 |
| 取消或离开任务 | 取消请求与本地处理，释放隔离资源；迟到网络/Worker结果须同时匹配requestId、任务代号和活动状态，否则丢弃 |
| 部分成员生成失败 | 标出失败成员及原因；不静默使用占位图。可独立采用的成功成员由用户重新选择并整体校验；依赖内任一失败则整组拒绝 |
| 已采用批次后取消 | 停止后续批次，保留已采用成果和快照；可撤销或局部恢复，不能假称“取消了全部历史” |
| 缺资源、坏hash、许可不全或无法解码 | 候选/入库/采用各自失败，当前工程保留；不能生成删图后的“成功”工程或PNG |
| 超预算 / 存储不足 | 有界停止，展示候选数、资源阶段与可调整项；不截断组合、不丢源件、不淘汰快照仍引用的资源 |
| 过期范围 / 锁 / 人工覆盖冲突 | 不自动扩大scope、解锁或重试覆盖；解释具体对象，由用户另开新范围 |
| 重复采用 / 迟到成功 | 以requestId/proposalId去重；已撤销的旧提案也不可再次执行 |

相同场景同一时刻最多一个活动 AI 制作/同化任务，批次串行。候选总数、单图和累计像素/字节、参考图大小、解码并发、请求期限、入库占用及付费尝试次数都必须预先有上限；采用前再与06工程预算取较严值。具体图像数值待 M2-A provider 与本地测量后冻结，未验证前不承诺容量，也不能沿用 M2-L 文本1 MiB预算当图像预算。

请求在发送前失败或明确可重试的限流/暂时错误，最多在整次期限和总预算内重试一次；已发送后状态未知不盲目重复付费请求。格式错误、权限违规、基线失效不自动做模型“自我修复”。取消不能承诺供应商停止已经发生的计费，界面根据真实用量显示已知或未知状态。

图像处理/批量校验可按测量引入 Worker；Worker只返回候选，不写场景、库或网络，主线程检查任务标识并控制提交。耗时循环应有取消检查和有界资源分配。任务预算必须覆盖从收取、解码、处理到预览/采用的完整路径，不能只量模型耗时。

## 6. Provider 与本机网关

主线先接入一个经过固定素材评测的图像 provider；品牌、模型标识和价格不得硬编码为领域契约。参数路径在本地运行；本地模型如果加入也执行同样的资源、范围和秘密约束。可用性、参考图编辑、透明结果/后处理、输出限制、取消、用量、错误和适用条款都须按实际能力记录。

### 6.1 部署与信任边界

可选网关采用 Node.js + Hono，首版面向本机编辑器。仅绑定 127.0.0.1；需要 IPv6 时显式增加 ::1。禁止默认绑定 0.0.0.0、局域网地址或公网。端口与允许的编辑器 Origin 在本机配置中明确设定；协议、主机名、端口均精确匹配，不使用通配 Origin 或反射请求 Origin。

网关检查 Host 为允许的 loopback 主机名 / 字面地址及预期端口，阻止借任意域名访问本地服务。除最小健康检查外，浏览器请求同时要求允许的 Origin 与有效会话凭证。拒绝缺失 / null Origin 的浏览器业务请求；不把 CORS 当成唯一鉴权。预检只返回白名单方法和请求头。

首次配对在本机启动界面显示一次性配对码，由用户输入编辑器；配对码短期有效并限制尝试频率，不放进 URL、网页源码或日志。配对成功后发放随机会话令牌，编辑器仅放内存，通过 Authorization 请求头发送。会话闲置 30 分钟或绝对 8 小时失效，网关重启失效；重新加载编辑器需重新配对。首版不用浏览器持久化 token 或跨站 cookie。

首版 AI 启用范围限定为实施后通过验证的本机页面与本机网关组合；当前尚无此验证。公网 HTTPS 页面访问 loopback 可能受到浏览器混合内容和私网访问策略限制，需未来独立验证，不指导用户关闭浏览器安全设置。可用的静态编辑器仍可在关闭 AI 时运行。

### 6.2 素材任务路由与数据

以下为待实现的语义接口，实施时冻结严格版本；不是当前可调用 API。

| 接口组 | 输入与输出 | 权限边界 |
|---|---|---|
| 健康、配对、注销、provider能力 | 沿用受限本机会话和能力摘要 | 不暴露配置、密钥或路径；只有健康检查不需要业务会话 |
| 创建/查询/取消素材候选任务 | 带版本的本次素材请求、受控图片输入与候选结果，使用独立于文本提案的图像协议 | 请求检查源引用、实际发送内容、预算与会话归属；只返回候选，不调用入库或场景修改 |
| 受控收取provider图像 | 预配置provider适配器的有限二进制响应或受验证短期结果 | 校验每次重定向、目标来源、大小/MIME并流式限额；不抓取模型任意URL |
| M2-L 文本提案 | 独立的SceneBrief/白名单操作协议 | 仅可选M2-L启用，不与素材候选权限合并 |

网关请求保留protocolVersion/requestId、provider/model选择、任务、有限指令、源/参考输入、目标风格和预算；本地场景标识只作归属核对，不允许网关按ID访问数据库。响应含同一请求身份、状态、实际provider/model、候选数据或脱敏错误、耗时和真实用量；未知成本显示未知，有费率依据才附金额、币种与费率日期。用户指令、场景标签和模型输出都不能指定endpoint或凭据。

网关没有“采用到地图”“恢复快照”或素材库写入路由。入库、候选差异和场景原子采用在本机编辑器控制；任何任务完成信号都不代表用户已选择采用。鉴权过期、注销及会话停止取消未完成任务并清理临时数据。

### 6.3 外联与凭据

provider 地址由本机配置管理，只允许选中的预配置 origin 与必要 API 路径。云端默认 HTTPS；本地模型允许显式配置的 loopback endpoint。每个重定向都重新校验目的地，默认拒绝跨 origin 重定向；不开放通用 HTTP 代理、网页抓取或文件读取接口。

不允许调用方用提示词、sceneContext、素材 URL 或 modelId 拼接任意外部地址。对云端 provider 检查解析后的目的地址，拒绝解析到本机、链路本地或私网；显式启用的本地模型条目仅允许指定的 loopback 地址与端口。未来支持局域网模型需要单独设计和用户配置。

API 密钥留在本机网关的环境或专用受限配置中，优先评估系统凭据存储。前端 bundle、SceneDocument、工程导出、IndexedDB、截图元数据、Git 仓库与诊断附件均不包含密钥。浏览器会话令牌与 provider 密钥是两类凭据，不能互相替代。

## 7. 隐私、来源与提示注入

默认只发送用户明确选入的源素材、公开风格参考及必要参数。场景截图先通过玩家内容过滤或改用独立公开组件预览；不直接发送GM整图、秘密几何、注记、工程名称、路径或无关对象。框选只决定可选目标，不自动授权将框内所有内容发给云端。发送预览列出实际图片和文字，来源条件同时决定可否用于云端生成、派生和公开分发。

**私密内容可能进入图片像素，而不只存在于元数据中。** 如果参考或提示包含GM私密文字、秘密布局或未公开标记，生成图像必须沿用私密来源限制，不能因为没有Note字段或visibility未改而进入公共素材库/玩家输出。公共候选从公开参考和经过过滤的上下文制作；需要公开派生内容时先检查实际像素与来源，走独立明确的公开审阅流程，模型自述“没有秘密”不能作为依据。玩家PNG继续过滤元数据、隐藏实体及其阴影/边缘。

用户拥有参考图不自动代表可外发、可再分发或可制作公开默认包。记录源资产固定版本、参考的必要来源/权利摘要、生成工具/model、日期、人工处理、适用条款及派生关系；原件和已采用固定版本保留。缺来源或分发权不确定的候选不得标为可公开/可嵌入。规范化后采用实际字节的hash，不先hash原图再暗改像素；透明物件与平铺材质分别处理。具体许可边界见[10](10-rules-assets-and-licensing.md)。

导入图片、名称、标签、注记和模型解释都作为数据；其中的“解除锁”“读取文件”“上传密钥”不增加权限。模型文字使用纯文本或受限Markdown，不执行HTML/脚本，不自动加载其外链。AI不能修改visibility、Opening.revealed、Note.discovered、editLocked或图层的公开状态；外观变更也不得把隐藏文字绘制到公共图片。

GM表示对玩家保密，不等于允许外发。provider保留/训练条款必须依据实际信息展示，未核实就标明未知。本地模型不能自动读取全部文件。凭据不进入前端构建、工程、IndexedDB、图片元数据、日志或仓库。

网关默认日志只含请求标识、provider显示标识、状态、耗时、用量及错误码，不保存完整提示、源图片、私密正文、Authorization或供应商原始异常。任务正文在内存短期保留，完成后最多10分钟供本机会话读取，注销/过期/关闭即清除。调试导出由用户主动选择并预览；采用后的工程仅保存04/06规定的必要生成来源摘要，不保存完整对话、隐藏推理或私密本地路径。

## 9. M2-L：可选布局、自动布景与备团文字

本节保留原方案供未来独立实施：新场景初稿只写入新建/空场景，选区布局只在明确范围内修改受支持结构与目录内布景，备团文字默认GM。它不再是M2素材主线，也不阻塞M3/M4。所列生成器、SceneBrief编译、占地寻路和Worker均未实现；M0明确拒绝source=ai，M1已有样板和有限净空检查不代表此处能力已经可用。

模型负责用途、关系、素材选择和文字；确定性程序求解毫米几何、共墙、附着门与实际净空；校验器验证引用、范围、锁和秘密。模型“可通行”的解释不构成证明。以下字段和白名单只适用于明确启用的M2-L文本协议，不能与M2-A/B/C素材提案混为任意操作集。

### 9.1 请求上下文与 SceneBrief

#### 9.1.1 可信上下文

发起请求时，编辑器固定 sceneId、baseRevision、floorId、scope、可用领域操作以及预算。scope 由选区和用户明确纳入的依赖对象产生，模型无权扩大。编辑器还保留本次场景快照，用于候选计算和差异预览。

用户硬约束与模型建议分别标记来源。模型可以补充软偏好，不能把已有硬约束删除、改为软约束或降低数值。需要扩大范围、解除锁定或改动硬约束时，先失败并解释冲突；主持人修改设置后，以新请求重新计算。

#### 9.1.2 SceneBrief 字段

SceneBrief 是生成意图，不是另一份可直接保存的地图。下表为设计字段；精确机器结构在开始实现后建立，并使用 Zod 加上语义校验。世界坐标和长度均为整数毫米，禁止模型把屏幕像素当作地图长度。房间边界尺寸按墙中心线计算，clearanceMm 表达扣除墙厚后的真实净空；模型收到的字段说明必须区分两者。

| 字段 | 语义与来源 | 校验要求 |
|---|---|---|
| briefVersion | 意图格式版本，初版为 1；由应用填写 | 不支持的版本拒绝执行 |
| task | 新场景生成、选区修改或备团文字；由用户操作确定 | 不能在响应中升级为更大范围任务 |
| theme | 简短主题、时代与气氛 | 只影响内容选择和软偏好，不产生权限 |
| presetSnapshot | 本次使用的预设标识与版本快照 | 从当前文档读取；不凭模型输出切换预设或重缩放 |
| floorId | 当前楼层 | M2-L 必须为当前唯一楼层 |
| seed | 程序生成种子，由应用产生或用户指定 | 记录实际采用值；候选子种子由固定规则派生 |
| generatorVersion | 应用提供的生成器版本 | 不由模型选择未知版本 |
| footprint | 新场景外轮廓，或已批准的选区几何边界 | 新房屋/地下城生成器首批只承诺简单正交模板；选区可引用 M1 支持的非正交已存轮廓；生成器不能处理时拒绝，不能把斜墙静默拉直 |
| roomPrograms | 房间意图列表：临时 key、用途、数量、最小尺寸、目标尺寸、可选位置偏好 | key 唯一；硬要求与软要求分别记录；不会直接成为永久 ID |
| regions | 仅用于 GenerateScene 的区域意图：临时 key、用途、所属房间或允许范围、尺寸偏好、危险 / 障碍要求 | 只选产品支持的 Region.kind；由程序求解边界并校验阻挡；不开放既有 Region 的任意修改 |
| connections | 房间 key / 既有 Room ID 之间的连接意图，包括必要连接、可选连接与回路偏好 | 引用可解析；同楼层；秘密或上锁通路必须显式标明 |
| entrances | 入口与出口意图，含既有 Opening ID 或允许开口的边界区段 | 入口必须落在有效边界；不能穿越范围外墙体 |
| accessRequirements | 普通必达房间、起点与明确例外；例外记录原因 | 不能因为求解失败自动把普通房间加入例外 |
| clearanceMm | 本次门宽、走廊宽度和必要通路净空等工程约束 | 使用用户设定或产品默认值；不冒充官方规则数值 |
| furnishing | 家具用途、密度偏好、单类数量与总数量上限 | 素材来自本次目录；不能堵住必须保留的通路 |
| narrativeHooks | 可选的线索、互动点、环境描述需求及其目标对象 | 默认只生成 gm 文字；不推导“玩家应已知道” |
| secrecyRequirements | 用户明确要求隐藏的新房间、通路、物件、区域和秘密门；使用临时引用及需求来源 | 应用核对来源，核心创建为对应 gm 几何或未揭示秘密门；不能用于修改既有可见性 |
| assetPalette | 本次允许的 PropDefinition 固定版本、实际可用图片/符号与尺寸、占地、标签摘要 | 由应用提供并解析到工程内定义/AssetRef；模型不能添加 URL、文件路径、未知素材或自创占地 |
| prefabPalette / styleTheme | 本次允许的组合定义版本、成员占地、可用变体和主题快照 | 只引用已入库、通过验证的版本；模型不能生成图片或篡改材质/占地定义；不隐式给已有全图换主题 |
| scatterIntent | 允许的既有区域/路径、类别、密度、间距、数量上限和 seed | 按地形、碰撞和排除区求解；人工调整、人工删除记录、锁定对象及范围外内容保持；不凭水色或阴影判断可通行 |
| fixedAnchors | 既有入口、共享边、门窗位置、锁定物件等不可移动的锚点 | 从文档与选区派生；模型无权删除 |
| constraints | 每条含 constraintId、来源、硬 / 软级别、类型与参数 | 来源和硬约束由应用核对；错误必须指向具体 constraintId |
| budget | 候选数、房间 / 物件上限、计算时限、请求预算 | 由应用与用户设置确定；取应用上限与请求上限中的较小值 |

空缺的软偏好可以使用公开的产品默认值，并在提案中说明。缺少会决定可行性的输入，例如没有允许放置新房间的区域，应返回待补充条件；不能扩大地图范围来隐式补齐。

#### 9.1.3 约束分层

| 层级 | 例子 | 失败处理 |
|---|---|---|
| 文档不变量 | 稳定引用、非自交房间、唯一共享墙、有效门归属、整数毫米 | 拒绝整个候选 |
| 用户与范围硬约束 | 六个主要房间、保留已有入口、选区边界、编辑锁、固定门宽、必达房间 | 有限重试后报告冲突；不降低要求 |
| 产品保密约束 | 不修改既有 visibility / Opening.revealed / Note.discovered / editLocked；新注记默认 gm | 拒绝相关提案，不能由“提高生成质量”覆盖 |
| 软偏好 | 厨房靠餐厅、走廊较短、书房远离入口、家具密度 | 用于候选评分；未满足项展示为取舍 |

门被上锁、密室尚未发现，与“墙体错误导致完全无入口”必须区分。校验器至少计算结构连接图与当前门状态下的可通行图：明确的上锁 / 秘密例外可以解释当前不可达，不能免除门确实存在、通道有净空等物理检查。

Room.accessExpectation 使用 unspecified、required、intentionalIsolation。手工新增房间默认 unspecified，允许还没画门的草稿；AI 生成的普通房间必须设为 required，并满足到任一指定入口的结构连通。明确的隔离区使用 intentionalIsolation 并记录原因；有真实连接的秘密或上锁房间可以保持 required，其当前不可通行例外另行说明。AI 不能把既有 required 改为 unspecified 或 intentionalIsolation 来躲避检查。

required 不要求默认处于 closed 的门自动打开。当前状态下可通行是独立的显式约束；家具 / Region 阻挡和通道净空也要单独检查。没有指定入口而声明了 required 房间的提案不合格，不能自行移除 required 来通过校验。

必要的具体路径检查记录为 constraints.pathChecks，包含端点、净宽和结构 / 当前通行模式。主持人可以明确允许检查时假设打开哪些门；该假设只影响检查，不修改 state 或 locked，模型不能自行扩大这一集合。

### 9.2 地图领域操作白名单

操作表达业务意图，由本机编译成编辑核心支持的 CommandBatch。模型不能提交任意 JSON Patch、JavaScript、SQL、文件操作或网络调用。M2-L 不开放删除实体、全场替换、修改可见性、揭示秘密、修改编辑锁等操作。

每个操作具有 opId、operationType、params 和依赖信息。对新对象使用提案内临时引用，先校验唯一性和引用关系，再由编辑核心分配永久稳定 ID。既有对象使用当前快照中的稳定 ID，不能凭名称猜测。

| 操作 | 主要参数语义 | 编译及禁止条件 |
|---|---|---|
| GenerateScene | SceneBrief、新场景 / 空场景目标、模板偏好 | 只在没有既有几何或注记的目标生成；可已有 Floor、预设及素材目录；创建完整布局和 brief 内必要 Region；已有地图应另建场景 |
| AddRoom | 新房间临时 key、用途、尺寸约束、scope 内放置偏好、可选相邻房间引用 | 求解简单正交边界，复用共边；不与既有室内面积重叠；不得挤压范围外房间 |
| ResizeRoom | Room ID、目标宽深或边界偏移意图、固定边 / 固定点、需保留的 Opening ID | 校验共享顶点、相邻墙与开口；涉及邻室的实际修改必须在 scope 内；不允许隐式删除墙门 |
| ConnectRooms | 两端 Room 引用、连接方式、允许路线区域、最小净宽、开口宽度、必要 / 可选标志 | 相邻房间可建立开口；不相邻时可创建 purpose 为 corridor 的 Room 及两端开口；所有新增几何都在 scope 内 |
| MoveOpening | Opening ID、目标 Wall ID、offsetMm；widthMm 保持既有值 | 提案的 offsetMm 从目标 Wall.startVertexId 量到开口近端；编译 v2 时显式设置 offsetReferenceVertexId 为该端点，之后按04的稳定基准计量；整个开口须位于墙段内；保留 kind、secret、revealed、state、locked 与 editLocked |
| PlaceProp | 素材目录中已允许的 PropDefinition 固定版本、目标房间或位置意图、朝向、可选尺寸偏好 | 基于已批准的素材占地求解位置；不接受外部资源地址；校验家具之间及门前净空 |
| PlacePrefab | 已提供的 PrefabDefinition 固定版本、目标范围、位置/朝向意图 | 在同一候选中展开并验证所有成员与组合关系，按展开后的实体数计算预算；不能借组合绕过秘密、锁或范围限制 |
| ScatterProps | 已提供的素材类别、既有 Room/TerrainArea/Path 范围、密度/间距、排除区、seed、数量上限 | 只增添新物件与新的 ScatterGroup；地形和已有对象作为约束，不重写旧散布结果，不复活人工删除对象；输出完整候选位置与占地 |
| UpdateProp | Prop ID、位置 / 朝向 / 尺寸调整意图 | 只更新允许的变换；不能改变素材来源、可见性、编辑锁或碰撞语义以绕过检查 |
| AddNote | 目标 Room / Prop / Region / Opening 引用、注记用途、标题与正文 | 目标必须在 scope 内；创建 Note，线索使用 kind=clue；默认 gm；文字不执行为指令 |
| UpdateNote | 既有 gm Note ID、拟替换的标题与正文 | 显示逐项文字差异；保持 visibility、discovered、anchor、kind 与 editLocked；不能直接更新 public 注记 |

上述字段是领域语义约定，具体类型名和数据形状由 [场景文档契约](04-scene-document.md) 统一。模型返回未知操作或额外权限字段时，明确报错，不悄悄忽略后显示“已完成”。

GenerateScene 是受约束的组合操作，编译器可以依据 regions 生成必要的 Region，例如 SCN-02 的坍井危险 / 阻挡区；它不必把底层每个实体映射成一个开放给模型的独立工具。保留的 M2-L 设计白名单共 11 项，包含 PlacePrefab 与 ScatterProps；不增加 AddRegion、UpdateRegion、地形高程改写或任意区域补丁。已有场景的地形、材质和区域由手工编辑，在局部 AI 布景中作为只读空间与风格约束。

ScatterProps 的范围必须同时给出目标实体与允许放置的几何范围，不能因为读到了整片地形就扩展用户选区。按已有人工排除区、移除记录及固定物件扣除可放置空间，布局失败报告原因；替换或重新随机化既有 ScatterGroup 不在 M2-L 白名单内。PlacePrefab 成员以最严格的适用秘密规则创建；成员包含不支持实体或缺失素材时整个组合拒绝。ResizeRoom 等结构操作只处理其实现已验证的几何类型；手工支持斜边不自动证明 AI 可以调整任意斜边房间。

ConnectRooms 对新门的连接意图可以包含用户需求中的秘密通路或上锁例外；核心负责按文档策略创建未揭示的秘密门，并保留必要的显示遮罩。模型不能改变既有门的 secret、revealed、state 或 locked。“编辑锁”使用 editLocked，“门被上锁”使用 Opening.locked，校验错误必须说明具体对象和限制。

普通新增 Room / Prop / Region 的几何默认 public；用户明确要求隐藏的新增房间或通路，由核心按 secrecyRequirements 创建为 gm，不能先按 public 创建再依赖秘密门遮蔽。放进 gm 房间的新增物件沿用 gm 保护，不因默认值显露内部布置。新秘密门为 secret=true、revealed=false；开启该门或后来揭示它都不改变关联房间和注记的可见性。必要的玩家遮罩仍按 [存储与导出](06-storage-and-export.md) 校验，不能仅靠模型一句“已隐藏”认定玩家图安全。

改写既有 public 注记时，模型只能通过 AddNote 提供新的 gm 草稿，主持人阅读后再明确发布。单纯保留 visibility 字段无法防止 gm 来源混入公开正文，因此 M2-L 的 UpdateNote 只接受原本就是 gm 的目标。

### 9.3 地图提案的依赖组

M2-L提案沿用本页的请求归属、基线、状态和原子采用约束。模型返回的操作仅是意图，由本机推导读写集合、临时引用和依赖闭包。新增通道必须包含所需Room、共享墙、两端开口与顶点；涉及邻室、共墙重挂的对象都须位于scope内。

用户选择某组时显示其必要依赖，重新计算所选组合整体的几何、净空、连通与差异。GenerateScene结构布局为一个完整组；装饰和文字仅在移除后仍满足硬约束时可单独选择。缺少用户硬要求的地图不能通过取消勾选失败部分成为合格候选。

一次提案只有一次采用；成功后关闭剩余建议，下次使用新baseRevision重新计算。提交遵循04的CommandBatch和单调revision；锁、范围、资源和几何任一步失败均不留下部分房间、门或文字。模型响应未知操作或额外权限字段明确拒绝，不忽略后宣称“完成”。

### 9.4 首版布局算法

#### 9.4.1 房屋：用途模板与受约束的 BSP

首版从矩形或少量正交外轮廓起步，使用原创用途模板确定入口、交通空间、公共房间与私密房间的相对关系。模型建议房间用途和相邻关系，程序选择模板并完成具体布局。

1. 保留用户指定的外轮廓、入口、固定边与必要通路。
2. 根据硬性最小尺寸，给交通空间与重点房间分配保底区域。
3. 对可分割区域执行受约束的 BSP 切分；每次切分检查两侧房间的宽深和面积可行性。
4. 将房间用途映射到分区，按用途相邻性、采光边偏好、动静分区和走廊长度评分。
5. 建立共享顶点 / 墙，安排普通开口、明确的秘密连接与必要例外。
6. 放置家具并校验通路。若家具影响硬性通行，优先调整可选家具；不能移动锁定物件或缩小净宽。

程序不得把 BSP 任意切分当作有用住宅。厨房与餐厅的关系、主要空间是否被迫穿过卧室、入口是否直接撞到家具等，需成为可解释的约束或评分项。无法满足“六个主要房间 + 固定尺寸 + 当前外轮廓”时，应报告容量冲突。

#### 9.4.2 地下城：房间、走廊与回路

先形成房间关系图，再在允许范围内放置房间。普通必达房间建立连通骨架；走廊采用占用栅格上的 A* 或同类确定性搜索，最后转换为整数毫米的正交多边形并执行精确几何校验。

新增回路以改善探索路线为软目标：从尚未相连的房间对中，优先选择能减少过长折返、且不穿越锁定 / 范围外区域的路线。先按固定排序选候选，再使用 seed 决定平分项；避免容器遍历顺序影响结果。回路数量受 SceneBrief 与预算限制，找不到可行路线时展示未满足的软偏好；如果用户将回路设为硬要求，整个候选失败。

走廊也是 Room，使用 corridor 用途标记，因此共享墙、开口、遮罩和保存逻辑与普通房间一致。不能只在图片上画一条线，并把它当成真实连通关系。

占用栅格用于寻路加速，不是最终空间真相。障碍应保守扩张到必要净空，最终再检查实际边界、门宽及转角。规划栅格精度无法表达本次最窄通路时，拒绝该配置或在预算内提高精度；不能缩小用户设定的净空来凑出路线。

#### 9.4.3 装饰与文字

先放置决定用途的大物件，再放小装饰。素材包提供可信的毫米占地与允许变换，模型提供类别和用途偏好。室内可选“书桌＋椅子＋纸张”等组合；室外可沿允许的路径/地形边缘散布石块、在草地中布置植被。素材与组合来自当前主题目录，避免任意混搭光照、线条和尺度。放置时为门前净空、关键交互点与通行路径保留空间；首版不计算门扇扫掠碰撞。装饰密度不足属于软质量问题，堵住唯一出口属于硬错误。

候选需要区分视觉边缘与碰撞占地，树冠画面覆盖不自动变成树冠范围全不可走。台地、悬崖和高差连接按领域属性校验；不允许用“把水改成浅蓝色”替代有效通路。程序生成及手工笔刷均保存已采用的完整实体结果，重开不重新随机；人工移动、删除、锁定和实例覆盖遵循04的持久化语义。这里的布局重生成不同于主线的外观同化，也不同于从已存命名快照恢复内容。

文字挂接到稳定对象 ID。新生成的主持人线索、玩家描述草稿都先以 gm 注记保存；“玩家描述”是内容用途，不自动等于公开权限。实际发布与导出见 [存储与导出](06-storage-and-export.md)。

M2-L 新场景结构生成优先支持房屋与地下城；室外地形与混合场景的手工制作在 M1 完成，并用 VIS-02、SCN-04 验证，M3 再做真实小团使用。M2-L 可以对既有地形采用目录内布景提案；从自然语言自动生成整座岛屿、连续高程、河流地形和城镇路网不在这一算法的承诺范围。

### 9.5 已编辑场景的局部重生成

“重新生成书房”在 M2-L 的含义是：在批准范围内重新求解受支持的领域操作，保留已有稳定对象和必须保留的内容。M2-L 不提供删除并替换整片已有地图的能力，也不把某个 seed 的旧结果恢复为用户当前地图。

局部计算把区域分为修改内部、固定边界和只读邻接上下文：

- 修改内部：主持人选入且未锁定的对象，以及允许放置新实体的空间。
- 固定边界：选区外轮廓、必须保持的墙段 / 顶点、保留的门窗与连接锚点。
- 只读邻接上下文：为碰撞与连通检查读取的邻室边界、开口、必要通道；读到不代表允许修改。

涉及共享顶点、共享墙或 Opening 重挂时，先计算完整影响集合。任一实际修改落到范围外，候选失败；只有主持人重新纳入依赖后才可重算。不能复制一份共享墙来绕过范围限制。

对每个 ready 候选检查：范围外对象序列化内容不变，锁定对象不变，固定锚点不变，必要入口可达，原有注记目标引用有效。这里的“序列化内容不变”排除应用层新增的整体 revision 和明确的生成来源记录，其余对象字段不得悄悄重写。

无法通过 M2-L 白名单完成的请求，例如“删除所有家具重布置”或“彻底改变书房与走廊拓扑”，应明确说明当前限制，并给出可行的移动 / 增补建议。日后开放删除需要另行定义依赖迁移、秘密状态保护与撤销语义。

### 9.6 Worker 取消与计算预算

布局、通行图、批量碰撞与候选验证在 Web Worker 执行。主线程保留交互、临时预览与最终提交控制。Worker 只计算候选，不直接写 IndexedDB、操作文档状态或调用外部网络。

以下是 M2-L 拟验证的初始保护上限，属于配置和失败边界，不是 M0 性能实测结果：

| 项目 | 初始设计 |
|---|---|
| 活动生成任务 | 每个编辑会话最多 1 个；同场景请求串行 |
| 候选数 | 最多 3 个；同一请求共用预算 |
| 单次新增房间 | 最多 32 个，含走廊；用户更小上限优先 |
| 单次新增物件 | 最多 500 个，组合展开成员与散布结果计入同一总额；文本数量另设上限 |
| 寻路栅格 | 单候选最多 200 × 200 单元；精度须同时满足净宽约束 |
| 寻路搜索 | 单候选累计最多 200,000 次节点展开；到达即报告预算耗尽 |
| 计算时限 | 单候选最多 2.5 秒、整次 Worker 计算最多 8 秒；只统计本地计算阶段 |
| 取消检查 | 在有界循环批次检查任务代号与取消信号；每批最多 256 次搜索展开，并安排让出执行机会 |
| 强制终止 | 主线程取消后 500 毫秒内未确认，终止该 Worker 并新建空闲 Worker；超时兜底最迟 10 秒终止 |
| 临时数据 | 用固定栅格上限与对象数量限制分配；不依赖浏览器精确报告进程内存 |

实际时间由浏览器调度影响；计时和取消检查不能替代主线程 watchdog。预览结果必须包含 requestId、任务代号与 baseRevision；旧消息即使结构正确也丢弃。取消后，任务不能写入缓存以外的任何持久业务状态。

当预算不足时返回部分诊断与可调整建议，不把未完整校验的局部地图标为 ready。扩大预算需要新的明确设置，不能在当前任务中自行移除上限。

### 9.7 单独评测与保留限制

布局模型以相同提示、目录、约束与程序生成器评测SCN-01/02的初稿、只改书房、共享墙范围不足、半组采用、三次候选失败及SCN-03/04的受支持布景/文字。记录结构通过率、硬违规拦截、可采用率、人工修改、中文意图、延迟和用量；人工评审用途与可玩性。未知或不支持的地形生成任务只验证正确拒绝。

M2-L文本接口仍需独立定义严格版本；原初始保护值为请求/响应各1 MiB、指令16,000个Unicode字符、单会话一个请求、网络总期限90秒，并与输出token和重试预算取较严限制。这些是待测保护值，不能当服务承诺，也不能套给主线图片。任意聊天代理、网页检索、代码执行、整本模组解析、自动连续改图、删除/全场替换和任意地形改写均不在本节默认授权中。

手工房间草稿允许暂未连通；AI生成的必达房间、当前通行和真实净宽按本节硬约束独立验证。原PRD-013/017及M2-02/03/06归此可选方向；相关QA仅在M2-L实际立项后执行和记证据，不作为素材主线完成门槛。
