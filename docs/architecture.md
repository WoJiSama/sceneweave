# 当前架构与关键约束

本文只保留继续开发所需的现行规则。准确字段、限制和错误由源码中的严格schema、命令与测试定义；修改能力时同步这些实现，不维护另一份逐字段副本。

## 模块入口

| 范围 | 代码入口 | 职责 |
|---|---|---|
| 纯领域 | [src/shared](../src/shared) | 模型、严格校验、命令、身份、几何、生成、投影和文件协议 |
| 应用 | [workspace](../src/application/workspace) | 候选、会话、事务协调和平台端口 |

| 编辑器 | [editor](../src/editor) | 表单、画布和会话交互 |
| AI服务 | [services/ai](../services/ai) | 凭据、provider请求、任务和有限工具执行 |
| 本机工具 | [tools](../tools) | CLI/MCP、测试与诊断；复用产品能力 |

共享层不依赖DOM或Node平台；应用层只依赖应用与共享层，浏览器实现从组合根注入。`npm run check:architecture`检查依赖方向，`npm run check:shared`检查共享层平台边界。

编辑器的[文件控制器](../src/editor/main/workspace-file-controller.ts)执行完整工程备份、所选历史备份及双受众图片输出。备份先严格校验内容、资源和许可，再由 Worker 压缩并累计检查 ZIP 字节上限。工程 ZIP 上限为 304 MiB，展开数据上限仍为 300 MiB。旧构建需更新才能读取超过 100 MiB 的档案。发起下载前重检工程检查点，取消会释放备份操作与 Worker。

<a id="project"></a>
## 工程与版本

正常入口只维护当前完整工程v1，包含完整建筑、室外地形、图层、固定资源、来源许可、外观、身份、人工记录及生成结果。`ProjectData`、`SceneDocument`和文件manifest的`schemaVersion`均为1；当前内部结构使用identity5、appearance2、visual3、generation5及适用的regional1。它们不是多套可选工程格式。

当前完整 v1 的发布兼容基线为 `80162f9`。后续读取器须能打开基线工程、保留已采用的实体、人工修改、资源、许可、私密性及历史，并能继续编辑和保存。新增可选字段时，缺省含义沿用已发布行为。重命名、移除、改为必填或改变存储含义时，须明确新结构版本、保留原始输入，并在读取边界完成结构转换与严格全验。已有地图的规则或物理行为变化通过可预览、可撤销的候选采用。

工程文件先读有界清单。网页备份的 `applicationVersion` 记录应用版本及可用的 Git 提交，带工作区改动时附加 `.dirty`。直接运行未打包的共享模块时标作 `unbundled`。格式号和最低读取协议 `minReaderVersion` 决定能否解读内容。v1 基线的最低协议为 1，写入时省略该字段以兼容已有严格读取器。需要更高协议时明确标注。完整工程和所选历史共用同一识别入口。

含 `weathered-v2` 地表或 `scatter-landscape-v2` 散布规则的完整工程或选定历史声明最低读取协议 v3。已有地表外观按原版本读取，物理承托与净宽继续由保存的地形和道路断面决定。

含 `weathered-v3` 露岩或 `roadFinish: terrain-v1` 道路外观的完整工程或选定历史声明最低读取协议 v4。

含区域轮廓输出选项 `showOutlineInOutput` 的完整工程或选定历史声明最低读取协议 v5。未保存此字段的区域沿用原来的出图行为。

浏览器存档含按内容哈希连接的增量和保护点。将来转换存储表示时，须先按旧表示验证原链，再校验新检查点，并在同事务版本检查后切换，保全原有分支。现有发布样本见[兼容回归](testing.md#release-compatibility)。

生成算法/配方、固定素材、AI协议/权限、预算、增量历史结构及数据库schema各自管理版本，不能全仓替换数字或原地改义。已存工程保存实际结果，不只保存seed；后续重开不运行生成器来重建实体。

新生成按地貌和配方选择实现。同一用途的配方升级沿用原界面入口。改动已支持请求的确定性生成结果时使用新算法版本。画风随渲染独立演进。

沿海地形的生成实现与编辑入口共用[算法版本清单](../src/shared/terrain-generation/recipe-capabilities.ts)。局部编辑根据保存的算法、配方版本和地形种类选择预算，再核对规则的原始输入摘要。

完整模型入口：[scene.ts](../src/shared/model/scene.ts)、[validation](../src/shared/validation)、[project](../src/shared/project)。

### 扩展接口

扩展清单 `sceneweave-extension` v1 用与工程私有数据相同的 `发布者/包名` 标识扩展。包的发行版本、清单格式版本、各扩展点的接口版本和工程格式各自演进。每个扩展项有包内唯一标识，并声明扩展点、所需的确切接口版本及 JSON 数据。字段和读取上限见[清单定义](../src/shared/extensions/manifest.ts)。

宿主在自己的入口用 `createExtensionHost` 登记可处理的扩展点与版本。`points` 列出实际支持范围，`inspect(manifestBytes)` 逐项报告匹配、未知扩展点或缺少的接口版本。同一包中其余匹配项仍可单独选择。`readContribution` 核对所选项及目标接口，取出的数据再交给该领域的校验器。宿主负责提供操作权限和可见范围，涉及工程修改时仍经候选、校验与原子采用。见[宿主接口](../src/shared/extensions/host.ts)。

### 内容包接入

宿主从共享入口取得 `parseAssetPackManifest` 和 `assetPackReference`，可在读取前固定待采用的发布版本。浏览器的 `collectAssetFiles(files, { expectedPack })` 检查实际来源字节和完整引用，返回草稿素材。工作台使用 `prepareAssetBatchImport` 生成候选，采用时把固定定义、资源与许可保存在工程内。再次打开工程只需工程自身的资源。清单中可用的物件与材质字段，以及发布者命名规则见[素材导入指南](reference/asset-import.md#批量文件夹和素材包清单)。

浏览器素材宿主登记了 `sceneweave/asset-pack` 接口 v1，扩展项的 `data` 是固定的 `AssetPackReference`。从扩展选择时，调用方显式传入扩展清单的 UTF-8 字节和包内标识。所选文件夹或 ZIP 仍须携带自身的 `sceneweave-assets.json`，其发布版本、完整内容摘要与每份原始图片均须核对。见[导入入口](../src/platform/browser/assets/batch-source.ts)。

```ts
await collectAssetFiles(files, { source: 'zip', extension: { manifest: manifestBytes, contributionId: 'trees' } })
```

完整工程的可选 `ProjectData.extensions` 保存主持人私有数据。每项以 `发布者/包标识` 为键，`schemaVersion` 由发布者独立管理，`data` 是核心按原文保留的 UTF-8 文本。每份工程或快照最多 32 项，单项正文最多 64 KiB，整个区编码后最多 256 KiB。工程内容摘要、历史、撤销和保存都覆盖这份数据。

带扩展的工程在 `extensions.json` 保存它，所选快照各自有独立条目。当前工程或任一所选快照带扩展时，备份声明最低读取协议 2。常规工程沿用协议 1。玩家出图、素材和场景模板只取各自所需的内容。AI 创作只传协议允许的工程字段，采用时从本机授权基线保留私有数据。

<a id="transactions"></a>
## 候选、命令与历史

- 预览在独立候选上进行，不写当前工程或历史。采用时重新检查确切基线、依赖、锁、资源、预算与玩家投影，过期候选拒绝。
- 手工和AI复用原子命令、一次采用和撤销语义。任一失败保留当前成果；revision单调增加，撤销不回退修订号。
- 实体锁与用户图层锁都有效。批量计算完整成员、支撑、附着、开口、相邻结构及递归注记，不以JSON字段差异冒充影响范围。
- 实际展开数量、几何计算、元数据和资源均按当前分档计量；不能拆批绕过预算，也不能把旧256限制套给已经采用新分档的操作。
- 制图预算按地块计入同次生成的岸线构件，逐段检查实际轮廓和外部引用。独立编辑的边缘按实际编辑对象计量。
- 编辑选择、视口、独显、定位提示和精确事务计时属于会话，不进入工程、历史或正式输出。
- 复制、模板和新建结果分配新实体身份，保留当前外观、支撑和有效私密性；不能借复制复活人工删除或恢复默认公开性。
- 历史按真实检查点/内容hash及出生/拓扑身份恢复明确属性组，保留范围外编辑与当前锁。先保护当前、再在CAS下完整采用；拓扑变化或删除重建不能仅凭同ID证明连续性。
- 建筑局部恢复仍需会话建立的结构witness，重开/导入后失效。尚未支持的依赖明确拒绝，不扩大恢复范围。

<a id="geometry"></a>
## 几何、地形与模板

世界坐标使用整数毫米，共享墙只存一份，门窗附着在真实墙端点和沿墙距离上。净宽检查计入墙厚、旋转家具占地和实际连接带。编辑锁、门锁、结构连通与当前可通行分别判断；没有显式通路声明的孤立草稿可以合法。

聚合组保存局部坐标和朝向。零转角直接保留朝向，旋转后的组优先沿用 v1 的单值局部角。单值会丢失小数精度时，分别保存局部象限和象限内的偏角，读取时精确还原世界朝向。

用户图层顺序、地面高程和Floor分别建模。换材质不暗改占地、秘密或通行；图片中的桥、船和楼梯本身不能证明高差或跨层可达。道路绘制、命中、遮罩和净空共同使用实际带区及当前端帽/连接规则。

生成、散布及持续地表规则保存完整结果、来源和人工移动/删除覆盖。局部修改只改明确范围；人工保护优先，不能后台补回或重排。旧算法重放保持语义，新算法使用独立版本。

模板保存实际存活成员、当前有效外观及完整资源祖先；目标Floor/图层/支撑显式选择。当前有限结构模板只平移和四分之一圈旋转，不缩放、自动合墙或携带源全局层规则。跨界共墙、不支持容器或附着闭包明确拒绝。

用途布置读取真实房间、门窗和家具尺寸；缺项如实报告。默认保留现存、锁定、移动及删除结果，只重排明确允许的独立物件。多房间以同一基线准备、累计实际费用，最后一次采用。

海面属于普通平面地形外观，水下/部分出水及波纹尾流属于同一物件；实际水域裁切、旋转表现包络、支撑及受众过滤仍检查。水下布景不因此获得物理水深或游泳通行。船内复用Floor与建筑编辑，入口关系仅用于主持人导航。

有限附着和山路保存真实宿主、局部锚点、承托及步行几何。完整坡体保存实际整数XYZ、面和独立净宽边界，坡侧不自动授予步行；山径/踏步是可撤销的表面处理，承托仍使用连续坡体。显式沿用源地表时，源绑定及独立装饰草带保留原坐标、记录和绘制顺序，参与影响审阅和锁检查；绑定其他道路的草带仍拒绝隐式处理。几何合法与自然观感分别判断，岩肩及端部接合的缺口见[剩余事项](roadmap.md#remaining)。

阶梯以连接上的独立`staircase`组件保存构造、材质、续接和局部覆盖；逐级完整踏面按保存路线派生，纹理使用独立毫米尺度。样式编辑不改物理承托；已采用坡体的路线/净宽修改须明确回填并重建，一次预览、采用及撤销。覆盖仅裁切阶梯表现，不能擦除底层或授予通行；保存、源还原与有限属性恢复保留配置的存在或缺省状态。严格合同与派生预算见[src/shared/stairs](../src/shared/stairs)。

<a id="storage"></a>
## 保存与资源

自动保存使用同事务版本比较，内容、头指针和元数据的CAS同时保护新修改。跨标签冲突保全双方成果，失败、配额、取消、导入或切换失败都不能用空场景替换当前内容。新建先保全当前，再完整验证并保存新工程，成功后切换。

IndexedDB保存完整工程与增量历史，保留真实分支、命名/保护引用和来源。坏块、缺块、长度/hash/实际字节不符须拒绝；持久化计数或调用方声称已验证不能免除检查。完整工程备份与个人素材库备份独立。

用户可确认移除单个工程和它所属的历史，删除按原始主键约束目标，在同一事务更新存储版本。清理共享资源及内容块前，先证明全部剩余引用并检查保留的实际字节。整理未标记版本保留当前存档和已标记快照的完整内容，留下独立检查点。没有减少占用或中途失败时回滚。

内部编辑预览和自动保存可以消费校验器签发的确切不可变快照与未变资源证明。证明绑定校验器独立捕获的内容、身份、外观以及资源/许可闭包；换对象、字节、句柄代次或能力即失效。首个await前拒绝访问器、隐藏字段、symbol和自定义原型，Blob独立捕获。外部冻结标记、sceneId/revision及调用方开关都不能免检。

公开validate/save、冷读、导入导出和正式输出继续实际字节、hash、许可、预算及像素全验。内部证明也不免除当前数据库新鲜性、坏块、锁、身份、依赖和CAS检查；取消/失败不发布半份凭证，不引入跨受众长期Bitmap缓存。

固定素材/定义/父源不可原地改义；保留原字节、派生参数、祖先、真实PNG和确切许可绑定。重放需核实际像素，缺图或解码失败必须整体失败，不能删图后返回成功地图。新增资源先复制容器，来源与资源闭包不能当临时缓存删除。

<a id="privacy"></a>
## 玩家输出

玩家内容先过滤，再生成几何、道路边缘、光影、水下表现、资源闭包及输出。秘密门、隐藏结构、注记、阴影和PNG元数据都不能泄漏；透明度、清澈度0或层隐藏不能替代合法玩家遮罩。缺充分保密覆盖时明确拒绝输出。

主持人工程备份含秘密。玩家 PNG 和 WebP 的元数据按图片容器白名单重写，保密遮罩为不透明填充。UVTT 复用玩家投影选定的墙和光源，再裁切可见墙段和物件挡线；只有完全公开的门窗写入结构。导入兼容依据见[检查方法](testing.md#external)。

<a id="ai"></a>
## AI与共享工作流

手工编辑不依赖AI。供应商密钥只在服务端，不能进入工程、前端构建或日志。授权基线、有限白名单、独立草稿、累计预算和保护后采用共用产品边界；未知计费请求不自动重发，取消/暂停不重置用量。

普通聊天、参数助手、有限场景创作、图片MCP各有实际工具和权限。目录发现不授予执行权限；工具未接线时准确说明缺口。模型只返回支持的提案，不能直接覆盖主工程。

本机制图 CLI 与 MCP 共用构图 schema、工作预算和交付验证。地貌配方将区域与路线锚点解析为原生地形起伏、岸边、坡地道路和散布组。地形边使用空间候选统计 `spatial-v1`，现有档位的数值和其他制图协议独立。局部修改采用原生命令并核对精确工程摘要。

`workflows/catalog.json`与同目录Markdown是共享流程来源，严格schema归执行器。`tools/sync-workflows.mjs`生成应用目录，校验预览与引用。任务/工作包绑定流程ID、版本、摘要及真实断点；定义变化须重新核对，不能修改历史绑定来冒充旧任务继续有效。

林中建筑窄循环最多3次生成/指定房间修正、4次决策。需求不降低，失败仍计费，无改善停止；只有真实宿主回执算执行，最终由用户审阅保存。真实收益以完整成图耗时、人工接管、缺项及实际用量判断。

制作入口见[制作总则](reference/project-creation-workflow.md)，素材权利见[素材说明](assets.md)。
