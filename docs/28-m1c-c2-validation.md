# C2 建筑工具与有限结构恢复验证

日期：2026-10-22。当前本地版本为 `0.2.0-m1-c2`。本批按用户“做吧”授权，承接[C1d](27-m1c-c1d-validation.md)，实现建筑创作与有限的同会话结构恢复。实现、实际运行证据和未完成范围分别记录；13/17–27的历史结论与原证据不覆写。本批尚未提交、推送或发布。

## 实现范围

历史工坊 `/#history` 新增“建筑”入口：矩形可输入坐标或在画布点击两点，多边形可逐点绘制或输入坐标。草图按世界坐标网格吸附，暂态量尺显示距离和ΔX/ΔY；它们不进入工程、revision、撤销或PNG。平移、锚点缩放和全图复位沿用已有视口。

房间先作为合法草稿建立，再设置门窗、外部入口和必达声明。房间边界、顶点、墙厚、门窗、入口、注记及固定矩形玩家遮罩通过同一命令入口操作：隔离候选→显示实际影响ID和图层→明确确认→一次事务采用，支持单调revision的撤销/重做及完整保存。外部入口复选框只编辑暂态值，点击“预览入口修改”才生成候选。

建筑几何使用整数毫米、唯一共墙和稳定门窗端点。完整或部分相邻共边会复用/拆分原墙，并更新房间边界和合法开口引用；跨开口切点、非整数重映射、墙端净距不足、带不可安全拆分局部材质覆盖等情况整笔拒绝。多边形支持斜边与凹形，拒绝重复点、自交、自接触、折返及正面积重叠。新房间显式选择Floor或地形支撑和已采用的适用固定材质，不从图面落点暗改归属。

完整影响检查包含邻墙与转角、房间、门窗、支撑物件、路径、地形连接、父组合/散布和递归附着注记；实体锁、当前及相关层锁共同约束。单次事务仍最多256条展开操作，不拆批绕过。注记支持点坐标或实体锚点，拒绝循环、悬空和仍有引用的删除；既有非建筑锚点只改文本时原样保留。组合/散布父容器锁同样保护成员编辑锁和附属注记。

世界/导出范围复用既有字段，尺寸1–200m、长宽比不超过20:1，完整校验保留实体与真实墙厚。该操作保守检查整个Floor的实体/层锁，并按实体数+1计成本；已有256个实体时，即使扩大范围也可能因预算拒绝。这是当前限制，不能宣传为任意大工程均可调整范围。

## 格式与恢复边界

场景仍为严格 `SceneDocumentV3`；工程信封仍是 `CompleteProjectV4`，容器为 `containerVersion=4/documentSchemaVersion=3/profile=m1-history`，独立仓库仍为 `sceneweave-m1-history`。C2没有增加持久字段、新数据库或历史身份版本，也不扩大资源、许可和历史预算。资源字节/CRC/hash/解码/许可、完整几何和玩家过滤仍逐次按既有路径校验。

C1d的持久身份版本1只记录物件出生令牌，不能拿结构ID或相同JSON冒充建筑出生身份。C2增加不可伪造、不可序列化的会话连续性证据：只接受本次打开期间建立的命名/保护快照；重开、导入、另存或切工程即清除。曾删除重建、改变连接/端点/实体锚点的结构，即使撤销回相同JSON也会拒绝按旧ID恢复；同一事务先删后建相同门窗/注记ID也明确拒绝。旧命名历史仍可查看、携带，C1d适用的独立物件恢复保持可用。持久结构身份、跨会话结构恢复和已删结构重建须后续新版本与完整迁移。

| 模式 | 写入历史字段 | 保留当前字段 |
|---|---|---|
| 位置与尺寸 `geometry` | 所选房间/墙的共享顶点坐标、所选顶点坐标、墙厚、开口偏移/净宽、点注记坐标 | 房间名称/可见性/连通声明、墙阻挡、门窗状态/秘密、注记内容及下列共同保留项 |
| 位置、尺寸与业务属性 `properties` | **包含geometry**；另含房间名称/可见性/连通声明、墙移动/视线阻挡、门窗类型/状态/通行锁/秘密/揭示、注记类型/标题/内容/可见性/发现状态 | 材质、固定资源、支撑、高程、图层、编辑锁和当前拓扑 |

只给所选根及其必要共享顶点写入历史字段。相邻房间、墙、门窗、支撑、物件/连接和注记作为明确列出的检查依赖，未被选择的业务属性及范围外后续编辑保持当前。检查后必须精确确认全部扩展ID及跨层集合，才可预览；256条写入预算、连续性、有效锁、资源/许可、完整几何和固定秘密遮罩都通过后才能采用。

采用前复用工作区checkpoint、源快照内容hash、场景内容/历史元数据CAS：flush当前分支→复核来源→持久保存完整保护点→再检查取消/基线/来源→当前revision+1的单一可撤销事务→串行CAS保存。采用前失败或取消不改当前场景；成功落盘的保护点允许保留。采用后保存失败保留新内存、撤销能力、保护点及旧持久分支，显示保存失败或冲突，不能把该阶段写成“从未采用”。

### 建筑与SCN-01子集

真实UI从空白制作7个房间、9扇门、3扇窗，使用实际随机稳定ID，保存/重开并下载完整工程，再严格导入核对文档与全部资源闭包；检查18张位图的实际SHA-256、资源记录、许可全文/hash和绑定。墙厚100mm，密道中心线宽1300mm，扣除两侧墙半厚得到1200mm净宽；唯一几何为14顶点、20墙。其结果和稳定ID对应见[UI制作记录](evidence/m1-c2/browser/attachments/c2-ui-scn01-authoring.json)。

该UI用例只制作建筑与一条GM注记，没有SCN-01要求的全部家具布景，不能写成完整SCN-01验收。另有领域命令夹具包含符号家具/3条GM注记，用于门前300mm有限净空、结构连接及秘密像素配对；有限门前检查及打开普通门后的房间邻接图不证明全图占地寻路。

六点凹多边形与3:4斜墙的真实界面操作覆盖非法输入/交叉边界拒绝、取消不写入、附着窗和反转墙后端点保持；[记录](evidence/m1-c2/browser/attachments/c2-ui-polygon-diagonal.json)。矩形点击、缩放后量尺和会话暂态由[量尺记录](evidence/m1-c2/browser/attachments/c2-ui-pointer-ruler.json)证明。共墙厚度采用/撤销及实体/层锁见[共墙记录](evidence/m1-c2/browser/attachments/c2-ui-shared-wall-locks.json)。

### 双受众与离线

独立公开参考仅含H1–H6，没有密道或秘密门；与含HS/两秘密门及GM注记的领域夹具在相同固定遮罩/范围下分别生成真实Canvas2D与PNG，尺寸均4096×3234。玩家输出与独立参考以及改变秘密物件/注记后的版本逐像素hash相同，GM有效变化；GM/玩家PNG解码像素等于各自Canvas，且无历史身份或PNG文本/EXIF/时间元数据。[4K对照记录](evidence/m1-c2/browser/attachments/c2-scn01-4k-privacy.json)与[玩家图](evidence/m1-c2/browser/attachments/c2-scn01-player-4k.png)、[GM图](evidence/m1-c2/browser/attachments/c2-scn01-gm-4k.png)保留。

这组4K独立隐私对照使用符号家具。真实18张资源的完整包在新浏览器context预载代码后断网，再严格导入、实际解码并输出双受众1600长边，文档/身份和像素保持，之后可继续修改普通门。[离线记录](evidence/m1-c2/browser/attachments/c2-scn01-offline-package.json)单独记录，不混作4K真实纹理对照，也不证明PWA离线冷启动。

揭示一处秘密入口后，另一门、密道及GM线索继续私密；固定遮罩不足则拒绝玩家PNG，见[揭示与遮罩记录](evidence/m1-c2/browser/attachments/c2-reveal-and-mask-guard.json)。真实UI双4K出图也有独立附件，但不以截图代替上述像素检查。

## 失败与修正

原失败执行单独保留，后续通过不覆写失败现场：

1. SCN-01单测首轮12项中2项失败。家具夹具中心6200mm使800mm占地跨房间边界；改为合法室内位置后仍能阻挡300mm门前检查。另一个渲染端点由浮点计算得到2550.0000000000005，断言改为1e-8容差；持久整数毫米和产品几何守卫未放宽。SCN-01及命令复验32项通过。
2. 首轮Chrome6项中5项通过，完整UI制作卡在外部入口复选框。控件直接生成预览后仍读已采用旧值，导致回弹；改为暂态勾选加显式预览按钮，现真实制作流程通过。
3. SCN-01 UI复验完成了建筑、遮罩、注记与包下载后，测试误认许可应为2条，实际同文本按hash去重为1条。测试改为逐项核对原始真实资源/许可闭包，产品未放宽去重或许可校验。
4. 注记附着依赖审阅发现父组合/散布锁和删除时锚点锁存在遗漏，已修闭包并补两项回归；成员自身锁仍可在父容器未锁时单独解除，不引入自锁死。
5. 注记锚点选择的TypeScript类型缩窄错误已修，保留原失败诊断；最终类型由正常构建确认。

原日志、原reporter和失败截图/上下文见[诊断索引](evidence/m1-c2/diagnostic/local-artifacts.json)；较大的trace及全量旧用例产物保留本地路径、大小和hash，不宣称为可携带备份；C2目标附件及失败截图/上下文独立归档，避免重复复制全量旧用例的4K图片。通过批次保留原reporter的无损gzip及目标附件，[验证索引](evidence/m1-c2/verification-index.json)记录各批范围，[源码指纹](evidence/m1-c2/source-fingerprints.json)用于定位实际文件状态。
