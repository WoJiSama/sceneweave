# 织境 · Sceneweave 产品需求

织境帮助主持人把一个场景想法变成可编辑、可保存、可上桌的二维俯视地图。目标包含有厚墙、材质和细节的建筑室内，以及有不规则岸线、台地、悬崖和植被的自然室外；两者可存在于同一场景。体积感来自墙厚、离散高度、边缘表现与装饰阴影。项目以公开仓库维护，首个可用版本优先服务个人小团。品牌表达为“把故事画成可以探索的地方”。

视觉标准与素材流程见[视觉与素材体系](14-visual-and-assets.md#doc-14)，新版领域与完整工程按04/06独立实现，原M0存档与历史证据保持独立。

当前正常入口只接收唯一完整v1工程，以原v8的全量能力为基础，涵盖视觉、地形/区域、曲线连接、轻量装饰、簇状布景与连续地表规则。下文旧v2–v8编号仅用于追溯能力来源，不代表当前并行工程格式；实际接线与待验范围见[07](07-roadmap.md)，严格模型与独立迁入以[04](04-scene-document.md#development-single-v1)和[06](06-storage-and-export.md#development-single-v1-import)为准。旧整页工作台和旧格式入口继续退役，用户原件保持。

开发任务与进入M3的条件只在[路线图](07-roadmap.md)维护，验收步骤与证据要求只在[质量计划](09-quality-plan.md)维护。地形当前支持与拒绝边界见[地形专题](reference/terrain-generation.md)，旧结果见[产品历史台账](archive/m2-project-validation.md#doc-01-overview)。

## 1. 目标用户与主要任务

主要用户是为线下或线上跑团备团的主持人：愿意调整房间和道具，希望减少重复绘图，也需要牢牢控制线索、秘密与最终地图。次要用户是共享原创地图和素材的社区创作者。玩家首先接收导出的图片，不需要进入编辑器。

| 用户任务 | 预期结果 | 典型场景 |
|---|---|---|
| 从想法做出初稿 | 得到能继续编辑的房间、门墙、道具与注记 | “一栋有六个主要房间和暗廊的老宅” |
| 制作自然场景 | 绘制台地、岸线和通路，用材质与物件形成可用场景 | “有两层台地、坡道与浅滩的岩岛” |
| 制作混合场景 | 在同一工程编辑建筑、院子、道路和自然环境 | 海岸哨所的室内、露台、营地与跨高差通路 |
| 精确调整场景 | 改动局部时能理解受影响范围，并能撤销 | 移动书房家具；改变门的位置；修正通路 |
| 成批组织与编辑 | 框选物件、从右键进入适用操作，按图层选择、锁定和调整 | 只调整家具层，保留墙、地形和私密注记 |
| 定制素材与美术风格 | 默认或用户提供的素材保留原件，通过参数或AI产生可编辑的派生版本 | 先把一把椅子改成旧木风格，再用于桌椅组合及选定的其他组合 |
| 准备主持人信息 | 线索和秘密依附具体地点，便于备团查阅 | 书架后的字条、上锁的库房、桥面危险 |
| 输出玩家地图 | 图片符合预期尺寸，秘密不出现在输出中 | 给玩家发一张无暗廊、无线索文字的老宅图 |
| 跨次继续编辑 | 保存完整场景，重开和换设备后保留人工修改 | 下一次跑团前调整已经使用过的地图 |
| 局部找回旧方案 | 从命名快照恢复指定对象、属性或图层内容，其余新修改保留 | 恢复桌椅的旧外观，同时保留后来画好的露台 |

产品价值依次是可编辑的地图、可靠的保存与导出、可控的 AI 辅助。AI 的可用性不影响手工编辑闭环。

<a id="workspace-information-architecture-requirements"></a>
### 工作台导航与左右分工（2026-11-07确认的目标）

用户从整张地图的查找、组织与创作入口开始，再调整当前对象或当前操作。最左侧以场景、素材、建筑、地形、氛围、生成、AI、历史作为直接模块入口；左侧展开列表、筛选、工具/任务选择，中央画布工具条承担选择、平移、量尺及明确的创作快捷入口，右侧承担对象/图层/效果属性、活动工具参数和候选审阅。文件/工程名称、保存状态、撤销/重做与导出归顶部。生成长表单及AI对话可留左侧完整操作，不为了分栏把一次输入任务拆散。

目录浏览、画布选区、查看图层、当前绘制层及工具/候选目标必须独立；只读导航不丢草稿、不重定向操作。全图环境、持续图层规则、所选对象与明确区域分别说明作用域，空选区不能变成全图修改；右侧无选择时不堆放全局管理。素材分类与高级参数保留合理层级，去掉“资源面板”总分类和右下全局导航，不删除原有素材、历史、生成和交付能力。

该目标细化PRD-029/030/031/032/035/036/042，当前为**八项开发整改已实现，整合自检见07；正式验收与发布未完成**；完整交互、能力归属与迁移边界见[交互设计](reference/editor-and-architecture.md#workspace-information-architecture)，实施只在[07](07-roadmap.md#workspace-information-architecture-plan)，验收只在[09](09-quality-plan.md#workspace-information-architecture-acceptance)。不改变唯一完整工程v1、原事务/资源许可/保护/CAS、AI权限或玩家输出合同。

## 2. 范围与规则支持

<a id="map-detail-general-capability"></a>
### 细节能力的通用覆盖要求（2026-11-10用户补充）

地图细节及后续工具以当前完整v1中适用的合法对象、几何和显式参数为输入，不依赖某张样板的sceneId/presetId、固定实体ID或预排坐标。手工创建、样板、生成结果、导入和冷读所得的同类内容，均可从正常产品入口使用同一能力；编辑预览、完整保存、撤销/重做与适用的GM/player输出保持一致。样板仅用于展示和验证，样板专属构造代码不能单独作为通用功能完成的依据。已有AI/Worker/CLI暴露的适用能力须复用同一内核；新增AI权限仍需按05显式接入，不因通用化自动放开操作。

用户进一步确认先回看既有实现、提炼适合复用的逻辑，再接续后续任务；允许森林、岩岛、营地等配方具有风格与用途偏向。通用计算接受真实几何和参数，风格配方负责色板、尺度、疏密和构图，二者可分别复用；不要求每种风格适用于所有题材，也不为抽象而替换已可复用的内核。旧样板精确基线守卫仍保护旧配方；普通工具另接真实选择与明确参数。

当前工程能使用新能力，不等于打开时自动改图。新画法/素材/生成配方采用明确的新版本或选项；已有合法工程提供明确的预览/采用入口，保全固定源、人工编辑与旧算法重放。几何、支撑、锁、预算及秘密限制属于明确支持矩阵；每项交付须列覆盖入口和具体未支持项，缺少关键入口时记为部分实现或后续缺口，不能用单一样板通过概括所有工程。具体欠账和实施状态只在07维护，正式覆盖要求只在09维护。

<a id="map-detail-scope"></a>
### 地图细节与创作工具主线（2026-11-10用户确认）

目标是让道路、建筑、地形高差、草岩边界、植被与光影形成可读且自然的关系。参考图中的不规则台地、裸岩留白通道、崖面层次和多尺度草石细节用于提炼质量目标；素材数量或全图滤镜不能单独代表达成。参考项目研究是本主线的组成部分，每项结论要落到工具、规则、样板和适配边界。

- **道路**：默认吸附合法门前接入点、道路端点/现有道路，明确提示目标；绘路时按住Shift临时自由取点。完整道路宽度、转角、墙门/障碍、支撑和高差共同检查，有限绕行先预览；道路与营地/地表自然衔接。吸附不自动建立随门移动的持久连接，外观裁剪不代替通行合法性。
- **地形与小工具**：复用真实离散高程、崖壁、显式坡道/台阶与曲线；增加整面升降、取高、有限平整、局部台地/洼地及轮廓整理。先支持空地/简单依赖，复杂跨界与未支持联动给出明确原因。连续圆滑高度场只做独立原型和投入评估，尚未纳入生产能力；当前不扩展完整3D、同XY多可行走面或实时水流模拟。
- **背景与植被**：区分画布显示、可保存的纯色/透明输出、真实地表和环境布景。复用已有树/灌/草通道、覆盖率与簇，提供具有疏密和体量层次的预设，保留道路/门口净空及人工修改。
- **氛围**：在清楚的中性底图上统一光向、局部光雾与整体调色；复用现有有限滤镜，补配方和同视角临时旁路/对照。视觉效果不改变支撑、净宽、占地和玩家秘密。
- **创作顺序导航**：目标为场景→生成→地形→建筑→素材与布景→氛围，AI/历史在底部作为全程工具；固定顺序用于引导，允许跳过和往返。既有11月8日信息架构的左右职责与草稿保全继续有效，当前实现尚未按新顺序重排。

本节细化既有自然地形、编辑、素材、视觉和输出需求，不新增一套工程格式或独立验收阶段。完整设计分别归[交互](reference/editor-and-architecture.md#detail-workflow-and-road-tools)、[地形](reference/terrain-generation.md#terrain-sculpting-tools)和[视觉](14-visual-and-assets.md#map-detail-visual-design)；范围、依赖、跨会话分工和状态只归[07](07-roadmap.md#map-detail-mainline)，验收只归[09](09-quality-plan.md#map-detail-acceptance)。

### 2.1 首个可用版本 M1

M1 完成单用户、单逻辑楼层的二维俯视地图手工编辑流程：创建地图，用矩形、正交或含斜边的简单多边形绘制房间，编辑厚墙与门窗；绘制不规则地形、岸线、离散高度台地及明确的高差连接；铺设材质，摆放单件或组合物件，使用可控散布添加自然细节；提供框选/多选、上下文菜单、用户图层及可撤销的参数外观调整；管理注记与秘密、撤销重做、自动保存、命名快照和局部恢复、工程往返，以及主持人版和玩家版 PNG。

借鉴 Photoshop 的对象组织、非破坏性调整和局部找回历史的思路，具体行为以02为准。图层是管理对象与外观调整的单位，临时隐藏/独显服务编辑，不充当玩家秘密设置；排序不改变地面高程、Floor或通行。修改默认素材创建派生版本，原件和既有引用保持可追溯；恢复只产生针对选定范围的新事务。M1先支持对象和明确属性组，不包含像素绘画、完整滤镜栈、任意混合模式或PSD兼容；这些未列入当前交付承诺。

一个逻辑楼层可以有露台、悬崖等离散高差。渲染叠放顺序、可站立表面的高度和楼层分别表达。M1 不含同一位置上下重叠的可探索楼层、可旋转视角、连续地形网格或实时物理光照。房间与自然地形的创作工具不同，但共用坐标、选择、事务、素材和导出流程。

手工绘制过程允许暂时孤立的房间。未指定通达要求时显示连通提示，不阻止用户先完成几何草稿；生成请求或主持人显式指定的必达约束才作为提交硬约束。门锁、门的开闭、秘密与编辑锁分别表达。

手工闭环使用VIS-01「书房与露台」、VIS-02「双层岩岛」、SCN-04「海岸哨所」检查室内外及混合编辑；[SCN-01 雾灯宅](reference/acceptance-scenarios.md#doc-08-scn-01-雾灯宅)检查完整调查地图旅程。样板展示不代表完整产品验收通过。

首批内容采用协调的二维俯视手绘主题，覆盖室内、室外与混合场景所需的材质、物件及组合。验收看视觉一致性、实际编辑与保存导出结果；素材数量不单独作为完成标准。用户参考图仅用于提取视觉特征，不作为可分发素材来源。

### 从俯视图片新建可编辑工程（规划）

主持人可用一张授权室内地图新建独立场景。系统先提出墙、区域和物件候选；用户通过正负笔画、点选、框选和手描轮廓纠错，并可标明地面相对高低及上下连接。审阅时可隐藏原图、移动家具、查看补全区域及玩家视图。首个目标取固定图右上房间，成功交付后可在普通工作区编辑、保存、重开和导出。产品范围与图解见[专题设计](reference/image-to-project.md)，实施状态见[07](07-roadmap.md#image-to-project-plan)。

### 2.2 可选AI：地图能力复用与轻量入口

**2026-11-09用户确认下一步方向**：优先建设可供本地harness调用的地图语义能力接口，并试做页面“自然语言填写生成参数”；暂停扩建通用页面agent。完整内置AI独立成图不再作为首个可用版本的前置条件，仍保留为后续目标且不将旧失败改记通过。普通主持人继续用页面完成制作，不要求clone源码；本地harness先服务开发者与技术型创作者。现有AI入口、任务成果、授权、差异审阅、保护采用和撤销继续保全，已暴露能力的正确性与隐私检查不降级。设计归[AI入口与能力复用](reference/ai-entry-strategy.md)，顺序归[07](07-roadmap.md#ai-entry-development)，范围验收归[09](09-quality-plan.md#ai-entry-acceptance)。

现有创作助手以对话API为主：用户用自然语言制作场景或素材，AI通过应用内技能和有限工具，在独立任务草稿中连续建场景、摆放、修改SVG或外观参数、检查和调整。用户能看到流式文字与已验证草稿进展，中途打断并补充要求，最后预览完整差异、一次采用到主工程和撤销；不逐个物件确认。手工编辑、保存和PNG仍可独立使用。下述服务器/素材合同描述现有能力，不要求下一步继续扩展全部agent功能。

前端继续GitHub Pages；自有服务器从首版承担provider密钥、技能/工具循环、任务状态/检查点、取消和事件重连。主工程仍在浏览器，任务工作副本按明确上下文授权发送。浏览器依赖步骤可在离线时暂停，不承诺第一版关闭页面即可完整无人值守。

第一版不接生图API。新素材采用受限可编辑SVG与固定PNG结果，参数调节保留本地路径，场景和SVG转PNG由本地渲染完成。单组件→组合→明确范围渐进同化继续保留；风格任务不暗改位置、占地、支撑、秘密或人工记录，默认源与固定旧版不覆写。

AI能力的当前范围、工具和失败边界见[05](05-ai-and-generation.md)；实现、真实请求与部署结果分别保存在[AI历史台账](archive/ai-validation.md)和[工程历史台账](archive/m2-project-validation.md)。技术链路接通不代表完整Q4、视觉回读或用户P3通过。

### 2.3 小团验证 M3 与兼容导出 M4

M3 用三个原创场景验证调查、战术、叙事三类使用方式，记录备团时间、人工修正、输出问题和团内反馈。首个明确版本组合的 Universal VTT 适配与真实导入在验收阶段完成；M3进入条件以路线图为准，PNG保持基本交换能力。

| 使用偏好 | 首版产品表达 | 规则边界 |
|---|---|---|
| 调查，面向 CoC 类玩法 | 默认弱化格线；线索、地点、秘密、门锁和玩家描述 | 不是完整 CoC 规则裁定或官方内容包 |
| 战术，面向 D&D 5e 类玩法 | 可配置方格、量尺、障碍、掩体与危险区域；初始常用设置为 5 英尺／格 | 规则来源和版本单独记录，不内置完整战斗结算 |
| 叙事，面向匕首之心类玩法 | 地标、可交互环境、距离显示偏好、可选精确网格 | 不把抽象距离与某个固定米数强行等同 |

预设改变显示、量尺与建议选项，不重缩放已经存在的地图。首版对外分发通用“调查／战术／叙事”预设；兼容描述与内容许可见 [规则、素材与许可](10-rules-assets-and-licensing.md)。

### 2.4 当前非目标

- 世界、星球、城镇和文明模拟。
- 多人实时协同编辑、玩家在线房间、实时战斗主持与完整 VTT。
- 角色卡、自动检定、伤害结算、官方规则全文和商业模组内容库。
- 多楼层联动、可旋转 3D、连续地形网格、实时物理光照和实时战争迷雾；离散高度及装饰阴影属于 M1 范围。
- 首版整图文生图、整图反推可编辑结构、素材市场。
- 自动覆盖已有地图、未经采用直接应用 AI 结果、默认公开主持人工程。

### 2.5 分层容量目标（已确认，待实现）

扩容面向几十万实际物件，采用分层编辑能力：建筑、碰撞和支撑对象保留完整领域能力；密集装饰至少可逐个选择、移动、删除和撤销，其余能力按需开放并明确边界。密集装饰不默认承担碰撞或支撑职责，增加这些职责须走完整领域校验。两类内容均保存实际结果、稳定身份及适用的人工移动/删除记录，重开不靠seed重生成，也不用烘焙整图替代可编辑实例。

2026-11-05用户明确本项同时交付：**大地图操作与保存优化，以及普通事务从固定256向有负载依据的分档额度扩展**。前者覆盖内容增多后的操作和完整保存链，后者让实际可承担的大范围编辑不被固定256统一拦截；分档仍保持真实成员展开、多维保护、一次采用/撤销和失败保全。开发缩样只支持所测输入范围，长期几十万目标与正式容量声明仍须逐级验证。

**已确认的结构方向（2026-11-05）**：整体以核心和局部坐标组织，内部关系与对外端口分开；语义聚合体和空间区块分别负责可组合编辑与按需加载，存储复用完整基底及实际修改。细节和远处地图增加而本次影响较小时，减少重复检查和重复保存；不承诺所有操作随地图扩大都更快。建筑、自然和混合场景使用同一合同，成员仍可进入编辑、删除、退出、撤销及完整交付。详细设计归[通用生成器3.8](reference/general-map-generation.md#aggregate-spatial-capacity)，全部开发收束为[07一个大步骤下的a–j](07-roadmap.md#t2-implementation)。

本分支的新程序底图与接续已采用任务开始前选择并固定的512/1024/2048注册档位，语义编辑量与几何、计算、依赖、元数据及资源分别检查。普通手工分档初版采用独立manual多维保护，按当前保留内容与请求范围选择并冻结256/512/1024档位，内部点段/来源/身份不混成编辑次数；两类运行时策略均不改变完整v1工程格式或旧任务重放；普通分档选择器与生产UI自检仍待收口。轻量实例、有限簇状编辑、逐件编辑和人工记录已实现；更高负载仍是递进目标，不是当前容量或性能承诺。可支持规模、操作范围与设备条件须经分级负载验证后确定；预算语义归[04的演进目标](04-scene-document.md#capacity-budget-evolution)，任务顺序只在[路线图](07-roadmap.md#development)维护。

### 2.6 岩岛生成目标与本分支新增范围（已确认；实施状态见路线图）

2026-10-30用户原话：“我们这个分支后面会把上面的都做了,请你用一个文档来定我们的计划,然后还有一个问题就是如图是我们的生成目标,请你看一下上面的那些需求会对做这个有帮助,然后这些作为我们首先要做的东西,然后放到我们的需求路线图里面”。本次确认承接同次讨论列出的非性能需求；以下保留其产品范围和岩岛视觉目标，不表示视觉目标或正式验收已通过。2026-11-04用户进一步确认优先建设**通用地图生成器**，岩岛改为自然地貌配方和验证样例；新优先级取代本段原有的“岩岛先做”顺序，但不撤销已有需求或实现。总体设计归[通用生成器参考](reference/general-map-generation.md)，统一计划与逐项状态归[07](07-roadmap.md#general-map-generation-priority)，参考特征归[14](14-visual-and-assets.md#island-reference-target)，验收归[09](09-quality-plan.md#branch-feature-acceptance)。

- **参数化室内布局**：在独立新工程中指定房间数量、用途、净面积区间、最小净边长、共墙/分离关系、墙厚和可选正交走廊。预览实际可编辑房间/共享墙，修改参数后重新生成，保存冷读成功才切换；初次生成可按用途、面积和实际空间自动建议门、入口、通路及家具，放不下给缺项说明；用户之后可关闭、移动、删除，不自动补回。相邻、有门、实际通路净宽分别报告，初次建议不成为永久必达/必需家具约束。有限切分未找到与需求矛盾分别说明。
- **森林与营地**：显式林区、活动空地、入口和路线先行，再按覆盖目标与固定素材尺寸生成真实树木/草灌；完整支撑、足迹与通路保留区参与初次布置。界面支持独立平地、1–4空地、四侧入口与覆盖目标，预览后保存新工程。数量不足给实际缺项，非法支撑/指定路线冲突明确失败；手工删改和冷开不自动恢复。已有地形及多林区共享接口的有限范围见[领域设计](reference/general-map-generation.md#d-forest)。
- **火山自然场景**：单火口、离散高程山体、实际低陷火口和活动平台，入口经足宽阶梯/坡道与道路连接。火口内流道、危险标记、阻挡及移动代价是明确独立参数，熔岩材质不决定物理或危险。工程面板支持预览、参数变化失效和独立保存冷开；后来手工删改不补回。首版只在空白基底生成，跨高差流道、多火口、连续三维及喷发模拟不在范围，详见[领域设计](reference/general-map-generation.md#d-volcano)。
- **有限混合场景**：一个建筑与森林或火山组成同Floor完整候选，建筑绑定真实地面/平台高程，真实外门连接足宽室外路线，植被避开建筑与通路并复查火山连接。可修改题材、范围、种子、房间数量/用途、家具建议及森林密度；保存后自由删改，现有受限局部操作保留人工状态。当前不支持任意多建筑联合搜索或建筑拓扑重生成，详见[混合边界](reference/general-map-generation.md#e-mixed-delivery)。
- **统一执行与采用**：室内、森林、火山和有限混合共用参数→预览→诊断→采用入口，默认本机Worker，可显式选择不调用模型的服务端。采用前仍本机完整重放及真实资源校验，新建保存冷读后打开；受限局部修改继续本机保护/CAS与一次撤销。四领域生成尚未授予AI工具权限，详见[执行边界](reference/general-map-generation.md#d-delivery)。
- **受限局部重生成**：在已保存生成结果中选择一个房间的家具、一个林区的树/灌/草通道、一个火山表面的底材或火口轮廓。直接按当前真实几何和人工状态生成候选，列出实际写入与只读依赖，保护后一次采用/撤销；人工移动、删除、退出、锁及范围外内容保留。火口只调整现有点坐标，破坏连接/支撑时拒绝，建筑拓扑重写尚不支持；详细范围见[局部设计](reference/general-map-generation.md#d-regeneration)。
- **可编辑的岩岛生成结果**：不对称主陆块、离岸礁石、裸岩活动区、草地台地、可读崖面、浅水与岸纹、成簇植被及真实高差连接。先由程序生成具备结构与基础视觉质量的候选，再允许AI在确切结果上受控精修；森林河谷、湖岸/丘陵及混合场景继续适用。使用原创或明确许可素材，不从参考图提取像素、自动推断物理尺度或复制具体地图布局。
- **密集装饰与素材摄取**：落实2.5的轻量可编辑装饰；在已有单张PNG/JPEG/WebP导入上补文件夹、素材ZIP的批量预览/采用及受限外部SVG导入，逐项保留固定定义、真实图像尺寸、占地、许可和资源闭包。用户能明确选择本批采用项，失败不留下半批资源或场景。
- **曲线楼梯与组件变形**：支持直行、曲线及之字回折连接和石砌/木梯/自然岩阶表现；支持明确适用组件的弯曲、局部拉伸与控制点编辑，保留细节比例及显式物理语义。先覆盖岸/崖/阶等岩岛用途，再扩展其他适用组件；任意位图无损变形不作为通用承诺。
- **精确与批量编辑**：提供子格锚点吸附，保持整数毫米及原格尺寸；提供填充柄式多份复制预览、显式数量/间距/方向和一次采用/撤销，覆盖独立物件与具有明确成员/支撑规则的组合。既有单件放置和复制继续有效。
- **建筑工具补齐**：正交绘制、直接拖边、合法房间/墙删除、整组建筑变换与通用拓扑修复的受支持操作和结果预览。完整预览共享墙、门窗、支撑物件和注记影响，无法保全合法关系时拒绝；不据此开放任意自动拓扑改写或跨会话结构恢复。
- **AI创作收尾与复核**：将阶段原子操作、预算边界的合法草稿保全/结构化缺项说明、实际公开画面复核及有限修正整合到当前协议。旧分支实现只能作为候选来源，须适配当前授权、分类账本及严格版本；完成状态不代替用户审阅。v3/v4地形与现有v2视觉创作之间的版本能力必须显式设计，不从已有接续入口推定支持全部外观工具。
- **交付闭环**：完成首个明确Foundry/导入器组合的VTT映射，并执行真实AI、视觉/P3、保存迁移/故障、跨浏览器及目标VTT验收；M3真实小团仍在验收通过后开展。

本次未把此前仅作为探索的可旋转2.5D/3D、实时风雾/物理光照、任意脚本滤镜、图片反推SVG或生图API加入交付范围。已有静态灯光/雾/滤镜、单图素材导入、程序底图接续和增量历史继续复用。新持久语义或任务协议先同步04/05/06的当前严格模型、授权、数据保全和拒绝边界；开发期工程直接演进唯一v1，算法/协议和额度按各自合同处理。

## 4. 初始成功指标

下表是待测产品目标；M0 已有的几何原型数据仅适用于13记录的负载。产品效率指标先用于 M1／M3 校准，不用一次个人试用推断普遍用户效果。几何、秘密、存档和撤销属于发布硬门槛。

| 指标 | 初始目标与采样方式 | 性质 |
|---|---|---|
| 手工闭环完成 | 主持人熟悉基本操作后，在 45 分钟内完成雾灯宅的六个主要房间、暗廊、门、基础家具、注记和两种 PNG；记录首次与熟悉后用时 | 待验证的效率目标 |
| 视觉与混合闭环 | 两个可编辑样板及海岸哨所完成14规定的视觉、修改、往返与导出检查；室外制作时间在 M1-B 建立基线 | M1 门槛；不沿用雾灯宅的45分钟假设 |
| 编辑稳定性 | 各阶段适用的 VIS 样板与 SCN 固定场景验收记录中，成功提交的文档几何／引用违规为 0 | 硬门槛 |
| 玩家秘密保护 | 固定秘密清单中可见泄漏为 0，包括私密文字、门标记、隐藏轮廓和遮罩上方阴影 | 硬门槛 |
| 保存与撤销 | 固定往返及撤销案例无不可解释的数据差异；不丢失已确认保存的编辑 | 硬门槛 |
| 局部恢复与批量范围 | 选定属性和依赖闭包恢复正确，范围外对象/字段及未选秘密设置保持；层操作和同化不跨范围修改；失败无部分提交 | 硬门槛；恢复权限、连续性与拒绝边界见04，实际证据见历史索引 |
| 基线交互 | 在记录硬件、浏览器和数据的 50×50 显示网格、500 物件基线上，交互帧 p95 ≤ 33 ms，普通编辑提交 p95 ≤ 100 ms | 目标保持；M0 程序符号首轮数据见13，M1真实素材复测；2,000物件用于压力评估 |
| 图片输出 | 能完成 4K PNG 输出，尺寸正确且秘密保护通过；记录耗时与峰值资源使用 | 功能门槛；不预设绝对耗时 |
| AI 可控性 | 所有实际采用提案的硬约束违规为 0；预览前后锁定和范围规则保持成立 | 硬门槛 |
| AI 有用性 | 固定场景/局部/SVG/组合/扩围任务记录可采用率、风格、手工修正、拒绝原因、时间和实际/未知成本；参数、工具与模型质量分开 | 统计指标，暂无已测通过率；阈值由M2-3/4固定任务校准 |
| 小团价值 | 每个场景至少有一份主持人反馈，说明是否能用于备团、最耗时步骤与一次实际修正 | M3 证据要求 |

## 5. 发布顺序与完成定义

开发顺序与剩余任务只在[路线图](07-roadmap.md)维护，完整验收从[质量计划](09-quality-plan.md)执行。一个需求完成需要相应证据，不能只以按钮出现或样板展示作为完成；计划、已实现、已验证和已发布分别成立。

发布、用户P3签收、真实模型质量、性能及目标软件导入各自需要对应证据；修复后按质量计划复验，不能用旧批次技术通过替代本轮验收。
