# 织境 · Sceneweave 产品需求

状态：M0 几何版原型首轮验证完成，M1—M4 未开始。本文主要定义产品目标，不能把所有能力与验收条件都视为已实现；当前能力和实际测试范围见[M0 验证报告](13-m0-validation.md)。

当前提供两公开房间与密道的简化雾灯宅，完成已有实体调整、原子历史、几何保存与双受众导出的首轮检查。完整 SCN-01/02/03、房间自由绘制、素材管线、当前占地路径、AI、Worker、PWA 与 UVTT 仍在后续范围；真实配额耗尽和跨浏览器未验证。

织境帮助主持人把一个场景想法变成可编辑、可保存、可上桌的二维地图。项目以公开仓库维护，首个可用版本优先服务个人小团。品牌表达为“把故事画成可以探索的地方”。

## 1. 目标用户与主要任务

主要用户是为线下或线上跑团备团的主持人：愿意调整房间和道具，希望减少重复绘图，也需要牢牢控制线索、秘密与最终地图。次要用户是共享原创地图和素材的社区创作者。玩家首先接收导出的图片，不需要进入编辑器。

| 用户任务 | 预期结果 | 典型场景 |
|---|---|---|
| 从想法做出初稿 | 得到能继续编辑的房间、门墙、道具与注记 | “一栋有六个主要房间和暗廊的老宅” |
| 精确调整场景 | 改动局部时能理解受影响范围，并能撤销 | 移动书房家具；改变门的位置；修正通路 |
| 准备主持人信息 | 线索和秘密依附具体地点，便于备团查阅 | 书架后的字条、上锁的库房、桥面危险 |
| 输出玩家地图 | 图片符合预期尺寸，秘密不出现在输出中 | 给玩家发一张无暗廊、无线索文字的老宅图 |
| 跨次继续编辑 | 保存完整场景，重开和换设备后保留人工修改 | 下一次跑团前调整已经使用过的地图 |

产品价值依次是可编辑的地图、可靠的保存与导出、可控的 AI 辅助。AI 的可用性不影响手工编辑闭环。

## 2. 范围与规则支持

### 2.1 首个可用版本 M1

M1 完成单用户、单层、二维场景地图的手工编辑流程：创建地图，正交绘制房间，编辑墙与门窗，摆放基础道具，标记区域与注记，设置秘密与玩家显示，撤销和重做，本地自动保存，导入和导出工程，导出主持人版和玩家版 PNG。

手工绘制过程允许暂时孤立的房间。未指定通达要求时显示连通提示，不阻止用户先完成几何草稿；生成请求或主持人显式指定的必达约束才作为提交硬约束。门锁、门的开闭、秘密与编辑锁分别表达。

首张验收地图是 [SCN-01 雾灯宅](08-test-scenarios.md#scn-01-雾灯宅)。M1 只需一套一致的基础平面图风格，以及覆盖老宅验收任务的原创或可再分发素材。素材数量不作为完成标准。

### 2.2 AI 版本 M2

M2 增加新场景初稿、选区修改和地点注记辅助。提案必须有范围、预览、约束校验和明确采用步骤。局部提案能按相互独立的操作组采用，依赖同组的几何变化一起采用。生成初稿以房屋和地下城为首批类型，开放营地首先通过手工编辑验证。

AI 不能绕过人工编辑使用的文档校验、锁定和事务。一次采用形成一次可撤销的操作；未采用的候选不改变当前场景。详见 [AI 与生成](05-ai-and-generation.md)。

新生成的文字内容，包括意图给玩家看的描述，都先保存为主持人草稿。M2 只允许直接改写既有私密注记；公开注记的改写产生一份新的私密草稿，再由主持人审阅与发布，避免私密上下文进入已公开正文。

### 2.3 小团验证 M3 与兼容导出 M4

M3 用三个原创场景验证调查、战术、叙事三类使用方式，记录备团时间、人工修正、输出问题和团内反馈。M4 再实现一个明确版本组合的 Universal VTT 导入目标；PNG 保持基本交换能力。

| 使用偏好 | 首版产品表达 | 规则边界 |
|---|---|---|
| 调查，面向 CoC 类玩法 | 默认弱化格线；线索、地点、秘密、门锁和玩家描述 | 不是完整 CoC 规则裁定或官方内容包 |
| 战术，面向 D&D 5e 类玩法 | 可配置方格、量尺、障碍、掩体与危险区域；初始常用设置为 5 英尺／格 | 规则来源和版本单独记录，不内置完整战斗结算 |
| 叙事，面向匕首之心类玩法 | 地标、可交互环境、距离显示偏好、可选精确网格 | 不把抽象距离与某个固定米数强行等同 |

预设改变显示、量尺与建议选项，不重缩放已经存在的地图。首版对外分发通用“调查／战术／叙事”预设；兼容描述与内容许可见 [规则、素材与许可](10-rules-assets-and-licensing.md)。

### 2.4 当前非目标

- 世界、星球、城镇和文明模拟。
- 多人实时协同编辑、玩家在线房间、实时战斗主持与完整 VTT。
- 角色卡、自动检定、伤害结算、官方规则全文和商业模组内容库。
- 多楼层联动、3D、复杂动态光照和实时战争迷雾。
- 首版整图文生图、整图反推可编辑结构、素材市场。
- 自动覆盖已有地图、未经采用直接应用 AI 结果、默认公开主持人工程。

## 3. 可验收需求

“应”表示对应里程碑的验收要求。需求的领域语义以 [场景文档契约](04-scene-document.md) 为准，界面行为见 [编辑器交互](02-editor-ux.md)。

| ID | 阶段 | 需求 | 可验收标准 |
|---|---|---|---|
| PRD-001 | M1 | 创建单层场景 | 能填写名称、选择通用预设、设置画布范围与显示网格；创建后存在一个楼层，能够直接开始手工编辑 |
| PRD-002 | M1 | 编辑房间与共享墙 | 能用正交边界完成雾灯宅；相邻房间只有一份共享墙；自交、重叠及无法保持引用的修改不能提交，并指出位置 |
| PRD-003 | M1 | 编辑门窗 | 门窗吸附到有效墙，支持位置、宽度及适用状态调整；拆墙或改房间时同步处理门窗，不能留下无归属开口 |
| PRD-004 | M1 | 布置道具与区域 | 能放置、移动、旋转和删除道具，标注危险或用途区域；影响通行的属性可检查，纯装饰不会被当成实体障碍 |
| PRD-005 | M1 | 管理地点信息 | 注记和线索可绑定房间、道具或位置；主持人能区分私密内容和公开内容，新注记默认私密 |
| PRD-006 | M1 | 管理选择与锁定 | 单选、多选和范围选择可用；被锁定对象不能被拖动、删除或作为邻接依赖被间接修改；主持人可明确解锁 |
| PRD-007 | M1 | 事务与撤销 | 一次拖动或确认的批量编辑对应一次撤销；撤销恢复几何、门窗关系、属性和可见性；重做复原结果；修订号继续增长 |
| PRD-008 | M1 | 自动保存与恢复 | 显示未保存／保存中／已保存／保存失败／外部更新冲突；重开恢复最后成功保存的完整文档；保存失败保留内存编辑并提供工程导出；冲突时保留本地图并可另存新场景 |
| PRD-009 | M1 | 工程迁移与备份 | 工程导出后可在新的本地存储环境导入；几何、秘密、预设快照和人工修改往返一致；缺失素材明确呈现占位与清单 |
| PRD-010 | M1 | 主持人 PNG | 可选择尺寸、格线与注记显示，预览与输出一致；输出能保留主持人需要的秘密信息，并明确标为主持人版 |
| PRD-011 | M1 | 玩家 PNG | 必须预览玩家视图；未揭示秘密门表现为普通墙，隐藏空间被保守遮罩；私密文字、图标及装饰阴影均不泄漏；工程文件不作为玩家输出选项 |
| PRD-012 | M1 | 离线手工闭环 | 在应用资源已可用、AI 未配置或不可用时，能完成雾灯宅的手工编辑、保存、工程输出和两种 PNG 导出 |
| PRD-013 | M2 | 生成可编辑初稿 | 从空场景或新场景入口生成房屋／地下城；生成结果经检查后可预览、采用并继续手工编辑；当前已有场景不被替换 |
| PRD-014 | M2 | 选区与受控局部修改 | 明确选择房间或对象后请求修改；锁定对象、选区外对象和其不允许修改的依赖均保持原值；必要扩围必须由主持人重新选择 |
| PRD-015 | M2 | AI 提案采用 | 提案列出改动和警告；可采用完整提案或独立操作组；依赖不完整的组不能采用；一次采用对应一次撤销 |
| PRD-016 | M2 | AI 失败与过期处理 | 取消、超时、校验失败和过期提案都不改变当前文档；等待期间发生编辑时，旧提案必须重新生成或重新预览，不能自动应用 |
| PRD-017 | M2 | 主持人文本辅助 | 生成地点描述、线索和互动点并绑定目标；新文本默认私密；既有公开注记的改写生成私密草稿；AI 不自行揭示、解锁或改变既有内容的可见性 |
| PRD-018 | M3 | 三类使用偏好与样例 | 三个场景均能完成对应人工流程；切换预设后世界尺寸和几何不变；距离显示与所选预设快照一致 |
| PRD-019 | M3 | 实际备团验证 | 三个场景各有真实小团使用记录，保留任务完成、阻塞、修正次数和导出反馈；主持人演练可作预验收证据，不能替代真实团测完成条件 |
| PRD-020 | M4 | 首个 VTT 目标 | 固定目标软件和导入器版本，实测图像、比例、墙、门及明确支持的属性；不支持项有报告；不声称全平台无损兼容 |

## 4. 初始成功指标

下表是待测目标，D0 没有测量数据。产品效率指标先用于 M1／M3 校准，不用一次个人试用推断普遍用户效果。几何、秘密、存档和撤销属于发布硬门槛。

| 指标 | 初始目标与采样方式 | 性质 |
|---|---|---|
| 手工闭环完成 | 主持人熟悉基本操作后，在 45 分钟内完成雾灯宅的六个主要房间、暗廊、门、基础家具、注记和两种 PNG；记录首次与熟悉后用时 | 待验证的效率目标 |
| 编辑稳定性 | 三个固定场景的验收记录中，成功提交的文档几何／引用违规为 0 | 硬门槛 |
| 玩家秘密保护 | 固定秘密清单中可见泄漏为 0，包括私密文字、门标记、隐藏轮廓和遮罩上方阴影 | 硬门槛 |
| 保存与撤销 | 固定往返及撤销案例无不可解释的数据差异；不丢失已确认保存的编辑 | 硬门槛 |
| 基线交互 | 在记录硬件、浏览器和数据的 50×50 显示网格、500 物件基线上，交互帧 p95 ≤ 33 ms，普通编辑提交 p95 ≤ 100 ms | 目标保持；M0 程序符号首轮数据见13，M1真实素材复测；2,000物件用于压力评估 |
| 图片输出 | 能完成 4K PNG 输出，尺寸正确且秘密保护通过；记录耗时与峰值资源使用 | 功能门槛；不预设绝对耗时 |
| AI 可控性 | 所有实际采用提案的硬约束违规为 0；预览前后锁定和范围规则保持成立 | 硬门槛 |
| AI 有用性 | 对固定提示语逐次记录成功候选率、需人工修正次数、完成时间、成本及原因；模型和阈值由 M2 小样本基线后确定 | 统计指标，暂无已测通过率 |
| 小团价值 | 每个场景至少有一份主持人反馈，说明是否能用于备团、最耗时步骤与一次实际修正 | M3 证据要求 |

## 5. 发布顺序与完成定义

| 里程碑 | 交付重点 | 当前状态 |
|---|---|---|
| D0 | 产品、交互、数据、架构、AI、保存、许可、样例和验证文档 | 文档基线已完成 |
| M0 | 共享墙门、保存往返、渲染性能、玩家遮罩和 4K 导出的风险验证 | 几何版原型首轮验证完成；完整退出门槛未全部验收 |
| M1 | 雾灯宅手工编辑与导出闭环 | 未开始 |
| M2 | AI 初稿、选区修改与可撤销提案 | 未开始 |
| M3 | 三场景小团验证与预设完善 | 未开始 |
| M4 | 首个 Universal VTT 目标适配 | 未开始 |

一个需求完成需要对应证据，不能仅以按钮出现或界面展示样例作为完成。风险验证与后续排期见 [开发路线](07-roadmap.md)，测试层次与证据记录见 [质量计划](09-quality-plan.md)。
