# 织境 · Sceneweave 产品需求

状态：M0原型首轮、M1-A设计、B1素材基础、B2/B3可编辑样板与B4联合矩阵已交付；B5、完整M1及M2–M4仍待推进。历史见13/17/18/19，双样板诊断、隐私和存档范围见[20](20-m1b-b4-validation.md)。

当前提供简化雾灯宅、可编辑VIS-01书房与露台和VIS-02双层岩岛。完整素材工程、有限结构/组合/地形/散布编辑、样板门口与台阶接入净空、原子历史、保存和双受众4K已有实现。完整SCN-01/02/03/04、房间自由绘制、通用素材管理、全图占地路径、AI、Worker、PWA与UVTT仍在后续范围；真实配额耗尽和跨浏览器未验证。

织境帮助主持人把一个场景想法变成可编辑、可保存、可上桌的二维俯视地图。目标包含有厚墙、材质和细节的建筑室内，以及有不规则岸线、台地、悬崖和植被的自然室外；两者可存在于同一场景。体积感来自墙厚、离散高度、边缘表现与装饰阴影。项目以公开仓库维护，首个可用版本优先服务个人小团。品牌表达为“把故事画成可以探索的地方”。

视觉标准与素材流程见[视觉与素材体系](14-visual-and-asset-system.md)，新版领域与完整工程按04/06独立实现，原M0存档与历史证据保持独立。

## 1. 目标用户与主要任务

主要用户是为线下或线上跑团备团的主持人：愿意调整房间和道具，希望减少重复绘图，也需要牢牢控制线索、秘密与最终地图。次要用户是共享原创地图和素材的社区创作者。玩家首先接收导出的图片，不需要进入编辑器。

| 用户任务 | 预期结果 | 典型场景 |
|---|---|---|
| 从想法做出初稿 | 得到能继续编辑的房间、门墙、道具与注记 | “一栋有六个主要房间和暗廊的老宅” |
| 制作自然场景 | 绘制台地、岸线和通路，用材质与物件形成可用场景 | “有两层台地、坡道与浅滩的岩岛” |
| 制作混合场景 | 在同一工程编辑建筑、院子、道路和自然环境 | 海岸哨所的室内、露台、营地与跨高差通路 |
| 精确调整场景 | 改动局部时能理解受影响范围，并能撤销 | 移动书房家具；改变门的位置；修正通路 |
| 准备主持人信息 | 线索和秘密依附具体地点，便于备团查阅 | 书架后的字条、上锁的库房、桥面危险 |
| 输出玩家地图 | 图片符合预期尺寸，秘密不出现在输出中 | 给玩家发一张无暗廊、无线索文字的老宅图 |
| 跨次继续编辑 | 保存完整场景，重开和换设备后保留人工修改 | 下一次跑团前调整已经使用过的地图 |

产品价值依次是可编辑的地图、可靠的保存与导出、可控的 AI 辅助。AI 的可用性不影响手工编辑闭环。

## 2. 范围与规则支持

### 2.1 首个可用版本 M1

M1 完成单用户、单逻辑楼层的二维俯视地图手工编辑流程：创建地图，用矩形、正交或含斜边的简单多边形绘制房间，编辑厚墙与门窗；绘制不规则地形、岸线、离散高度台地及明确的高差连接；铺设材质，摆放单件或组合物件，使用可控散布添加自然细节；管理注记与秘密、撤销重做、自动保存、工程往返，以及主持人版和玩家版 PNG。

一个逻辑楼层可以有露台、悬崖等离散高差。渲染叠放顺序、可站立表面的高度和楼层分别表达。M1 不含同一位置上下重叠的可探索楼层、可旋转视角、连续地形网格或实时物理光照。房间与自然地形的创作工具不同，但共用坐标、选择、事务、素材和导出流程。

手工绘制过程允许暂时孤立的房间。未指定通达要求时显示连通提示，不阻止用户先完成几何草稿；生成请求或主持人显式指定的必达约束才作为提交硬约束。门锁、门的开闭、秘密与编辑锁分别表达。

M1 按 M1-A 视觉规范与契约设计、M1-B 两个可编辑样板、M1-C 完整手工工具与组件库、M1-D 混合场景及验收推进。两个先行样板为 VIS-01「书房与露台」和 VIS-02「双层岩岛」，随后用 SCN-04「海岸哨所」验证两套工具在同一工程的协作；[SCN-01 雾灯宅](08-test-scenarios.md#scn-01-雾灯宅)保留完整调查地图的闭环验收。样板展示通过不代表完整 M1 完成。

首批内容采用协调的二维俯视手绘主题，覆盖室内、室外与混合场景所需的材质、物件及组合。验收看视觉一致性、实际编辑与保存导出结果；素材数量不单独作为完成标准。用户参考图仅用于提取视觉特征，不作为可分发素材来源。

### 2.2 AI 版本 M2

M2 使用已入库、通过尺寸与来源检查的素材，增加新场景初稿、选区修改、组合布置和地点注记辅助。提案必须有范围、预览、约束校验和明确采用步骤。局部提案能按相互独立的操作组采用，依赖同组的几何变化一起采用。生成初稿以房屋和地下城为首批类型；室外先通过 M1 手工编辑验证，已有地形上的布景可在05定义专项受控操作后接入。M2 不默认承诺任意自然地形生成，也不生成未入库的素材图片。

AI 不能绕过人工编辑使用的文档校验、锁定和事务。一次采用形成一次可撤销的操作；未采用的候选不改变当前场景。详见 [AI 与生成](05-ai-and-generation.md)。

新生成的文字内容，包括意图给玩家看的描述，都先保存为主持人草稿。M2 只允许直接改写既有私密注记；公开注记的改写产生一份新的私密草稿，再由主持人审阅与发布，避免私密上下文进入已公开正文。

AI 新素材制作列为 M2 之后的独立可选阶段 A1：生成图片候选，经背景、俯视角、尺寸、占地、风格及来源审查后才入库，不能直接改写当前地图。A1 不阻塞 M3 小团验证或 M4 兼容导出，流程见14。

### 2.3 小团验证 M3 与兼容导出 M4

M3 用三个原创场景验证调查、战术、叙事三类使用方式，记录备团时间、人工修正、输出问题和团内反馈。M4 再实现一个明确版本组合的 Universal VTT 导入目标；PNG 保持基本交换能力。

| 使用偏好 | 首版产品表达 | 规则边界 |
|---|---|---|
| 调查，面向 CoC 类玩法 | 默认弱化格线；线索、地点、秘密、门锁和玩家描述 | 不是完整 CoC 规则裁定或官方内容包 |
| 战术，面向 D&D 5e 类玩法 | 可配置方格、量尺、障碍、掩体与危险区域；初始常用设置为 5 英尺／格 | 规则来源和版本单独记录，不内置完整战斗结算 |
| 叙事，面向匕首之心类玩法 | 地标、可交互环境、距离显示偏好、可选精确网格 | 不把抽象距离与某个固定米数强行等同 |

预设改变显示、量尺与建议选项，不重缩放已经存在的地图。首版对外分发通用“调查／战术／叙事”预设；兼容描述与内容许可见 [规则、素材与许可](10-rules-assets-and-licensing.md)。

### 2.4 当前非目标

- 世界、星球、城镇和文明模拟。
- 多人实时协同编辑、玩家在线房间、实时战斗主持与完整 VTT。
- 角色卡、自动检定、伤害结算、官方规则全文和商业模组内容库。
- 多楼层联动、可旋转 3D、连续地形网格、实时物理光照和实时战争迷雾；离散高度及装饰阴影属于 M1 范围。
- 首版整图文生图、整图反推可编辑结构、素材市场。
- 自动覆盖已有地图、未经采用直接应用 AI 结果、默认公开主持人工程。

## 3. 可验收需求

“应”表示对应里程碑的验收要求。需求的领域语义以 [场景文档契约](04-scene-document.md) 为准，界面行为见 [编辑器交互](02-editor-ux.md)。

| ID | 阶段 | 需求 | 可验收标准 |
|---|---|---|---|
| PRD-001 | M1 | 创建单层场景 | 能填写名称、选择通用预设、设置画布范围与显示网格；创建后存在一个逻辑楼层，可选择建筑或地形工具；离散高差不产生隐含新楼层 |
| PRD-002 | M1 | 编辑房间与共享墙 | 能用正交与斜边简单多边形完成样板和雾灯宅；可编辑真实墙厚，相邻房间只有一份共享墙；自交、重叠及无法保持引用的修改不能提交，并指出位置 |
| PRD-003 | M1 | 编辑门窗 | 门窗吸附到有效墙，支持位置、宽度及适用状态调整；拆墙或改房间时同步处理门窗，不能留下无归属开口 |
| PRD-004 | M1 | 布置道具与区域 | 能放置、移动、旋转和删除道具，标注危险或用途区域；影响通行的属性可检查，纯装饰不会被当成实体障碍 |
| PRD-005 | M1 | 管理地点信息 | 注记和线索可绑定房间、道具或位置；主持人能区分私密内容和公开内容，新注记默认私密 |
| PRD-006 | M1 | 管理选择与锁定 | 单选、多选和范围选择可用；被锁定对象不能被拖动、删除或作为邻接依赖被间接修改；主持人可明确解锁 |
| PRD-007 | M1 | 事务与撤销 | 一次拖动或确认的批量编辑对应一次撤销；撤销恢复几何、门窗关系、属性和可见性；重做复原结果；修订号继续增长 |

| PRD-010 | M1 | 主持人 PNG | 可选择尺寸、格线与注记显示，预览与输出一致；输出能保留主持人需要的秘密信息，并明确标为主持人版 |

| PRD-021 | M1 | 材质与统一主题 | 地面与墙面可更换材质；铺装真实尺度、方向和接缝可调整；改变轮廓不拉伸纹理；主题不隐式改变几何、通行或公开设置 |

## 4. 初始成功指标

下表是待测产品目标；M0 已有的几何原型数据仅适用于13记录的负载。产品效率指标先用于 M1／M3 校准，不用一次个人试用推断普遍用户效果。几何、秘密、存档和撤销属于发布硬门槛。

| 指标 | 初始目标与采样方式 | 性质 |
|---|---|---|
| 手工闭环完成 | 主持人熟悉基本操作后，在 45 分钟内完成雾灯宅的六个主要房间、暗廊、门、基础家具、注记和两种 PNG；记录首次与熟悉后用时 | 待验证的效率目标 |
| 视觉与混合闭环 | 两个可编辑样板及海岸哨所完成14规定的视觉、修改、往返与导出检查；室外制作时间在 M1-B 建立基线 | M1 门槛；不沿用雾灯宅的45分钟假设 |
| 编辑稳定性 | 各阶段适用的 VIS 样板与 SCN 固定场景验收记录中，成功提交的文档几何／引用违规为 0 | 硬门槛 |
| 玩家秘密保护 | 固定秘密清单中可见泄漏为 0，包括私密文字、门标记、隐藏轮廓和遮罩上方阴影 | 硬门槛 |
| 保存与撤销 | 固定往返及撤销案例无不可解释的数据差异；不丢失已确认保存的编辑 | 硬门槛 |
| 基线交互 | 在记录硬件、浏览器和数据的 50×50 显示网格、500 物件基线上，交互帧 p95 ≤ 33 ms，普通编辑提交 p95 ≤ 100 ms | 目标保持；M0 程序符号首轮数据见13，M1真实素材复测；2,000物件用于压力评估 |
| 图片输出 | 能完成 4K PNG 输出，尺寸正确且秘密保护通过；记录耗时与峰值资源使用 | 功能门槛；不预设绝对耗时 |
| AI 可控性 | 所有实际采用提案的硬约束违规为 0；预览前后锁定和范围规则保持成立 | 硬门槛 |
| AI 有用性 | 对固定提示语逐次记录成功候选率、需人工修正次数、完成时间、成本及原因；模型和阈值由 M2 小样本基线后确定 | 统计指标，暂无已测通过率 |
| 小团价值 | 每个场景至少有一份主持人反馈，说明是否能用于备团、最耗时步骤与一次实际修正 | M3 证据要求 |
