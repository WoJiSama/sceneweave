## 主定义原则

对象字段冲突以04为待修订主定义，存储/导出以06为主，AI协议以05为主。发现其他文档与主定义不一致时应一起修订，不能据“优先级”忽略实际矛盾。产品范围变化先改01与11，再调整实现/验收契约。

需求编号使用PRD，任务使用M阶段编号，质量用例使用QA，场景使用SCN。它们分别代表用户价值、开发工作、验证证据和固定内容，不互相代替。样例中的H/D/N短编号仅是测试别名，实际实体仍使用稳定ID。

## 共同术语

| 术语 | 含义 |
|---|---|
| GM / 主持人 | 制作和持有完整工程的人，可访问秘密和线索 |
| 玩家投影 | 只含玩家可见内容的临时渲染数据，首版输出为PNG |
| SceneDocument | 完整可编辑场景的持久化模型，格式与渲染引擎独立 |
| revision | 文档成功事务的单调序号，撤销后也不会倒退 |
| editLocked / locked | 前者禁止编辑；后者是门窗通行锁，二者独立 |
| required | 房间必须有从指定入口出发的结构连接；不等于门当下敞开 |
| CommandBatch | 一次完整、可校验、原子提交和撤销的编辑批次 |
| Proposal | 尚待本机校验及主持人采用的AI建议 |
| 本地优先 | 核心数据与编辑在本地；不自动表示已经完成PWA离线冷启动 |

## 当前交付边界

D0交付的是一套可以指导后续实现的设计文档。尚未创建应用骨架、依赖、源码、自动化测试、CI或运行环境；性能目标和兼容矩阵均不是测试结果。用户明确开始开发后，从M0进入，并同步维护仓库状态。
