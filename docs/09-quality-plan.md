# 质量验证与验收计划

状态：M0 几何版原型首轮验证完成，本文仍定义完整里程碑的验收目标。已运行 95 个单元测试（8 文件）、13 个真实 Chrome 浏览器测试，生产构建与生产依赖审计通过；实际环境、用例、性能与隐私范围见[M0 验证报告](13-m0-validation.md)。不将这些测试数量等同于全部 QA 编号或 M0 退出门槛通过。

完整 SCN-01/02/03、真实小团、真实图片素材、当前占地路径、AI、Worker、PWA 与 UVTT 尚未实现或验证；真实存储配额耗尽和跨浏览器也未验证。本文的性能阈值仍是目标，实测数值只在13中按方法和范围报告。

本计划服务于[产品定义](01-product.md)中的编辑、保存、双版本导出和可控 AI 流程。验收场景以[固定样例](08-test-scenarios.md)的 SCN-01/02/03 为准；协议、默认行为和边界分别引用[场景文档](04-scene-document.md)、[AI 与生成](05-ai-and-generation.md)、[存储与导出](06-storage-and-export.md)，不在此重定义数据结构。

## 1. 门槛与证据

| 类型 | 意义 | 判定方式 |
|---|---|---|
| 硬门槛 | 文档结构与几何不变量、引用、约束与事务正确；秘密不泄漏；保存与撤销完整；无静默覆盖 | 适用用例必须全部通过；发现问题阻止对应里程碑验收 |
| 体验目标 | 交互时间、普通提交耗时、易用性与 AI 软质量 | 按环境和分布判断；M0程序符号数据见13，未测场景/AI不能推定达标 |
| 兼容性声明 | 浏览器支持、工程迁移、VTT 目标组合 | 只依据真实运行证据声明，未运行的组合保持未验证 |

硬门槛失败不能以体验较好、平均成功率较高或样例截图正常抵消。软质量较差的 AI 提案可以不被采用；任何已经通过采用入口的提案都必须遵守硬约束。

每次验证记录至少包含：QA 编号、代码版本、场景与文档格式版本、操作步骤、预期与实际结果、设备/操作系统/浏览器版本、结果状态、证据位置、失败影响和负责处理的任务。涉及 AI 时增加模型/provider、参数、requestId、固定原创样例或允许保存的脱敏需求及成本口径；涉及 VTT 时增加目标软件和导入器版本。验证记录不保存密钥或未经许可的玩家信息；产品运行日志不写入完整提示词或私密注记正文。

状态只能使用「未运行」「通过」「失败」「阻塞」「不适用」。不适用必须解释范围；人工看过文档不能写为功能通过。证据应能从固定样例或清楚说明的变体复现。

## 3. 几何、门墙关系和通行

以下均为硬门槛。既验证被接受的合法结果，也验证非法输入被拒绝后原场景不变。

| ID | 验证输入与操作 | 通过条件 | 建议证据 |
|---|---|---|---|
| QA-GEO-01 | SCN-01 正交房间创建、共享边编辑；变体含自交、重复/缺失顶点、零面积、同层室内重叠、无效 floorId、重复实体 ID | 世界坐标保持整数毫米；房间是简单多边形；同层室内面积不重叠；共墙只存一份；非法事务整体拒绝 | 不变量检查结果及编辑前后文档差异 |
| QA-GEO-02 | 将门放在墙端、超出墙长、门窗重叠；拆墙、移动墙、反转墙方向或改变墙长；删除被门引用的墙 | offsetMm/widthMm 与有向墙一致且落在有效范围；所有 Opening 有有效 wallId；允许的结构调整在一个事务内重挂引用，不能出现悬空门或半完成状态 | 所涉稳定 ID、墙门关系及撤销后的快照 |
| QA-GEO-03 | 手工先画孤立房间再放门；SCN-01 普通房间、隐藏通路；SCN-02 循环路线、上锁区域；切断 required 房间的全部结构入口路线 | unspecified 草稿可以保存；required 按指定入口的结构可达验证；有连接的秘密/锁门房间可以 required；真正结构隔离才使用 intentionalIsolation；当前门状态下通行约束与豁免另查，闭门/锁门不当作结构孤岛 | 访问期望、派生结构与通行结果、例外清单、入口到目标路线 |
| QA-GEO-04 | 在门口摆放阻挡物、旋转家具、只放装饰；调整通道宽度；SCN-03 增加开放区域并改变导出裁剪 | 装饰与阻挡语义有区别；必须通行的路线满足当前工程约束；室外路线限制在 Floor.boundsMm 内，不借裁剪范围变化绕过溪水；开放区域不强制成封闭房间；违反硬约束时不能提交 | 物件占地、阻挡/装饰标记、场景边界与验证报告 |
| QA-GEO-05 | 保持墙中心线位置，改变一侧/两侧墙厚；在接近最小通道净宽的位置旋转家具；设置刚好等于允许下限的开口，再减小；检查转角处净空 | 以墙实体边界及变换后家具占地验证净空，不能把中心线间距误当净宽；Opening.widthMm 表达沿墙开口净宽；按领域文档的边界和量化约定判定阈值，不用贴图留白或网格视觉代替计算 | 中心线尺寸、墙厚、有效障碍轮廓、最窄净空与阈值比较 |

「全部房间连通」不是独立的无条件要求。Room.accessExpectation 使用 unspecified、required、intentionalIsolation；手工新增默认 unspecified，允许先画房间后连接门的草稿流程。required 只有在用户明确声明或生成合同要求时才构成硬约束，其含义是通过结构连接到指定入口。当前通行要求与上锁等豁免由 constraints 独立表达；有结构连接的暗廊或封库不应因为秘密/上锁而标成 intentionalIsolation。检查器不得为了通过验证自动解锁秘密门、打开门或改写可见性。

## 4. 编辑事务、撤销与并发冲突

以下均为硬门槛，手工编辑和 AI 采用共享同一组验证。

| ID | 验证输入与操作 | 通过条件 |
|---|---|---|
| QA-TXN-01 | 一批操作中前项合法、后项引用无效或违反几何；验证中失败；提交 baseRevision 已过期 | CommandBatch 全部成功或全部拒绝；失败不修改正式场景、不生成半条历史，也不增加 revision |
| QA-TXN-02 | 连续完成房间调整、门重挂、家具移动、注记修改，逐次撤销并重做；撤销后做新编辑 | 撤销/重做恢复完整语义内容和引用，不仅是可见像素；每次成功事务、撤销、重做均使 revision 加 1，绝不倒退；新分支后的重做行为符合编辑契约 |
| QA-TXN-03 | 锁定房间、墙或物件；选区编辑触及外部依赖；依赖实体被锁 | 实体锁和编辑范围锁都生效；不能通过修改共墙或关联门绕过锁；必须扩展范围时给出可理解的原因，不能静默越界 |
| QA-TXN-04 | 一次拖动产生多次移动事件；拖动中取消或失焦；释放后撤销 | 拖动暂态不反复提交文档；一次完成的拖动产生一个事务；取消不留修改，撤销返回拖动前内容 |

比较撤销快照时，应排除按契约合法变化的 revision 与审计字段，再比较其余语义内容。回到旧几何不意味着回到旧 revision。持久化重试本身不是一次新的编辑事务。

## 5. 保存、导入、离线与恢复

以下是持久化安全硬门槛。正常编辑在内存中成功但保存失败时，不能假装已保存；错误应可见，并保留导出或恢复当前成果的路径。

| ID | 验证输入与操作 | 通过条件 |
|---|---|---|
| QA-IO-01 | 对 SCN-01 完成保存、关闭、重开、继续编辑；导出 .sceneweave 后在空环境导入 | 默认导入为新 sceneId；该场景命名空间内房间/墙/门稳定 ID、单位与比例、预设快照、注记、可见性、锁和合法资产引用完整保留；无需按 seed 重建；可继续编辑与导出 |
| QA-IO-02 | 导入截断 ZIP、无效 manifest/scene、hash 不匹配、未知高版本、多楼层、缺失资产、坏引用、不合法几何；在导入确认前取消；尝试显式替换现有场景 | 隔离暂存区完成完整校验；失败或取消保持当前场景与已保存工程；多楼层文件不静默合并；缺失素材可经用户确认以占位打开并列清单；替换必须先备份，以当前 revision+1 和 CAS 提交，不采用文件旧 revision |
| QA-IO-03 | 自动保存时模拟写入失败、事务中断、存储不可用或页面异常关闭；之后恢复打开；选择历史快照恢复 | 保留最后一次完整持久化结果；不会读到半文档；未保存状态清楚；历史恢复默认新 sceneId，不覆盖较新文档或将旧 revision 写回原场景；导出可用时仍能取走当前内容 |
| QA-IO-04 | 同浏览器两个标签打开同一 sceneId，分别从相同 revision 编辑；标签休眠后恢复；一个标签先保存；单标签出现多次连续编辑 | 单标签自动保存串行；IndexedDB 事务中 expectedPersistedRevision 匹配当前记录时才写入新快照；跨标签冲突冻结冲突标签的写入并保留内存副本；可另存为新 sceneId，不能静默覆盖；用户能够保留自己的工作 |
| QA-IO-05 | 资源可用后断网编辑；AI 网关不可用；存储配额不足；浏览器拒绝持久存储；工作区资产丢失 | 手工编辑不依赖模型在线；离线前提与可用范围清楚；AI 失败不阻塞手工流程；配额或权限错误有反馈且不标为保存成功；已有持久化内容不被清理以掩盖错误 |

同浏览器多标签冲突是单用户产品也会遇到的场景，不能留待多人协同时再处理。CAS 比较与写入必须在同一个 IndexedDB 事务内完成；通知其他标签不能替代实际版本比较。完整协议以[存储与导出](06-storage-and-export.md)为准；验收必须证明后到的旧快照不能覆盖较新快照。

“离线可编辑”需要应用与已有资产可访问。首次加载、服务器停止、刷新或缓存清理的支持范围必须实测并写明，不能据此推导出已具备 PWA 离线安装能力。

## 6. 玩家秘密：像素与元数据

以下均为硬门槛。播放器结构化数据不在首版范围；完整工程只面向主持人。

| ID | 验证输入与操作 | 通过条件 |
|---|---|---|
| QA-SEC-01 | SCN-01 中放置未发现秘密门、隐藏房间/通路、GM 线索、私密标记；分别导出主持人与玩家 PNG | 主持人可见设计内容；玩家图中秘密门表现为完整普通墙，隐藏几何使用约定的保守遮罩，GM 文字和图标不出现 |
| QA-SEC-02 | 为隐藏区域添加不同纹理、装饰光影、轮廓、装饰与网格；缩放、改变导出尺寸；导出中继续编辑 | 最终遮罩位于装饰与光影之上；输出使用固定 revision 与 exportBoundsMm，不受私密对象包围盒或中途编辑影响；隐藏内容不能经边缘、透明度、裁剪或网格变化泄漏；预览与最终导出策略一致 |
| QA-SEC-03 | 私密文字、秘密名称、资产名称/来源与生成提示词出现在工程数据中；使用无实际凭据的标记检查异常输入；检查玩家文件 | 玩家 PNG 不附带私密结构化数据、文本块、资产路径、提示词或来源；生成文件名不暴露秘密；仅合法的图片编码信息可以保留；导出入口不会误给玩家完整工程 |
| QA-SEC-04 | AI 网关错误、请求记录、工程导出、浏览器持久化及诊断输出 | API 密钥不进入场景、资产、导出、前端构建产物或可共享日志；发送给模型的范围符合实际功能和文档说明 |
| QA-SEC-05 | 把 public 注记锚定 gm 房间、未揭示秘密门或被遮罩坐标；之后只揭示其中一个对象 | 玩家投影不生成悬浮文字或图标；GM 预览提示锚点冲突；揭示只影响明确公开的锚点和文字，其他信息仍被过滤 |

像素验证同时采用配对场景与人工检查：两份工程的公开部分相同，只有秘密内容不同，导出的公开区域应一致，隐藏区域均落入同一保守遮罩策略。固定渲染环境下检查像素差异，再放大查看墙边和阴影。不同字体或浏览器的抗锯齿差异不能成为放过秘密泄漏的理由。

隐藏区域留白的具体外形也可能暗示秘密，需按预先定义的遮罩范围验收。不能仅确认「文字消失」就判定通过。主持人主动揭示的行为单独验证：仅改变已明确公开的对象，关联私密注记不会随之自动公开。

| QA-AI-04 | 「只改书房」且保留门窗；选择部分提案，但它依赖未选操作；预览后再修改依赖对象 | 实际差异与范围一致；有效依赖组一起校验和采用；不允许断开依赖的部分提交；采用一次可完整撤销，过期预览不能直接提交 | 硬门槛 |
| QA-AI-05 | 相同生成器版本、seed、配置和已确定结构提案多次执行程序布局；改变模型请求重复运行 | 程序部分可按约定复现；记录必要输入与版本；不宣称模型输出相同或整个 AI 流程确定性 | 硬门槛 |
| QA-AI-06 | 固定中文请求集，对候选 provider/model 比较初稿、局部修改和注记 | 统计有效提案率、未通过的约束类别、局部命中、人工修正、语义质量、延迟和单次成本；被采用结果硬违规为 0；不以文案流畅替代地图质量 | 硬门槛 + 体验评估 |
| QA-AI-07 | 以 gm 线索为上下文，要求 AI 改写已公开的地点说明；直接返回 UpdateNote 指向 public 目标；再通过草稿流程审阅 | UpdateNote 只能更新既有 gm 注记；public 目标的直接更新被拒绝；合法建议先以 AddNote 生成 gm 草稿，原公开正文保持不变；只有主持人手动发布所选文字后玩家输出才变化 | 硬门槛 |

模型选择前先固定请求、场景、约束与评分方法，避免为不同模型挑选有利样本。样本数量、重复次数和软质量目标在 M2 评测开始前写入记录，当前尚未确定。记录「原始提案被拒绝率」与「提交后的硬违规」两种指标：前者影响体验，后者必须为零。

公开文字本身也是信息边界。仅保持 visibility 字段不变，仍可能把模型读取的 gm 内容写进 public 正文；QA-AI-07 必须检查文本去向、玩家导出以及手动发布前后的差异，不能只比较可见性字段。

## 8. 资产与恶意输入边界

以下均为完整资产管线的硬门槛。M0 已实现两条目 m0-geometry ZIP 与有界输入检查，拒绝全部外部素材；PNG/JPEG/WebP 输入及完整资产容器仍是后续范围。具体条目、类型、M0 实际预算与未来候选预算以[存储与导出](06-storage-and-export.md)为准，不把几何 ZIP 负例通过扩展为真实图片解码已测。

| ID | 验证输入与操作 | 通过条件 |
|---|---|---|
| QA-IMPORT-01 | 超大文件、极高像素图片、伪扩展名、损坏编码、高压缩比 ZIP、目录穿越、绝对路径、重复条目、嵌套归档 | 按压缩体积、解压体积、单项大小、像素量和条目数共同限制；先检查再解码或展开；拒绝越界路径与重复条目，不自动展开嵌套归档；错误可理解，原工程不变 |
| QA-IMPORT-02 | 导入 PNG/JPEG/WebP 带 EXIF/文本元数据的有效图片，以及活动 SVG/HTML、动画、脚本、外链字体/图片；注记含 HTML 与脚本片段；文件名带控制字符 | 按实际编码核对支持类型，移除非必要图片元数据；不支持类型明确拒绝；不执行脚本，不因打开工程发出未知外部请求；文本按普通内容显示；安全处理不静默改写当前工程 |

安全边界应使用平台实际解码行为验证，不能只按扩展名判断。非法输入导致的失败属于可预期错误，不应破坏已打开的文档，也不能绕过来源和授权信息要求。
