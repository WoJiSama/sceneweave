## 统一验收入口

当前验收尚未开始。先完成开发整改，再按下列顺序在明确冻结上执行；旧批次证据只用于历史对照，不能自动变成当前通过结论。

开发整改完成后，所有验收在本阶段统一执行，包括技术、AI、视觉、用户P3、性能及交付。首先冻结源码、算法、素材、样例、模型/参数和目标VTT/导入器版本，记录唯一指纹；旧T/Q批次结果只用于历史对照。

执行前将[视觉AI独立样本](#ai-visual-acceptance)的9份空白创作/3份局部修改与[地形真实AI样本](#terrain-ai-acceptance)的16项自然语言/4项局部任务按需求覆盖映射合并。一次任务可覆盖多个QA，只计一次独立任务；室内、局部、私密、保存/导出和独立样本要求不得省略。

### 执行与复验

1. 冻结输入，执行全量单元/AI/共享边界、类型与前后端构建、Chromium完整流程、适用Firefox/WebKit和正常生产/存档流程。
2. 完成合并后的真实AI创作与局部修改、视觉回读、素材检查、用户P3和无引导人工场景；明确展示程序底图与AI修改后的结果。
3. 正确性问题收敛后独占串行完成正式性能，记录设备、负载、方法、p50/p95/max及失败。
4. 完成目标VTT真实导入、线上版本/交付旅程和限制清单，决定是否进入M3真实小团。

修复后更新受影响冻结并复验影响范围；共用算法、素材或模型变化时重跑受影响组。同冻结且未受影响的证据可复用，不拼接旧通过数字，保留首轮失败。未通过项保持阻塞，限制试用或延期须用户明确决定；P3只能由用户签收，未知计费请求不自动重发。

证据按[门槛与证据](#1-门槛与证据)记录；真实样本见[视觉AI](#ai-visual-acceptance)和[地形AI](#terrain-ai-acceptance)，全部QA检查定义在下文。原始图片、完整包和运行日志放忽略的work目录，必要紧凑夹具与结果归对应主题台账，不新增逐批编号报告，不提交密钥或私密内容。

## 1. 门槛与证据

| 类型 | 意义 | 判定方式 |
|---|---|---|
| 硬门槛 | 文档结构与几何不变量、引用、约束与事务正确；秘密不泄漏；保存、撤销、局部恢复完整；范围、锁及原素材保护有效；无静默覆盖 | 适用用例必须全部通过；发现问题阻止对应里程碑验收 |
| 体验目标 | 交互时间、普通提交耗时、易用性与 AI 软质量 | 按环境和分布判断；未测场景或AI不能推定达标，历史程序符号数据不替代真实素材 |
| 兼容性声明 | 浏览器支持、工程迁移、VTT 目标组合 | 只依据真实运行证据声明，未运行的组合保持未验证 |

硬门槛失败不能以体验较好、平均成功率较高或样例截图正常抵消。软质量较差的 AI 提案可以不被采用；任何已经通过采用入口的提案都必须遵守硬约束。

局部恢复、目录、外观、地形和AI的有限子项按各自严格合同验证。单选不能抵扣框选，系统绘制带不能抵扣用户图层，完整副本恢复不能抵扣有限局部恢复，工具或自动化通过不能抵扣人工/P3。每组独立记录适用范围，未执行输入保持未运行；历史证据从[历史索引](archive/README.md)追溯。

资料状态见[46清理记录](archive/m2-project-validation.md#doc-46-7-按用户要求执行清理)：对应历史批次的work/与docs/evidence/原始产物已按当时授权删除。历史结果/失败/限制保留，必要测试夹具移至tests/fixtures/performance-b5；不能再把已删除附件当作当前可取回证据。新批次保留可执行测试、简短结论/命令/环境和必要紧凑结果，原始图片/trace/源码快照只在忽略目录按需保存，不默认入Git。

每次验证记录至少包含：QA 编号、代码版本、场景与文档格式版本、操作步骤、预期与实际结果、设备/操作系统/浏览器版本、结果状态、证据位置、失败影响和负责处理的任务。涉及 AI 时增加模型/provider、参数、requestId、固定原创样例或允许保存的脱敏需求及成本口径；涉及 VTT 时增加目标软件和导入器版本。验证记录不保存密钥或未经许可的玩家信息；产品运行日志不写入完整提示词或私密注记正文。

状态只能使用「未运行」「通过」「失败」「阻塞」「不适用」。不适用必须解释范围；人工看过文档不能写为功能通过。证据应能从固定样例或清楚说明的变体复现。

## 14. 地形与双尺度验收

本节统一承接原地形设计的样本和硬门；实际支持范围归[地形参考](reference/terrain-generation.md)，已有结果归[地形台账](archive/terrain-validation.md)。源码、严格版本、输入范围和声明的有限能力须在执行前写清楚；未支持目标保留缺项/阻塞，不用历史阶段的拒绝边界冒充当前支持范围。

### 14.1 地貌与视觉样本

| 样本 | 明确目标 | 视觉检查 |
|---|---|---|
| T-S01 岩岛 | 非中心高台、海湾、活动区与真实连接 | 无同心模板感，崖顶/面/脚清楚，树石有主次 |
| T-S02 海岸营地 | 弯曲海岸、干湿沙、浅水、营地和入口 | 过渡宽度有变化，漂木/草石沿地貌聚集，留白明确 |
| T-S03 林中河湾 | 连续河道、双岸、浅滩与两岸活动区 | 河宽变化连贯，无断岸/假桥，渡点可识别 |
| T-S04 湖畔森林 | 内陆湖、林缘、空地、沿湖路线 | 湖水与陆地分区正确，树林呈簇，湖中岛可表达 |
| T-S05 丘陵道路 | 至少两级真实地面、坡道、指定路线 | 地形有主方向，高差和连接易读，无彩色假坡 |
| T-S06 混合哨所 | 既有建筑/院路保留，外围地形改造 | 地形贴合建筑支撑，入口不被树冠/崖面盖住 |
| T-R01 区域河网 | 山脊、汇流、湖/海出口、森林和道路 | 正面树山图符统一，地图层次清楚，无图符冒充真实物件 |
| T-R02 区域下钻 | 河流与道路穿过选区，独立场景创建 | 方向/端口/尺度继承，场景细节不会反写父图 |

每个场景配方至少五个固定种子作为技术/视觉候选集；区域至少三套明确输入。全部结果与失败保留，不能手调失败样本后计为自动成功。重复候选可用形状摘要辅助发现，但最终构图、疏密和画风仍由人工审阅，用户P3独立签收。

视觉比较保留：全景、中性图、固定世界近景、带树根/占地的编辑辅助图，以及双受众4K。比较近侧视素材变更时使用同一地形和构图，避免通过移动相机或添加雾遮掉问题。

### 14.3 地形AI真实样本

最终冻结上运行六类场景各两个独立自然语言任务，共12个；区域创作2个；区域下钻2个，共16个。需求只给用途、必要元素、风格与范围，不提供实体ID、精确坐标或工具步骤。每种代表性修改至少覆盖海岸、森林、混合建筑和关联场景四次局部任务。

每个任务记录模型/渠道配置、输入/素材/代码指纹、真实请求/工具/展开、耗时、已知token、完成项、缺项、失败、是否人工接管，以及采用/保存/完整包。未知付费请求不重发；在额度或渠道阻塞时保持验收未完成，不用确定性夹具替代。

全部声明硬要求通过、四次局部范围保护成立、逐张视觉审阅完成才关闭相应门。人工接管不计AI独立成功。共性实现/模型/素材改变后重跑受影响组；不同冻结不能拼成一次16/16。该样本仅证明这些任务，不声称普遍成功率。

<a id="ai-visual-acceptance"></a>
## 15. 视觉AI独立样本与覆盖合并

三类场景各3个独立从空白任务，共9次；需求只给用途、必要元素、风格和范围，不给实体ID、精确坐标或工具步骤。每类含基础需求、表达变化、明确空间约束三种输入，使用同一冻结代码/模型/素材版本。9次全部保留，记录请求、耗时、已知token、采用/人工介入、缺项和失败原因；价格未知时金额标未知。

每类再选一份结果做1次局部修改，共3次，例如只改北侧崖面和灌丛、只协调一片海草、只重布餐厅且保留厨房。范围外文档/资源/人工记录保持；对于阴影外扩，提前列出授权影响范围，不能笼统要求物件边框外像素绝对不变。局部滤镜则继续验证其约定区域外像素不变。

退出要求为9次均达到冻结的结构/功能要求、3次修改保持范围，以及逐张完成视觉审阅。人工接管的结果单独记录，不能计为AI独立成功。失败修复后重新记录受影响任务组，首轮失败保留。共性代码、模型或共享素材变化影响三类时，最终9次按新冻结独立重跑；只改局部配方时可复验对应3次，但各组记录自己的冻结指纹，不能拼成“同次9/9”。这是功能验收样本，不宣称普遍成功率；用户最终P3仍按作品签收。验收执行时，可与本页地形真实任务按需求覆盖映射合并，一次任务可同时覆盖多个QA，但不得把它计为多个独立任务；9空白/3局部及室内、私密、保存/导出等覆盖仍须明确满足，不以自然地形任务替代室内验收，也不拼历史通过数。

素材、公开画面回读和可观察视觉标准归[视觉与素材](14-visual-and-assets.md#visual-quality)。执行前建立“需求/QA → 独立任务”映射，合并地形16项创作/4项局改与上述9份空白/3份局改；一次任务可覆盖多个QA，但只计一次独立任务。保留每套样本的独立输入、室内、私密、局部及采用/保存/导出覆盖，不用自然地形替代室内任务。
