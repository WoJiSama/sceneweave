# M1-B / B5 真实纹理性能与 M1-C 交接

日期：2026-10-20。应用版本：`0.2.0-m1-b5`。开发基线：`dadb099f82db8cbbc43ba24a260bca532c30f9cd`。本批建立 VIS-01「书房与露台」和 VIS-02「双层岩岛」的真实素材 500/2000 物件负载，记录可复核的分段时间和采样资源，修复预览与保存之间的解码并发预算。下一入口为 M1-C，周计划见[07](07-roadmap.md#43-b5-后的-m1-c-滚动周计划)。

本批技术测量完成不等于完整 QA-PERF-01/04、主题 P3 或整个 M1 通过。v2 尚无平移、缩放和自由拖动；完整工作台的功能验证与专用测量入口分别记录。[M0](13-m0-validation.md)、[B1](17-m1b-b1-validation.md)、[B2](18-m1b-b2-validation.md)、[B3](19-m1b-b3-validation.md)、[B4](20-m1b-b4-validation.md)及旧证据保持历史原状。

## 1. 实际改动与结论

v2 预览与 PNG 使用原生 Canvas2D。M0 几何版才使用 Konva。当前保留 Canvas2D，M1-C/C0 先处理重复全场景校验、预览重绘及工作台视口，再按相同负载决定是否引入 Worker、分层重绘或其他渲染引擎。更换渲染器不能消除领域事务、图片校验和持久化成本。

原渲染器直接解码，完整工程校验使用自己的队列；baseline 的实际原生解码时间区间显示每轮峰值 2，与声明的单解码预算不符。现统一经 `withImageDecoderSlotV2` 排队，保留渲染的 alpha 默认值与校验的 `premultiplyAlpha:none`，等待时间单列为 `decoderQueueWaitMs`。成功、失败及排队取消均释放队列位置；不减少严格校验。

先建立 12 轮正式 baseline，再试验每次渲染内的单项材质 Canvas 同尺寸复用。候选另跑 12 轮，全部 4K 像素相同，但四组产品 RSS 采样最大值均更高，岩岛 2000 的绘制 p95 从 384.9ms 增至 474.8ms、画面代理从 653.8ms 增至 753.8ms，因此**撤回同尺寸复用**。最终再跑 12 轮，只保留共享解码槽和临时画布在 context/pattern 设置前登记所有权的故障清理修复。三构建证据均保留；不把 JS Canvas 数量减少当作底层内存减少，也没有证据将 RSS 差异直接诊断成 COW 或泄漏。最终每轮原生解码在途峰值均为 **1**。

测量基础设施通过显式 opt-in 的生产模块测量入口和 runner 提供；正常构建没有 `window.__sceneweavePerformance`。没有引入长期 ImageBitmap 缓存、图集、Worker、AI、云同步或外部素材。观察回调默认关闭，观察器失败不影响产品结果。

## 2. 负载、环境与计时方法

Apple M1、16 GiB、macOS 26.6.2（25G83）、Node 24.14.1、Chrome 155.0.8059.84，headless，视口 1512×1120、DPR=1，ANGLE Metal Apple M1 / Canvas2D 加速已启用。普通工作台回归视口为 1512×982。数据只覆盖该设备与浏览器。

| 负载 | 范围 | 工程独立PNG / 像素 | 完整ZIP bytes | 实例矩形面积/输出 | 多矩形覆盖抽样 |
|---|---|---|---|---|---|
| 书房 500 | 14×10m | 15 / 2,121,728 | 135,135 | 1.597 | 25.4% |
| 书房 2000 | 14×10m | 15 / 2,121,728 | 169,160 | 6.151 | 30.3% |
| 岩岛 500 | 30×27m | 13 / 8,208,384 | 312,701 | 1.206 | 31.3% |
| 岩岛 2000 | 30×27m | 13 / 8,208,384 | 344,337 | 4.370 | 39.5% |

完整包保留原物件、结构、材质、固定 Prefab 和散布人工记录，并使用正常样板守卫；不改 preset ID 绕过通道检查。书房保留 13 原物件与 2 组合，岩岛保留 39 原物件及 3 组/36 个散布成员。所有新增物件使用真实尺寸与已有 PNG。书房渲染投影实际用 14 张/1,859,584 像素，工程还保留未采用的备选材质；岩岛投影用完整 13 张/8,208,384 像素。

表中数量为完整文档/受众投影纳入数量，全部图像矩形位于固定输出范围内，**遮挡后实际可见物件数未测**。原 PNG 的零/部分/不透明 alpha 像素逐张读取；实例矩形和 alpha 面积累计会重复计入重叠，网格抽样估计忽略 alpha。这些高密度副本保留合法结构，但大量物件相互覆盖，不能作为可玩布局或美术验收。

每个构建依次运行四组负载，每组 3 个独立冷 Chrome 进程及空仓库，禁用 HTTP 缓存；不声称清空 OS、驱动或整机缓存。夹具准备在另一个随后关闭的进程中完成。每轮依次执行：严格导入/采用/首幅预览；60 次真实鼠标选择与清空；30 次物件 0↔1°、30 次轮廓 ±1mm 交错编辑；完整保存与精确重开/20 快照；GM/player 4096 长边 PNG；4097 超限拒绝后编辑及撤销。完整备份、工具像素读回/下载在独立阶段。

每组编辑与选择各 180 样本（编辑为 90 次物件＋90 次轮廓；分类统计各 n=90），单构建合计 720 编辑、720 选择、24 次 4K。p95 使用 nearest rank `sorted[ceil(n*0.95)-1]`；原始单次数组、时间戳、运行窗口及各轮统计保留。冷启动、重开和每个受众导出各仅 3 次，其 p95 等于三次中的最大值，不视为稳定尾延迟模型。

| 指标 | 起止与边界 |
|---|---|
| 已准备命令提交 | 从 commands 构造完成到 `workspace.execute` 返回，含领域校验与文档事务；**不含工具输入/候选准备**，室外 `terrainPointCommandsV2` 的整文档复制与浅水联动准备在计时前 |
| 渲染分段 | validation/projection、字节/header/hash、decoder queue wait、native decode、draw submission 分别记录；total 包含 finally 清理，清理未单独拆分；draw 是 CPU 提交耗时，非 GPU 完成 |
| 画面更新 | 从上述命令计时起点到实际产品 Canvas 复制/选区绘制后两个 rAF；仅显示调度代理，不是输入到屏幕光子的延迟或拖动帧耗时 |
| 保存 | 完整 `repository.save`，含资源严格校验与 IndexedDB CAS；单独 IDB 事务未拆分，flush 只表示剩余等待 |
| 冷路径与重开 | 记录包 fetch、strict import、adopt/persist、首次 Canvas；重开为完整 repository load 和文档/资源精确核对，不含工作台侧栏挂载 |
| PNG | 真实绘制到 `toBlob` 产出，固定尺寸/比例；编码与异步栅格等待的剩余项不能等同纯编码 CPU |

## 3. 实测与优化比较

以下均为最终构建的 p95，单位 ms；编辑和选择分别按每组 180 次合并统计。

| 负载 | 冷导入→首图¹ | 已准备命令提交 | 绘制提交 | 画面调度代理 | 热完整保存 |
|---|---|---|---|---|---|
| 书房 500 | 267.4 | 30.4 | 25.3 | 100.7 | 55.7 |
| 书房 2000 | 507.4 | 109.6 | 28.0 | 211.9 | 150.0 |
| 岩岛 500 | 394.3 | 38.3 | 98.8 | 197.7 | 71.7 |
| 岩岛 2000 | 679.8 | 131.3 | 433.3 | 708.0 | 186.2 |

¹ 冷路径不含应用 runtime navigation，单列原始值；每组只有 3 次。下表渲染子项的各自 p95 不能相加当作整体 p95。

| 负载 | 校验/投影 | 字节校验 | 排队 | 原生解码 | GM / player 4K ms² |
|---|---|---|---|---|---|
| 书房 500 | 10.6 | 3.2 | 0.1 | 5.0 | 549.6 / 478.9 |

² 每受众 3 次。书房 4096×2926（11,984,896 px），岩岛 4096×3686（15,097,856 px），全部保持固定物理比例。

按 **baseline → 同尺寸复用候选 → 最终（不复用）** 顺序，使用同一设备、逐条目相同的工程。每一项均保留三轮原始记录；运行顺序未随机化，不能把所有差异归因于一个变量。

| 负载 | 绘制 p95 ms | 画面代理 p95 ms | 产品阶段RSS采样最大 MiB |
|---|---|---|---|
| 书房 500 | 24.8 → 22.9 → 25.3 | 100.6 → 106.9 → 100.7 | 1462.6 → 1526.6 → 1572.5 |
| 书房 2000 | 28.5 → 25.6 → 28.0 | 214.8 → 217.8 → 211.9 | 1530.8 → 1701.8 → 1589.7 |
| 岩岛 500 | 117.5 → 105.5 → 98.8 | 216.6 → 211.0 → 197.7 | 1709.2 → 1985.7 → 1692.8 |
| 岩岛 2000 | 384.9 → 474.8 → 433.3 | 653.8 → 753.8 → 708.0 | 2050.4 → 2214.0 → 1922.6 |

500 两组的已准备命令提交 p95 为 30.4/38.3ms；2000 为 109.6/131.3ms。室内增加物件后校验/提交开销明显，室外还叠加重绘成本，岩岛2000绘制提交 p95 433.3ms，画面代理 708.0ms。单槽修复使排队成本显式化，但并未解决大场景交互；最终对baseline仍有部分耗时及室内RSS上升，不能宣布整体提速或内存全面下降。岩岛2000三轮画面代理p95为643.8/670.4/720.6ms，合并值不能掩盖运行差异。M1-C/C0 应先减少重复全量工作和重绘，再验证持续操作。

真实选择 handler 和 Canvas 复制可独立查看汇总；选择后的两个 rAF 约束不证明持续交互帧 p95≤33ms。普通编辑目标从用户意图开始，当前提交计时缺少准备与输入，不能用 500 的已准备命令 <100ms 关闭 QA-PERF-01。2000 仅为压力证据；不对外承诺 2000 物件流畅编辑。

| 负载 | 每轮产品RSS采样峰值范围 MiB | 产品JS堆采样最大 MiB | 全程RSS / 堆样本数 | 最长实际RSS / 堆采样间隔 ms |

RSS 是 macOS `ps` 目标间隔 100ms 的独立 Chrome root PID 及后代**同时** RSS 和；共享页可能重复计入，不等于去重物理内存、完整浏览器内存或 GPU/Metal 峰值。CDP 目标 JS 堆目标间隔 200ms；主线程阻塞可能使响应和下一次采样变迟。原始观察记录实际采样间隔、请求耗时、进程身份、阶段交叉及缺项；跨阶段样本不归入单个阶段最大值。

表中“产品阶段”排除工具像素审计/下载和尾部 idle；原 summary 的全局 JS 堆最大值包含这些工具阶段，保留原值并另算产品阶段值，不能混用。采样间瞬态仍可能遗漏；未采集精确原生分配/唯一物理峰值、VRAM 或 GPU 完成时间。理论 RGBA 字节和 JS 对象个数不替代这些缺项。预览 Canvas 在导出期间驻留；双受众顺序导出，PNG Blob 留到审计，临时画布和本次位图在每次渲染结束释放。

现有 100MiB 编码包、300MiB 展开、256 位图/64M 像素、10000 实体等格式保护上限保持不变，**不是本机验证过的容量保证**。实测只用上表 PNG、固定尺寸和列出的操作。500 是 M1-C 优化与回归目标，2000 保留为压力夹具；4K 仍限长边 4096 及既有总像素预算。单原生解码并发统一为 1；当前没有跨渲染解码缓存。

## 6. 下一入口

M1-C/C0 先提供 v2 视口操作、完整输入/准备/提交/显示的计时，并减少不必要的全场景工作；再按[滚动周计划](07-roadmap.md#43-b5-后的-m1-c-滚动周计划)推进空白工程、建筑绘制、组件库、室外地形/道路/散布，M1-D 完成 SCN-04 混合与完整验收。每周 10 小时是排期估算假设，尚未得到实际人力确认；前两周重新估算，P3 素材返工计入同一投入。

本批不新增自由绘图、全图路径、任意素材管理、AI、UVTT 或 PWA。现有主题仍 O/P2；完整 QA-PERF-01/04、SCN-04、跨浏览器、真实小团与用户美术签收保持开放。
