# 剩余事项

这里只记录未完成工作。完成后从本页移除，在[已完成功能](completed.md)对应位置补一句能力说明。具体开发记录由Git和测试输出承担，不在这里追加会话日记、批次或研究否决过程。用户独立的[todo](../todo.md)继续保留。

<a id="current"></a>
## 当前优先

**编辑 → 保存 → 重开 → PNG导出。** 这是用户选定的第一个独立交付目标。使用普通页面制作和修改一份有实际素材的地图，检查撤销重做、完整保存、刷新重开、备份导入和双受众PNG。执行方法见[检查方法](testing.md#core-journey)。

这条流程的通过条件只约束自身范围；AI收益、VTT兼容和新地貌效果分别判断。此次文档整理不把旧运行结果改记为当前通过。

<a id="remaining"></a>
## 已知缺口

| 事项 | 剩下要解决什么 |
|---|---|
| 核心编辑交付 | 在当前代码上执行上述完整旅程，修复实际阻塞，再明确可用范围 |
| 性能与容量 | 当前整套性能目标尚未全部验证通过；解决有复现的编辑、保存、长任务和内存问题；500物件目标与2000压力结果分开报告 |
| 海洋成图 | 继续另一会话的共用SVG栅格问题、跨浏览器保存导出和容量检查；自然岸线、素材质感、实际尺寸巨怪及最终视觉由该会话确认 |
| 岩体与山路 | 继续另一会话的完整坡体连接低台和高台；解决弯板感、岩肩/崖壁与两端接合，再评估自然效果 |
| 图片整件质量 | 主体边缘、细杆、色边、木纹接缝和隐藏补底仍有缺陷；人工修正可用不代表自动提取或新手稳定 |
| 整图视觉 | 室内明暗、海岸节奏、崖面台阶、植被和素材协调仍需看实际成图；用户美术签收单独进行 |
| 真实AI收益 | 用相同需求比较完整交付时间、人工接管、缺项和实际用量；工具接通及回复更快不能单独证明收益 |
| VTT兼容 | 在明确版本的Foundry和导入器中真实导入，核对比例、墙门、秘密、灯光和玩家视角 |
| 使用交付 | 真实备团/上桌反馈、目标浏览器覆盖及公开分发前检查；只声明实际验证的组合 |

既有实现可以继续使用；以上条目仅保留未解决部分。新的功能扩展先明确用户任务和最小结果，不从样板缺件自动扩大产品范围。

<a id="image-work"></a>
## 制作与开发的接续

图片任务先读[图片步骤](reference/image-item-workflow.md)，地图或局部制作先读[制作总则](reference/project-creation-workflow.md)。当前模型和事务约束看[架构](architecture.md)，素材权利和导入看[素材说明](assets.md)。

开发时选择受改动影响的检查即可；一个能力完成相关检查后可以独立交付。公开发布、外部调用和用户签收按当前授权处理，不继承旧会话授权。
