# 地图编辑架构整改设计

第一张验收图是一条沿山折返的路。作者从山脚向上拖出路线，把中段铺成石阶，再给临崖一侧加木栏。以后拉宽一个弯道，踏步和木栏都应该跟着这段路走，旁边独立摆放的路灯则留在原地。要做到这一点，工程需要记住作者把东西放在这里时建立的关系。

本设计用于后续整改。首轮聚焦画地图、编辑和复用。岩纹、洞口暗部、桥梁细部可以用贴图和光影画到合适的效果。涉及支撑、开口、通行或玩家可见性时，才需要相应的结构和校验。可进入的隧道、上下重叠的可行走空间，以及在平台上实际跑团，留到后续。现行实现与约束见[当前架构](../architecture.md)。

## 对象有哪些部位，部位之间是什么关系

一条路画出来就有起点、终点、左边、右边和路面。一座桥有桥体、桥面铺装、两侧边缘和桥头。房间的每条边能定位到真实墙段，墙有厚度、两侧和沿墙定位的开口。即使土路两侧都空着，「右边」也已经是放置木栏或路灯的有效目标。木桥、石桥可以用不同的部件和材质预设搭成。栏杆的阻挡移动、阻挡视线与外观可分别设置。

| 关系 | 地图里的例子 | 编辑时应发生什么 |
| --- | --- | --- |
| 组成 | 桥体、桥面、桥柱和栏杆组成一座桥 | 选整桥能一起移动，选一节栏杆可以单独替换或删除 |
| 承托 | 山面承托一段道路，桥面承托桥上的物件 | 改宽、移动或平滑后，按实际路面宽度和落点复核支撑 |
| 附着 | 路灯沿道路右边排布，踏步铺在路线中段 | 跟随所引用的那一侧或那一段。独立摆放在旁边的灯保持原位 |
| 连接 | 道路末端吸附到桥头，桥头吸附到码头的接点 | 移动时预览两端能否继续接合，也能明确断开、稍后再接 |
| 共享 | 厨房和餐厅引用同一面墙 | 从任一房间选墙、改墙或开门，另一侧看到同一个结果 |
| 区域归属 | 鱼摊位于市集内 | 扩大市集边界可以把摊位纳入市集，摊位保留原来的世界位置 |

工程保存真实对象和部件、关系两端的身份，以及作者选中的部位。比如「右侧这一截」要能随路线变形定位，「删除这一节」要能在重新排布后识别。画布上的接近只产生吸附候选，接受吸附的落点才建立连接。图层负责整理、排序和编辑显隐，楼层决定对象所在的空间，高程和承托另行计算。

## 选区、删除与实例组件

删除范围由当前选区决定。只选餐桌就只删餐桌，同时选中餐桌和烛台就删这两件，选中「宴席」组就删该组及其成员。画布高亮与右侧对象树显示同一选区。搬桌时，吸附在桌面的独立物件会跟着移动。单删餐桌时，预览标出这些物件将解除的附着，撤销一次可恢复餐桌及原有关系。

对已附着的部件，锁定默认保护它相对宿主的摆放位置。例如把壁灯挂在门左侧并锁定后，平移整面墙两米，灯和光源随墙平移两米。要单独把灯挪到另一个挂点，先解锁壁灯。

作者可以直接在画布上给单个物件实例添加组件。例如摆下三个同款书柜，选中走廊里的一个，在右侧点「添加组件 → 视线遮挡」，沿柜背画线，再从门口预览柜后的可见范围。遮挡线只属于这个实例，随它移动和旋转。也可以在导入的木柜图上圈出可摆放花瓶的柜顶，同样的承托面可用于窗台、祭坛和货架。想在别处复用时，作者可以将改好的物件连同组件存入「我的模块」。

单个组件也可以直接跨项目复制。在项目甲选中书柜的「视线遮挡」组件并复制，然后在新标签页打开项目乙，或在同一标签页切换到项目乙，选中目标书柜即可粘贴。副本带入组件的参数、相对柜身画出的遮挡线，以及组件用到的固定资源和许可。目标项目为副本分配新身份，作者可以对照目标书柜调整遮挡线。若组件提供连接点，复制的是接点定义，实际连接在目标地图上建立。

## 沿山画路与露天开凿

1. 山地初始只有地形。作者选「道路」，从山脚拖到平台，样式给出默认宽度、铺面和栅栏设置。鼠标越出山面、在该高程没有承托时，画布标出放不下的区段，保留上一个有效预览。自动圆滑可以关闭，开启时也检查弯道两侧，避免圆滑后的路面切出悬崖。
2. 作者可以改整条路的宽度，也可以只改一截。使用默认宽度的路段遇到窄山肩可以自动收窄。建议在地形拓宽后让这段恢复到默认宽度。作者手设的宽度优先，空间不足时标出冲突位置，由作者改宽、改线或开挖。
3. 选一段或整条路铺台阶。台阶采用这段路线的实际长度、弯道、局部宽度和高程。假设入口与出口直线相距 5 米，作者画的是 20 米折返路，选择全段时，两个折返和上下端都要进入结果。检查要能指出哪段没有铺到、哪一端没有落地。
4. 碰到无处落脚的岩壁，可以先用地形工具削出山肩，也可以选中路段，主动使用「开凿山路」。同一候选展示削去的岩体、新的承托面、道路或踏步以及两端接合，采用和撤销各一次。普通画路只使用已有地形。将做好的山路样式用到另一座山时，沿新路线采样当地地形，再应用材质、踏步与沿边部件。

## 桥、道路与模块实例

**建桥有两个入口。** 可以选中已有道路的一段改成桥，沿用该段的走向并处理两端过渡。也可以从「我的模块」拖出独立的桥，再把道路接上。选中后都能改桥体、桥面材质和两侧部件。删除桥再新建会得到新实例，旧路端可以重新吸附。

**吸附决定是否建立链接。** 拖入吸附距离时，类型、楼层、高程和方向相容的接点自动吸附并显示接合预览。松手便建立链接。只是挨着放的桥和路可以各自移动。模块作者还可以在部件上标接点，例如给码头缺口指定「接桥处」。保存为模块后，每个实例按自己的位置和朝向提供这个接点。

**链接只带动能跟随的部分。** 已连接的桥挪动一点，路尾可以随之调整，画布直接画出调整后的路形。超出路尾可动范围、失去承托，或继续跟随会改动锁定路段时，显示红色断链和「放下将断开」提示。拖回有效位置可恢复预览。放下时，合法的桥移动与断链一并采用。若桥本身无处承托，则提示放置无效。撤销一次还原此前的形状和链接。

**桥柱和栏杆按部件排布。** 对定长栏杆，13 米长的可铺区使用 2 米一节的源件，默认排 6 节，余下 1 米留空，作者可以逐节调整。左侧原有四节时，作者删掉靠右桥头的第四节，再从右端加长两个节距，结果应是「栏、栏、栏、空、栏、栏」。整桥移动时，缺口随桥走。部件的稳定身份和局部位置承载这些修改，显示的「第几节」可以随排布变化。

**模块库是来源，画布上是实例。** 整座桥和单节带灯护栏都可以存入「我的模块」。实例引用固定版本并保存自己的实际部件和修改。作者发布新版后，用户选择要同步的实例。同步比较原版本、新版本和实例的人工修改，合入源模块新增的灯具，保留实例上单独添加的组件、手调部件、锁和已删除的栏杆。成员无法对应时，预览指出具体冲突，由作者决定。公共分享可在个人模块的制作、放置与同步体验成熟后再接入。

**更新原模块时可以逐项勾选实例改动。** 例如酒馆里的书柜加了视线遮挡，也刷了红漆。「更新原模块」列出这两项改动，作者只勾选遮挡组件并发布新版。以后从库里拖出的书柜使用模块原配色，带有这条遮挡线。红漆是酒馆这一个实例的外观，已有书柜仍由作者选择是否同步新版。

整桥在「素材 → 房间、建筑与桥梁模板」发布和同步。放置时，桥梁实例保存原模板的内容摘要。发布只把勾选的设置写入原模板的新版本，局部改动留在实例。同步时，按原模板和新版的差异，更新当前实例仍在继承的设置。排布照常沿实例自己的路线计算，手工删除的一整节保持留空。整桥的铺面、独立布置和路线几何可以随整桥另存，跨版本合并规则见[剩余事项](../roadmap.md#remaining)。

## 房间共墙、视野与工作台

**拖墙和搬房间有不同的结果。** 拖厨房与餐厅之间的共墙，两间房一宽一窄，门仍附在同一面墙上。选中整间厨房搬离时，餐厅留在原位，预览把即将分开的共墙标红，并显示已有门窗最终挂在哪一面。对于归属有歧义的门窗，建议由作者指定去向，沿用其开关、锁和秘密状态。采用后两间各有完整墙体，撤销后恢复一面共墙和原有开口。

**视线遮挡是一项行为。** 墙和屏风都能提供遮挡，通行另按各自的设置计算。制图时，作者可以在走廊放一个临时视点，开关普通门，观察柜台后方的可见范围，也可以预览某个分区揭开迷雾后的画面。面向玩家的预览和输出先过滤秘密，未揭示的秘密门在墙上应呈现连续遮挡。氛围薄雾属于画面效果，保密遮罩决定哪些区域必须盖住。棋子移动、探索记忆和多人同步归后续跑团设计。

**画布与右侧详情共用选择。** 单击桥先选整桥，双击进入部件，Esc 返回上一级。也可以在右侧展开「桥 › 左侧护栏 › 第三节」。两条路径选中同一节，画布高亮和属性同步。拖画布空白处平移视口，拖对象预览地图编辑，拖面板调整停靠位置。「我的模块」「楼层」「详情」的布局属于个人工作区偏好。

**分区在同一张地图上编辑。** 同一楼层、同一级的市集与河岸可以共边，内部互斥。边界划过摊位，摊位随之改属。双击市集只是放大到这片区域，新画的井回到镇图仍是同一个对象。分区支持按范围选取、细画和局部导出。穿过两个区的道路保持连续，局部输出按区域裁切其可见部分。玩家能看到区内哪些内容，仍由受众规则决定。

## 从现有实现接入

共享层按关系计算哪些对象要跟随、哪些部位需要重算、哪些连接会断。手工工具和 AI 都把这组变化交给同一套工程命令，工作台只呈现候选结果。接入一种新木栏，只需描述源节、排列方式和阻挡属性，桥和山路都能使用它。需要引入新行为的例子是吊桥升起时改变通行状态。

| 切入处 | 建议的改法 |
| --- | --- |
| 道路与山体 | 从「道路」画布入口贯通手势、完整路线、分段宽度、真实承托和阶梯。现有阶梯已经沿传入的中心线求踏面，排查短梯时先对照作者画出的路线、交给阶梯的区段和最终承托。沿用已有露天坡体的校验和采用过程。 [道路与楼层模型](../../src/shared/model/scene.ts) · [地形承托](../../src/shared/geometry/support-sample.ts) · [阶梯几何](../../src/shared/stairs/geometry.ts) · [坡体校验](../../src/shared/terrain-inlay/scene.ts) |
| 边、端头与开口 | 让道路和桥提供可定位的两侧与端头，让墙提供带厚度及开口的边界。绘制、吸附、通行、遮挡读取同一份来源几何，再各自应用门窗状态等规则。将既有门路连接的接点与跟随经验用于桥路连接。 [墙体绘制](../../src/shared/geometry/wall-paint-geometry.ts) · [门前净宽](../../src/shared/geometry/doorway-clearance.ts) · [光影遮挡](../../src/shared/visual/projection.ts) · [门路连接](../../src/shared/path-attachments/contracts.ts) |
| 部件与版本 | 沿用沿线构件、真实成员、人工删除记录和固定素材身份。先在桥栏上做通单节编辑、改长和选定实例同步，再用同一节木栏沿山路临崖侧排布，检验复用。 [沿线构件](../completed.md#generation) · [素材与模板](../completed.md#assets) · [固定内容与身份](../../src/shared/library/content.ts) |
| 工作台与工程 | 画布和详情发出同一编辑意图，应用层准备候选，采用时重检工程基线、依赖、锁和预算。已有等宽道路按恒定宽度读取，已有连接按保存的引用读取。保存和备份保全实际部件、固定资源与局部覆盖，导入后能离线继续编辑。 [工作区布局](../../src/editor/workspace/WorkspaceLayout.tsx) · [工作区事务](../../src/application/workspace/workspace.ts) · [工程与保存](../architecture.md#storage) |

开发顺序先做通沿山画路、局部铺阶和露天开凿，再用桥路验证同一段护栏、连接和人工覆盖是否可复用。共墙拆合验证共享对象的身份，分区、面板停靠与模块同步可以分别交付。

## Godot 的设计参考

- **场景实例与覆盖。** Godot 的 `PackedScene` 保存场景及其拥有的节点。放置实例后，可以覆盖实例属性，源场景修改时保留这类覆盖。织境采用固定模块版本，并由作者逐项发布实例改动、主动同步选定的画布实例。 [场景实例](https://docs.godotengine.org/en/stable/getting_started/step_by_step/instancing.html) · [PackedScene](https://docs.godotengine.org/en/stable/classes/class_packedscene.html)
- **对象组成与外部依赖。** Godot 的场景组织建议让子节点承担父对象的实际组成部分，并显式传入外部依赖。对应到织境，桥体和护栏属于桥，路尾与桥头保存链接，厨房与餐厅引用同一面共墙。图像和材质可以作为固定资源供多个实例共享。 [场景组织](https://docs.godotengine.org/en/stable/tutorials/best_practices/scene_organization.html) · [Resources](https://docs.godotengine.org/en/stable/tutorials/scripting/resources.html)
- **选区与详情。** Godot 的 `EditorSelection` 提供统一选区和变化事件，树中的顶层选区可用来执行整组移动。织境让画布和右侧详情读取同一选区，移动或删除时再根据对象关系求实际受影响的成员。 [EditorSelection](https://docs.godotengine.org/en/stable/classes/class_editorselection.html)

## 交付时如何验收

以下是后续实现的验收场景。每个涉及工程内容的案例都从正常工作台操作，同时核对撤销、保存重开及备份导入后可继续编辑。

| 操作 | 通过条件 |
| --- | --- |
| 从山脚拖出折返路，开关圆滑，收窄一段并给另一段铺阶 | 整个选中区段及两端都有承托，平滑后的外侧也在山面内。人工宽度保留，冲突能定位到具体区段 |
| 在岩壁主动开凿，再撤销 | 同一预览能看清切口、路面和两端。采用后山路可连续通过，撤销一次恢复原山体与原路 |
| 把桥拖近两条路，只吸附一端，再将桥拖远 | 只有已连接端跟随，断链位置在放下前标红。取消拖动保留原连接，放下只断开预告的接头，一次撤销恢复桥、路尾和链接 |
| 删一节桥栏、延长桥、同步加灯的模块新版 | 末端短料留空，原位置的登船口仍在。只有用户选定的实例同步，新增灯具和手工修改可以同时保留 |
| 给一个书柜加遮挡并刷红，在「更新原模块」中只发布遮挡，再从库中放置一个新版书柜 | 新书柜带遮挡且使用模块原配色，酒馆实例保有红漆。此前摆放的其他实例可分别选择是否同步 |
| 复制单个遮挡组件，分别在新标签页打开另一项目、在同一标签页切换项目后粘贴到目标书柜 | 两种操作都能直接粘贴。目标书柜按自己的位置和朝向显示遮挡线，副本可独立调整。在目标项目撤销一次即可移除本次粘贴的组件 |
| 分别拖共墙和搬厨房，再从玩家视点查看 | 拖墙时仍是一面共墙，搬房间时得到两面独立墙。门窗归属明确，秘密门和私密注记在玩家预览、输出中受保护 |
| 双击市集画井，移动市集边界，再按区导出 | 镇图与分区指向同一口井，摊位归属随边界更新，跨区道路保持一条，导出范围与受众正确 |

### 其他制图场景的讨论用例

| 场景 | 画布操作 | 建议的验收结果 |

| 酒馆家具与布景 | 把餐桌、四把椅子和吸附在桌面的烛台编成「宴席」组，再把一只组外酒杯吸附到桌面。分别试搬桌、搬组、删桌与删组，每次撤销后再试下一项 | 搬桌时烛台和酒杯跟随，搬组时椅子也一起移动。单删餐桌后，烛台和椅子仍可在组内选取。删整组后，可单独选取原先摆在桌上的组外酒杯 |
| 屏风、玻璃隔断与壁灯 | 给屏风画遮挡线，给透明玻璃隔断设置通行阻挡。从门口预览视野，再把屏风移开一道缝。把二楼走廊的壁灯归入照明图层，锁在门左侧的挂点上，再拖动整面墙 | 玻璃允许视线穿过，通行检查识别实际占地。移动屏风后可透过缝隙看见后方。壁灯和光源随墙移动，灯与门的距离保持作者锁定时的数值 |
| 树林、菜园与废墟 | 选树种和密度画一片林地，手动把两棵树挪到营地入口两侧，圈出入口和营地的「留空」范围，再调高种植密度 | 新树只补在可种植的地方。入口两棵树采用作者摆定的位置，圈出的空地可供摆帐篷。菜园的田埂、废墟中的空场可用同一方式留出 |
| 设备与管线 | 在自制水泵上标出进水口和出水口，把一根管线吸附到进水口，另一根只摆在出水口旁。拖动或旋转水泵 | 只有吸附的管端跟随，画布预览接头位置和相邻管段的新形状。放下会断开连接时，接头提前标红 |
