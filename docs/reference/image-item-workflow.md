# 图片 item 辅助制作工作流

本流程是项目默认[制作总则](project-creation-workflow.md)下的图片专用步骤，面向用户、应用中配置的大模型和外部制作助手。共同目标是从一张获准使用的地图中，得到可独立移动、边缘可以接受、来源可追溯、下次打开能继续修改的 item。规范随项目维护，工具执行步骤，具体状态与审核证据记录本次进度；独立制作工作包只是进度载体，不是工作流规范本体。模型名称、聊天记忆和操作者经验不作为恢复条件。开发排期只在[07](../07-roadmap.md#image-to-project-plan)维护，正式验收从[09](../09-quality-plan.md#image-to-project-acceptance)执行；这里定义操作协议和恢复方法，不记录每轮通过数字。

## 共同入口与能力发现

应用页面、项目内模型和外部助手应使用相同的原图坐标、严格参数、候选生成与采用链。模型开始时读取当前任务和可用工具，不能根据旧聊天推定已经具备视觉、分割、增强或导出能力。文本模型可以解释进度、收集标记和调用有限工具；看图须具备实际已配置的视觉能力和获准的图像输入。没有相应能力时保留人工路径并显示缺项。

运行时向模型提供可序列化的任务回执：任务身份、源摘要、当前代次、可用操作及参数 schema、当前 item、下一步、待确认问题、预览制品、预算与限制。提示词只负责解释这个回执；后续每个决定仍由工具验证，不能用提示词里的“已审核”跳过检查。应用中的模型接入状态及图像外发权限以[05](../05-ai-and-generation.md#image-import-tools)为准。

内置普通聊天和有限草稿任务默认加载项目制作总则与图片步骤，用户无需在每次会话重贴规范。当前普通应用聊天仍未接入这些图片制作工具；模型只有实际接入项目 MCP／相应工具，并具备看图能力与获准的图片输入，才能执行制作和视觉复核。缺少工具时按流程指导页面或可用宿主，不能假称已经执行。页面可导出给模型的接续说明，但不会自动外发原图，也不能把说明文本本身视为已经完成工具接入。

现有页面从“从图片新建场景”进入；程序宿主使用项目自带的 stdio MCP，启动参数由宿主设置，模型工具不接受任意文件路径：

```text
node tools/image-import/server.mjs --image ABS_IMAGE --license-file ABS_LICENSE --attribution TEXT --output EXISTING_OUTPUT_DIRECTORY
```

已有独立工作包时直接恢复，不必再次指定源图或许可文件：

```text
node tools/image-import/server.mjs --resume ABS_WORK_PACKAGE --output EXISTING_OUTPUT_DIRECTORY
```

先调用 `tools/list`，再 `image_import_workflow`；需要纯草稿详情时调用 `image_import_inspect`。修改工具要求匹配当前 `generation`；成功、撤销或恢复后重新读取代次。常规制作仍使用 `image_import_set_scale`、`image_import_set_room`、`image_import_set_source_boundary`、`image_import_extract_item`、`image_import_refine_selection`、`image_import_assess_fidelity`、`image_import_preview`、`image_import_build_project`。本轮新增工具如下，准确参数和预算仍以本次 schema 为准：

开始先区分三种范围：`roomPointsPx` 定义房间地面内边界；`sourceBoundaryPx` 保全整间原画，须包住墙沿、叶尖和所有家具最外沿，未设置时仅保留房间内边界；每件 `guide.boundaryPx` 只是局部分割的搜索上限。三者不能互相替代。完成标定与前两种范围后，先执行 `image_import_assess_fidelity` 预检，再拆第一件。工具报告越界时会给物件名和原图像素坐标；扩大原画外框后另存新候选，保留失败，不能把出界部分直接裁没。

| 工具 | 实际行为与使用时机 |
|---|---|
| `image_import_workflow` | 读取共同流程、任务 ID、当前草稿、代次、断点、暂定／实测比例、恢复的未完成选区，以及审核的输入匹配状态。`matchesInput` 仍需结合 `requiresOutputCheck` 核对实际输出，不能单凭布尔值关闭视觉项 |
| `image_import_set_checkpoint` | 用 `generation`、`notes`、`nextAction`、`scaleStatus` 记录问题、下一步和比例依据，推进代次；不授予视觉通过 |
| `image_import_guided_selection` | 在原图坐标 `guide.bounds` 内，用 `foreground`／`background` 笔迹生成选区；每笔为 `points` 与 `radiusPx`，可选 `edgeRadiusPx`。新请求默认显式算法2，旧配方无版本仍重放算法1。算法2可携带3–256点的 `boundaryPx` 粗多边形，外部硬背景，内部继续分割；前景笔刷越出粗范围时拒绝。不指定 `target` 时只返回蒙版和诊断；指定现有 item 后重放受影响图层，成功才更新草稿 |
| `image_import_local_segment` | 仅在宿主显式启用本机模型时可见；以房间 `contextBounds`、单件 `targetBounds` 与最多32个 `points: {x,y,label:0\|1}` 产生3份候选，保留各自分数、原网格选区、400%预览与来源；不自动选最高分或修改草稿。`target` 只选择已有item拆出前的输入。可选 `cleanup` 显式填≤4像素封闭小孔／移除≤4像素无正点孤岛，默认0，不封闭通向外部的椅隙 |
| `image_import_set_selection` | 对已有item采用选定模型候选，携带 `selectionMask`、`selectionOrigin` 和最新代次；新item通过 `extract_item` 携带同样两字段。源、实际输入像素和先前拆分基线须匹配，成功重放才一次更新，后续精修仍走共同画笔 |
| `image_import_set_surfaces` | 用最新 `generation` 和完整 `surfaces` 清单原子定义共用底材、取样及取证排除，再重放使用它们的物件；显式 `kind:'guided'` 可携带方向与有限结构路径，每条绑定可信可见参考及判断理由。图层以 `repair:'surfaces'`、`repairSurfaceIds` 引用，不能混用旧 `fills`。改变清单会改变输入摘要，须重新审核 |
| `image_import_analyze_repair` | 用 `target` 只读检查该物件实际补底，返回同组候选、适合原因、与周围冲突及原图坐标中的局部辅助建议，并输出来源／目标对照图。绑定当前输入摘要，不修改像素、审核或工程；修改取样、材质、排除及前后层后重新分析。状态只为待审或需辅助，分数不是成功概率 |
| `image_import_item_preview` | 用 `target` 读取真实400%黑／白／棋盘预览及当前 `inputHash`、裁片 PNG 与补底摘要和推断信息，先实际看图再复核 |
| `image_import_enhancement_candidates` | 用 `target`、`direction`、`count:2\|3` 和可选 `scale:1\|2` 从确切原分辨率裁片产生独立切后候选；返回父源、配方、像素变化及每份黑白棋盘PNG。只读，不修改选区、原图复核、工作包或场景；候选目录另行携带，采用经统一素材编辑页 |
| `image_import_matte_candidates` | 用 `{target,count:2\|3,bandPx?:1\|2}` 从完整原图上下文、当前选区及稳定外侧背景依据生成只读边带分色候选。仅反解已有半透明边带RGB，alpha与核心保持，二值裁片无变化；依赖完整上下文，当前仅供审阅，不走普通裁片增强的采用入口 |
| `image_import_subject_candidates` | 用 `{target,count:2\|3,method?,bandPx:1\|2}` 生成原裁片、覆盖与最终派生的只读候选。显式 `subject-contour-v1` 只接收二值选区与不透明原前景，边带固定1；`subject-matte-v1` 在内侧1／2像素作颜色混合估计。省略方法沿用已采用，否则旧matte；保护／排除省略沿用、`null` 清除。共同原图网格审阅与限制见[分阶段流程](#subject-refinement) |
| `image_import_set_subject_refinement` | 用当前 `generation`、`target`、候选 `inputHash` 与完整显式 `refinement` 原子采用已审阅派生；`refinement:null` 恢复原裁片。严格工作包v1保存配方，普通工程保存实际派生及来源；物理占地与补底不随视觉边缘改变，基线保真不授予派生视觉通过 |
| `image_import_review_item` | 用当前 `generation`、`target`、预览取得的 `inputHash`、`verdict: needs-work\|reviewed` 与具体 `note` 记录助手复核；程序重新生成并绑定实际 PNG／补底摘要，旧输入拒绝。`reviewed` 不代表用户P3 |
| `image_import_export_work` | 导出独立工作包，宿主返回实际文件路径、SHA-256 和代次；可用于结束会话和跨电脑接续 |

MCP 宿主在每次成功修改后写入新的 `work-代次-随机身份.sceneweave-image-work` 检查点，保留旧文件。只读预览和未指定目标的辅助选区不会被记成修改。检查点写入失败时，回执包含 `checkpointError`，当前结果可能仍只在进程内；应先显式导出并核对成功再结束。普通工程构建另行产生候选目录与冷读记录。

已有完整配方可离线重放：

```text
node tools/image-import/replay.mjs --image ABS_IMAGE --recipe ABS_RECIPE --license-file ABS_LICENSE --attribution TEXT --output EXISTING_OUTPUT_DIRECTORY
```

这些命令都要求已有绝对输出目录；新建和配方重放另需实际原图与许可文件，`--resume` 则从工作包读取已保全的资料。重放产生工程和冷读记录；它不能代替人眼查看裁片、背景与移动结果。配方只描述操作，不能单独恢复遗失的原图、未提交笔迹或外部截图。

### 可选本机语义分割

颜色相近的家具墨线、墙线和地板接缝容易混淆，可由离线语义模型提出另一组候选。宿主显式增加 `--local-model-dir ABS_DIR --python ABS_PYTHON`，需要独立依赖目录时再加 `--python-path ABS_DEPENDENCY_DIR`；准确准备方法见[贡献说明](../../CONTRIBUTING.md#image-item-workflow-tools)。工具不下载模型、安装依赖或上传原图，未配置时不提供此工具，也不改变页面颜色算法的默认行为。页面可通过同一工作包接着修正和保存已选候选；普通应用聊天和页面本身尚无直接启动本机Python的入口。

本机工具固定 `Xenova/slimsam-77-uniform` 的确定文件身份，使用原图PNG、CPU和显式正负点；模型接口没有box输入，`targetBounds`只是输出裁图范围，不应称为box提示。`contextBounds`则决定真正进入编码器的上下文；过小裁图放大可能把“家具连地毯”识别成整体，保留房间上下文应作为首轮选择。分数是模型内部预测，不能当作实测IoU或视觉分；每次比较全部3份候选，再决定选择、补点或局部画笔。模型提示点也不保证每个像素一定保留。

每次推理在输出目录保留独立输入PNG、三份候选、400%图和 `candidates.json`；空候选保留但不可采用。采用后的 `selectionOrigin` 记录原图及实际输入SHA、先前图层摘要、模型版本／两个权重文件摘要、上下文、目标区、正负点、所选候选和显式小孔／孤岛参数；这些资料随独立工作包保全，不进入普通场景格式。后续画笔编辑保留初始来源，并在journal记录修正，不能把初始模型参数当作最终蒙版的唯一重放依据。重新打开已选工作包不需要模型在线或再次推理；完整候选目录是包外诊断证据，跨电脑需要继续比较旧候选时另行携带。

## 可选切后优化

<a id="subject-refinement"></a>
### 主体、覆盖估计与去混色的分阶段流程

低清、压缩噪声和复杂背景的图片先检查主体完整性，再估计边缘覆盖，之后去混色，最后才试细节增强。先保全原始RGB与最终选区；需要轻度去噪帮助识别时另留识别图，不把它自动用作最终颜色源，细描边／叶尖损失时不用。主体缺块或选入背景先用原有分割和少量硬画笔修正，不能靠透明度或锐化遮住错误。

主体派生仍使用同一 `subjectRefinement` 字段，必须显式记录方法、边带和强度。两种方法解决的问题及边界不同：

| 显式方法 | 输入与变化 | 保全与需要判断的范围 |
|---|---|---|
| `subject-contour-v1` | 只接受二值选区和选中处不透明的原前景，`bandPx:1`，内外各1原像素估计几何覆盖，并尝试补偿总覆盖面积；`strength` 为 `gentle`／`balanced`／`strong`。覆盖阶段与最终派生是同一结果，**尚未去混色** | 核心、细杆、孔洞、显式主体保护与邻物保持；原选中RGB不变。外圈RGB延拓自相邻原前景，外侧新增位置是推断，不能称轮廓支撑范围不变。是否补偿成功看指标，面积接近也不保证每处描边归属、粗细或自然程度 |
| `subject-matte-v1` | `bandPx:1\|2`，仅处理现有非零选区内侧1–2原像素带；可信内侧F和外侧B须能解释观察色C，分别提供原裁片、原RGB＋覆盖估计和去混色派生 | 核心、细杆、孔洞与显式前景保护保持，不外扩非零轮廓。颜色近、描边多色、底色弱或残差大时保持原版，给有限原图坐标／原因；alpha和前景色变化仍是估计，不恢复未知真实细节 |

MCP的 `method` 省略时沿用已采用方法；没有已采用方法时沿用旧 `subject-matte-v1`。页面尚未采用时按实际选区选择待生成方法：二值选区且选中处源不透明才默认 `subject-contour-v1`；已有半透明覆盖则默认 `subject-matte-v1` 并解释原因，不自动二值化或清掉原alpha。显式蒙版、辅助分割与多边形使用同一实际选区判断；旧工作包恢复已采用的明确方法，不静默换法；只有显式采用才写入派生配方。两种方法都不能补救主体错选；邻物、保护、显式排除与working前序推断不作颜色依据，几何外推也不跨已知邻物或被排除的位置。有歧义的小处先补主体保护／排除或修正选区，再重新生成。

页面“主体边带精修”按共同原图网格、统一倍率和黑／白／棋盘显示三阶段，可选方法／允许的边带／强度，定位未决区域，查看后显式采用，或恢复原裁片。轮廓方法的输出图框可能向外扩1像素，原裁片在三阶段并集图框中补透明；不能按各自裁片左上角强行对齐。橙色未决区与主体保护都按原图坐标映射，物理占地不随视觉图框扩大。方法、参数或输入变化使旧候选失效，失败保留当前已采用结果。

MCP先用 `image_import_subject_candidates {target,count:2|3,method?,bandPx:1|2}` 读取原裁片、coverage PNG、最终派生PNG及当前inputHash；轮廓方法显式使用 `method:'subject-contour-v1',bandPx:1`，其coverage与final相同。实际看图后用 `image_import_set_subject_refinement {generation,target,inputHash,refinement}` 原子采用完整显式配方，`refinement:null` 恢复原裁片。额外保护／排除蒙版沿用原图坐标二值RLE及共用预算。工作包仍是同一严格v1，保留输入／配方而不嵌入诊断PNG；跨电脑重新计算可复现，候选对照目录另携带。

页面可直接使用“保护主体描边／擦除主体保护”，在原图涂少量必须保持的像素。黄色覆盖、0.5–16原像素半径与独立取消／清空入口只操作前景保护，不改裁片选区、移除范围或补底保护。未完成的笔画取消会回滚；保护变化使旧候选失效，重新生成并显式采用后才随工作包保存。没有采用的临时保护不作为已保存断点。MCP或高级输入仍可提供确切二值RLE。

MCP的只读主体候选也接受可选`foregroundProtectionMask`／`excludedEvidenceMask`：省略沿用已采用输入，传二值RLE预览新的局部辅助，传`null`预览清除该项。三者都不修改任务；按输出中的确切配方审阅后再采用，共用蒙版预算及原图边界照常检查。

旧matte的非零支撑保持只说明没有彻底删像素，不代表描边没有变淡；轮廓方法允许外侧推断，不能套用支撑范围不变的说法。压缩噪声可能使真实黑边也符合混色拟合，故须比较白底是否出现断续浅缝，并对已确认的真实描边作明确保护。若目标与邻物共用接触边，先扩大原图核对归属；取证排除不等于禁止人工选区，人工保留也不使该像素自动成为可靠旁证。不能只按颜色相似，把柜沿或琴凳边复制给主体。当前实图三件整体尚未通过，本流程不授予稳定画质通过。

采用的派生用于独立item预览、后续可选增强及普通完整工程的实际素材，并保留确切方法与来源。原选区记录、原图RGB、补底范围、物理占地和原始保真重建保持；matte可改变派生中的原选中RGB，轮廓方法保持该RGB而允许外侧位置推断。保真检查只证明原裁片基线与补底，不认证派生外观。采用改变审核输入身份，后续物件的取证轮廓变化也使主体复核失效；不把保存／冷读相同称视觉改善。主体与边缘未过时不靠锐化、插值或模型重绘推进为完成；通过后可用既有增强候选逐一比较，零变化／无收益明确不采用。

先修正选错、漏边和带入背景，再按缺陷选择方向。下列 `image_import_enhancement_candidates` 的 `direction:'contour'` 是既有独立裁片增强，不能与上述 `method:'subject-contour-v1'` 混用：它仅调整有实心内侧支撑的部分二值斜角alpha，RGB、非零覆盖范围、孔洞和无支撑细杆保持，不能重新识别正确轮廓。`edge`只处理已有半透明覆盖，纯二值裁片可能完全不变。`decontaminate`须有可靠邻近透明区与内侧颜色依据，也可能无变化；它不能解决所有混色边。`clarity`插值放大只平滑呈现，不恢复未知细节；去噪须防止丢掉原笔触。

查看全部2/3份候选，与原裁片按同物理尺寸、100%及400%黑白棋盘背景比较，零变化和无实际改善均不可称提升。MCP将确切源、候选、换底图及 `candidates.json` 写入独立目录并复读；该目录不在三条目工作包内。工具不把增强结果写回原蒙版、保真重建或旧复核。实际采用须在统一素材编辑页以同一父源、同配方生成，再经现有保护、场景预览、一次采用、撤销和冷读；当前MCP不直接自动采用增强结果。

另有独立的 `image_import_matte_candidates({target,count:2|3,bandPx?:1|2})`，用于审阅已有半透明边带的背景混色。它同时读取完整原图上下文和当前选区，只在外侧存在稳定可见底材时估计前景RGB，排除保护区域和未审核的前序推断；alpha、实心核心及选区保持，二值裁片不处理，缺少依据时不变。查看全部候选并对照原色，不能把零变化或局部估计称为真图全面改善。

边带分色候选另存其确切输入、选区与取证摘要，仍是只读审阅制品。当前统一素材页只有裁片，缺少该配方要求的完整上下文，不能同配方复现，因此不自动采用到个人素材或工程。上文 `contour`、`edge`、`decontaminate` 等既有增强方向继续使用原采用链；不要把边带分色候选伪装成这些裁片处理方向。

## 持久任务与制品

工作任务在独立图片拆分工作包中保留制作资料，允许未完成、失败和多个候选。采用成功后，普通场景工程保存已采用的合法资源、必要来源关系及工作包关联；打开、渲染和继续编辑场景必须可以独立完成，不能要求工作包仍在原电脑路径。回到制作过程则通过关联选择并校验相应工作包。主持人的整张原图、辅助笔迹、否决原因和制作预览不进入玩家输出。完整工程、个人素材库和制作工作包是不同交付对象，界面必须分别说明保存了哪一份。

| 记录 | 最少内容与约束 |
|---|---|
| 原图 | 原始文件名、字节数、SHA-256、规范化源 SHA-256、尺寸、来源／许可；两个摘要分开。原始文件与规范化像素只读保全，不能因修边覆盖 |
| 房间任务 | 稳定任务 ID、房间 ID／名称、原图内范围、墙沿外框、房间内边界、标定及其“实测／暂定”性质、实际世界尺寸、任务代次 |
| item | 稳定 ID、名称、用途、可移动性、对象／地面覆盖／阴影／环境角色、上层遮挡及下层支撑、独立物理占地、当前阶段、未决问题 |
| 辅助输入 | 粗范围、前景／背景种子、保留／排除笔迹、原图坐标与像素半径、局部搜索范围、孔洞、采用顺序；直接覆盖蒙版时仍保留上一步 |
| 算法候选 | 固定算法及重放版本、参数、确切输入摘要、输出蒙版／透明 PNG 摘要、不确定区、补底分区和取样范围；实际实现未测的读取量不能写成统计事实 |
| 图像派生 | 原图保真裁片和增强候选各自身份、确切父源、处理参数及推断区；否决候选保留，不覆盖保真版本 |
| 审核 | 审核人／助手、确切候选摘要、黑白棋盘底与原图同尺度预览、移动／旋转及露底证据、通过或具体缺陷；技术检查和视觉决定分开 |
| 断点 | 最后一次验证成功保存的位置与摘要、当前 item、下一操作、依赖缺项、失败原因、待执行复验；文件存在不自动等于可冷读 |
| 交付 | 工程／个人库／工作包路径、字节数、SHA-256、冷读与重新编辑结果、未解决缺陷、仍需单独携带的文件 |

工作包实际携带原始源字节和规范化 PNG；包外的截图等资料另列经校验的依赖清单，不能只保存当前电脑的绝对路径。跨电脑缺必要许可或资源时保留包并说明缺项，禁止用同名图片猜测替换。读取、验证和重放全部成功后才切换活动任务；写入或冷读失败时继续保留上一次可用状态。

### 当前工作包结构与实现入口

独立文件扩展名为 `.sceneweave-image-work`，ZIP 只接收三个固定条目：`state.json`、`original.bin`、`normalized.png`。`original.bin` 保留上传文件的原始字节，真实类型由状态和实际编码共同核对；`normalized.png` 是绑定源身份的规范化图片。当前包保存制作状态与输入，实际预览 PNG 可重放生成；需要携带旧预览或否决候选时，将对应检查点和图像证据一同保全，不能声称三条目包已经嵌入全部截图。

共享实现为 [workflow.ts](../../src/shared/image-import/workflow.ts)：`imageWorkStateSchema`、`parseImageWorkState`、`writeImageWorkPackage(state, original, normalized, signal?)` 和 `readImageWorkPackage(bytes, signal?)`。严格状态包括：

- `format: sceneweave-image-work`、`version: 1`、稳定任务 `id` 和单调 `revision`。
- `image` 规范化源摘要／尺寸，`original` 原始摘要／字节数／名字／类型，以及未确认时也可保存的 `rights`。
- `draft` 中的题名、完整或尚未完成的标尺、距离输入、原点、房间／外框、已拆图层、倍率与可选共用 `repairSurfaces`；旧矢量设置可保全，但不因此获准采用。
- 可选 `active`，保存当前物件名字、尚未闭合的粗轮廓、不完整取样框、最终精细蒙版、辅助分割输入、补底分区、尚未提交的分区轮廓／取样点、占地与正在精修的 item ID；与已拆层一样保留 `appearanceSource`、`repair` 和 `repairSurfaceIds`。擦空的未完成选区以 `emptySelectionBounds` 明示，恢复时不能变回粗多边形；空选区仍不可采用。辅助输入可以暂缺前景或背景，执行分割时仍须补齐。
- `notes`、`nextAction`、`scaleStatus`，带输入／输出摘要和可选 `paramsJson` 的 `journal`，以及绑定确切输入／裁片／补底摘要的 `reviews`。

任务角色、遮挡理由和不能确定的细节应明确写入问题记录；上表的全部业务含义尚未各有独立字段，不能将自然语言描述冒充结构化校验。已拆层的 `guidedSelection` 保留辅助候选输入，`selectionMask` 保留最终人工修正结果，两者职责分开。

表面及其取证排除蒙版与已拆层、当前未完成蒙版共用既有累计像素、段数和状态字节预算。保存和冷解析不放宽限额；缺失或重复引用、非二值表面范围均拒绝。制作包仍只有上述三个条目，普通工程无需制作记录即可独立打开。

共享读写核对实际 ZIP 目录、CRC、字节 SHA-256、格式、尺寸和状态预算。浏览器边界 [image-workflow-store.ts](../../src/platform/browser/content/image-workflow-store.ts) 的 `readBrowserImageWorkPackage` 还实际解码，对照原文件规范化后的像素与包内规范化 PNG。独立 `ImageWorkflowStore` 使用 `sceneweave-image-workflows` 数据库；`save(bytes, expectedRevision, signal?)` 做版本比较与写后读，`loadLatest(signal?)` 返回经完整读取的最近工作，不自动清库。

### 页面保存与接续

图片导入工作台已接入自动保存、打开／导出工作包和“继续上次拆分”。修改停稳并完成当前笔画后保存制作进度；查看真实保存状态，失败时用导出保全。未完成标尺、当前物件、辅助标记和选区属于制作进度，尚未采用时也可以保存。刷新后打开工具，通过“继续上次拆分”恢复本机最近任务；跨电脑使用“打开制作工作包”。页面和 MCP `--resume` 都沿用工作包稳定任务身份，原文件保持；页面导入后若本机已有同ID任务，保存会报告冲突并保留双方，可先导出当前成果再选择恢复，不覆盖既有记录。

“导出给模型的接续说明”产生工作流与状态 JSON，须连同工作包交给实际具备看图和工具能力的模型。它不包含图片字节，不替代工作包，也不自动给当前应用聊天添加图片工具。

普通工程及采用资源的来源署名包含“图片制作任务：任务ID”，用于关联制作资料。工程仍携带实际采用的合法资源，独立打开与渲染不依赖工作包；通过该 ID 回查工作包时仍需用户保全对应文件。实际页面恢复、冷读和独立试做结果由07及其主题证据记录，接口接入不代表这些用例全部通过。

## 阶段与通过条件

阶段是可恢复的工作进度，审核是绑定确切结果的事实，两者分别保存。“已生成”不自动变成“已通过”。每一步的失败都保留输入和最后可用候选，并返回可继续的下一步。

| 阶段 | 动作 | 离开本阶段的依据 |
|---|---|---|
| 建立任务 | 核对原图、范围、许可，建立标定与 item 清单 | 源图可读且摘要匹配；未知实际尺寸明确暂定，不以格线猜实测值 |
| 明确对象 | 确认独立移动范围、支撑、遮挡、阴影和组合关系 | 一个 item 的含义清楚；依赖有方向，无循环；环境光晕不混进家具 |
| 辅助分割 | 粗框或粗轮廓，少量前景／背景标记，生成局部选区 | 存在可回看候选、保留人工输入、算法和参数；不确定区仍明确 |
| 修正边缘 | 放大检查，以保留／排除笔局部修正，再处理覆盖度和孔洞 | 细杆、叶尖、黑描边与孔洞保留；背景、地毯和墙面没有大块带入 |
| 换底审核 | 同尺度原图、黑／白／棋盘底，100%及200%–400%，试移试转 | 没有明显背景色边、削边、粗锯齿、矩形残片或内部误透明；仍失败则回到分割 |
| 补底审核 | 分材质标注遮挡区和取样，物件移开后检查旧位置 | 看不到物件重影、矩形补丁、明显纹理接缝或重复暗带；原可见区域保持 |
| 可选增强 | 在保真裁片上生成独立派生，对照缩回原尺度的画面 | 有实际可接受改善，保持原件与来源；推断细节明确，不称恢复事实 |
| 工程采用 | 形成完整工程，按普通预览、采用、保存和撤销链执行 | 实际资源、许可、物理语义、支撑、身份和基线检查通过；未确认候选仍可保留 |
| 交付恢复 | 导出三种所需制品，在空存储／新任务中重新打开 | 裁片、选区、辅助输入与状态可恢复，已采用 item 可移动和继续编辑，摘要可复核 |

前景和背景种子用于约束分割；保留和排除笔用于表达明确的人工选区决定。不能把四种笔迹混成仅最后一张 alpha 图。局部重算应保留范围外结果，确认变化影响了哪些后续遮挡层；后层裁片来自前层补底时必须标注推断来源。

模型候选主体完整后，只剩局部漏边或环境凸块时，优先直接修正当前蒙版。一次保留／排除画笔后查看实际PNG，再决定下一笔；模型提示点可能改变别处，不是硬保留／排除。先从原图判断该处属于物件还是环境，无法辨认的细节记为未决。此顺序用于减少无效重推，不能据此放宽有限辅助试做的次数或笔数。

新辅助任务用颜色混合模型与图割寻找边界，并暂不采用没有前景种子连接的独立同色岛；真实的分离细节可补前景。页面用橙色覆盖显示当前算法候选的待判断区，人工修正或标记变化后旧覆盖失效。粗轮廓应包住真实描边并留出少量余量，凹角可隔开与家具相连的地板线；它是计算上限，不能代替内部细边与孔洞识别。新候选显式写入算法版本，旧配方不因升级改变输出。

新辅助输入显式使用 `algorithmVersion: 2` 与 `edgeCoverage: 'boundary'`，页面新任务自动记录。后者将透明过渡限制在确切空像素相邻的外缘，内部恢复分割得到的实心覆盖，避免把原画内部明暗误当成多像素宽透明带；不改变RGB，也不扩大原图保真豁免。缺少该字段时沿用旧结果，恢复旧工作包不会静默换图。粗范围触边诊断 `touchesCoarseBoundary` 提醒先检查是否削掉描边或叶尖。`outlineRadiusPx: 0..3` 是显式可选的近主体暗墨保留，默认0；它可能带入相连环境线，真实钢琴对照未证明普遍收益，不应作为默认画质修复。

补底方式另行选择：`tile` 重复取样，`seamless` 作平滑色差衔接，`aligned` 先匹配同材质取样相位；`texture` 固定为原尺寸纹理补片，不平滑、旋转或镜像原笔触，至少需要3×3同材质取样。四者都属于遮挡内容推断；纹理补片仍可能重复、亮度不匹配或板缝错接，实际移开后审核，不能把“没有糊色”写成补底自然。

页面的“画移除范围／画保护范围”把补底与裁片分开：橙色二值移除区域须包含全部物件选区，可额外包含阴影／漏墨；青色保护区域从实际写入扣除，也不参与边界颜色估计和干净取样。移除非零像素最多到物件图框外32px，与旧残影外扩互斥；保护不能穿过选中物件，取样与任一范围相交拒绝。未完成点、复杂导入蒙版、局部编辑和撤销分别保全，不用矩形框替换原蒙版。MCP通过 `image_import_set_repair_scope` 一次设置两种范围，`null`清除；失败保持最后可用任务，后续层整体重放并重新核对输入摘要。

<a id="surfaces-and-sources"></a>
### 共用底材表面与裁片来源

同一严格配方v1中，每层可显式选择 `appearanceSource:'original'|'working'`。`original` 使用捕获原图，适合保留新家具的原色；`working` 使用该层之前已补底的背景，适合先去掉上层遮挡后提取柜体／柜面或地毯。旧配方缺省仍为 `working`。例如先移植物并补柜面，再以 `working` 提净柜体；先移上层家具并补毯，再以 `working` 提净地毯。先前补底属于推断，不能当作捕获原图；`original` 裁片不计前序补底提取量，背景修补及其来源标记仍保留。

跨底材或多件共用同一底材时，可在“分区补底”中标注完整底材范围及干净取样，再“保存为共用底材表面”。每项严格保存 `{id,name,kind:'soft'|'planks'|'patches'|'neighbors-soft'|'neighbors-planks'|'guided',mask,donor,excludedEvidenceMask?,guided?}`，最多16项；底材 `mask` 包含被家具遮住的部分，`excludedEvidenceMask` 列家具及其阴影、保护区域和未审核推断等禁止取证范围。二者均为原图坐标二值蒙版，排除取证不等于扩大或缩小移除权限。取样每个像素都须在同材质范围内、排除区外，并在重放时保持不透明、未移除、未保护。

`soft` 适合织物或连续色面，`planks` 适合有可见窄缝依据的小范围木板接续，两者取样至少3×3；`patches` 取样至少8×8，使用原尺寸有限纹理拼接。拼接不恢复未知木板拓扑，也不自动保证自然衔接；重复纹理、接缝、色差和暗带仍须实际移开后审核。

<a id="neighborhood-repair"></a>
“同组邻域 · 织物与连续色面”（`neighbors-soft`）及“同组邻域 · 木板结构”（`neighbors-planks`）是显式可选的同组比较与补底方式，取样至少4×4。“同组”由明确的底材范围决定，不能只因颜色接近就混用地毯、木板、阴影或柜面。算法在该组可信原像素中查找完整小块，比较局部与较大范围的颜色、梯度、细纹和结构，并联合检查相邻候选的拼接与重复使用；实际写入仍限于移除与底材交集并扣除保护区。未移除家具及其阴影也须标为取证排除，不能依赖算法自动认出它们。

同组候选只使用未移除、未保护、未排除、未被前序修补推断的不透明原像素；整块来源都须可信。先前补底即使看起来相似，也不能成为新一轮的原图证据。已有 `soft`／`planks`／`patches` 配方保持原算法；选择新类型后重新生成并审阅，不静默替换旧输出。可信取样不足时，修补明确拒绝；只读分析仍可定位证据缺口并说明需要哪种小范围辅助，不编造候选分数。

使用物件清单的“分析补底”或 `image_import_analyze_repair`，同时看来源小块、目标原图及实际补底。每处候选说明来源位置、可见依据数量及各项差异；冲突指向具体小块或接缝，区分颜色／材质差异、内部或外沿跳变、平补、重复纹理与缺少结构依据。局部提示的“去补充干净取样”“去标记不可信区域”“去修正底材范围”“去对照板缝并取样”会定位原图并进入相应标注工具；候选可“定位同组参考”或“以此处为起点重新取样”。这些动作本身不采用结果。完成标注后用“仅更新干净取样”或对应表面更新操作实际重放，只改建议指出的小处；无法辨认的隐藏板头保留未决。

差异分数只用于本次候选比较，既不是概率，也不是质量通过线。`needs-guidance` 表示有冲突或证据缺口，`needs-review` 表示当前规则未发现明显冲突，两者均须实际视觉审核。输入或图层顺序改变后旧分析失效，须重新计算；独立工作包保全范围、取样、排除和先前层等可重放输入，不把诊断缓存或整份分析写入普通场景工程。候选对照图等包外证据另行携带。

<a id="guided-surface-repair"></a>
#### 有限结构辅助

结构粗线先检查笔触来源。只读邻域分析的每个参与guided表面可返回`structureReferences`，逐块列出完整表面已保存的引导序号、原图参考、方向、原理由，以及逐截面最暗位置差、半深度线宽差／中位数和对比度。页面展开“原图结构参考”可看400%原像素并定位；MCP的`reviewLayout.structureReferences`提供相同依据，原图紫框表示有疑点的参考。每表面最多32块、每块最多4096像素；整块不可信则不读取其RGB。只增加只读小块测量，不另作修补求解、不改变配方或写入权限。

最暗位置差或线宽差≥3px、线宽中位数≥5px、截面对比不足5级及深色带触框只作固定提示。曲线、斜缝、交叉线、装饰和原阴影都可能触发，不能自动分类为错误或排除；无提示仍须看图。表面全部引导会列出，即使部分路径未经过当前物件移除区，不能由有疑点推定本次缺陷由它造成。先对照真实原图，确认其角色，再用同材质可信窄缝替换必要参考并重放；路径与参考角色分开判断，不为消除提示改阈值。

整齐断头另查`structureEndpoints`。仅当已保存引导的起点／终点处于本次实际可写补区，且沿末段向外仍有至少3px连续可写同表面时，返回具体原图位置、连续距离和32px内可达的声明底材边缘距离。每条最多查两个端点、每端最多32步，只读范围关系，不读取隐藏RGB，也不穿过保护或不连续写入区累计距离。页面“结构路径端点”可定位补图，MCP的同源布局在补图以粉框标记；独立于常规24条冲突，不因列表满而丢失。它可能是真实板头或有意收尾；先对照可见线端，明确这里应接缝、停笔还是短距收尾，再只修改必要路径并重放。无提示只说明未触发这项几何规则，不证明笔触、材质边界或隐藏走向正确；不自动延长或扩大移除权限。

颜色误差低也可能丢板头或换钉点。只读`structureMotifs`在当前写入最多的guided表面、且方向明确为horizontal／vertical时，检查实际补图的深色笔迹及外侧3px内允许的原图；soft及其余表面未查，不由无提示推定正确。12级局部对比、八邻接分量和少于3个原图深色锚点仅用于指出小范围；长分量偏离13px局部主线至少3px的分叉另查，不能借主线锚点通过，分叉扫描另守800万有限操作。完整总数、未列组数／像素及跳过分叉数保持，最多六处定位，独立于常规24条冲突。`counts.components`数整分量，`uncertainComponents`还包括另查的分叉，不能相减当通过率。

页面“补图笔迹角色”可定位当前补图或对照原遮挡，MCP同源布局／橙框。`kind`区分整分量和长线分叉，`extent`只描述沿纹理／横跨／集中形状，不识别真实板头或钉点。对照附近同材质原图，必要时只补少量结构辅助或换取样，不自动加线、擦除、扩大移除或改变审核。保护、当前其他移除、排除、前序推断、未移走物件及非不透明原图均不提供颜色锚点；非写入补图也不提供颜色。宽色块、浅笔迹、完全隐藏且未生成的原板头和3px外都可能漏检，有锚点也可能接错。真实真值已暴露这种漏检，低误差或提示消失均不能授予结构通过。

同组小块仍产生宽补片、重复线或底色／细纹混在一起，或局部缺少可可靠自动接续的板缝时，可显式选择“结构辅助 · 显式推断路径”（`kind:'guided'`）。它分别估计可信底材的缓慢明暗变化、干净取样的细纹和有限线结构，再合成待审补底；细纹受原取样幅度限制，不凭空强化纹理。它可能仍有平补、色差、重复或错缝，真实候选须移开物件后检查，不能因算法分开了底色与纹理就认定自然。

宽亮暗块须先查底色依据。只读分析对当前写入最多的一个结构辅助表面，额外追踪实际求解中的局部底色观察：指出所用原图坐标／RGB、附近同材质观察的差异及需确认的小范围，其余表面明确未检查。最多8处提示；常规冲突仍最多24条且不挤掉旧发现，未能列入的底色提示通过`additionalToneFindings`单列，页面提供“原图底色依据”的定位／标记入口，MCP对照图在原图以黄框表示。合计底色提示不超过8处，不重复展示。阈值只用于提醒，不证明暗色就是错误，真实渐变和阴影也可能触发。合法可见原像素仍可能来自柜沿、描边或环境影，不能因其“未被排除”就认定属于地毯或木板。

先对照原图确认提示中的取证角色，再只在必要的小处补充 `excludedEvidenceMask`，合并保留旧排除并重新重放和分析。取证排除只禁止参考该处颜色，不授予写入或删原线的权限；新候选变亮后出现阶梯接缝时，分别检查原移除范围与范围外烘焙阴影，不能继续扩大排除掩盖它们。原图已有折线、纹样或暗线保留归属未决；隐藏底色仍是推断，没有真值时不宣称恢复。

该类型必须携带 `guided:{orientation,guides,detailPatches?}`；其他类型禁止携带 `guided`。`orientation:'horizontal'|'vertical'` 声明可见板缝的延续方向，只有相称的可信双侧依据才尝试自动连接；`'soft'` 关闭自动板缝连接，仍允许明确的人工路径。`guides:[]` 可仅处理底色与细纹；确需补充结构时再加少量路径，每条为 `{points:[{x,y},…],reference:{x,y,width,height},axis:'horizontal'|'vertical',reason}`。`axis` 描述参考线方向，`points` 描述人工决定的隐藏延续路径，`reason` 说明可见依据及不确定处。这里的 `guided` 是底材辅助，不是物件辅助选区 `guidedSelection`。

板头或钉点的二维形状不能用窄线截面沿路径拉长时，可显式添加 `detailPatches:[{role:'board-end'|'nails',reference:{x,y,width,height},target:{x,y},reason}]`。`role` 是人工声明的用途，不是算法识别结果；理由应说明可见依据与推断。每块参考宽高各5–64像素、最多16块，与路径合计最多32项；目标整数坐标、保持原尺寸、不旋转／缩放／重复，目标框不重叠。参考整块须是当前可信同材质原图，目标整块位于当前底材，实际仅写本次移除且未保护的交集。不会增加原图移除权限。

缺省叠加模式的二维笔迹用7×7局部原图的明暗排序第80百分位估计底色，提取深色差；4至12级渐入、最多180级差，避免把平色框整体覆盖。合成只加深已有推断底色，原有长缝和没有参考笔触的位置保持；补区外上下文只有在同次可信图允许时才参与，前序推断或保护像素不被重新当作原图。无足够深色笔触、越界／重叠或不可信参考明确拒绝，取消不返回局部成功。此缺省模式不能删除旧错线，仍可能新增双板头、重复钉点或错接；这类冲突需对照原图小处判断，不能为消除提示扩大移除。

页面沿用结构辅助JSON载入／另存／原子重放，紫框为原图来源、橙框为原尺寸目标，展开可读角色、来源、目标与理由；MCP `set_surfaces` 消费同一严格字段，`analyze_repair` 汇总确切用途及局限。同一v1工作包保存配方，旧配方缺省不变，变更使旧审核失效。采用前看100%与400%局部、再导出并空冷读；专家精确放置只能证明局部辅助，不证明隐藏真值、新手稳定五类或整房通过。

每表面最多32条，每条2–16个原图内且属于该底材的点，路径总长1–8192像素，理由去除首尾空格后1–400字。每个 `reference` 是整数像素框：沿 `axis` 至少3像素，横跨至少5像素，面积最多4096像素；它须包含可区分的窄线和两侧底色，平面或宽阴影会拒绝。`donor` 至少5×5、最多100万像素，移除图框最多25万像素；表面／蒙版预算仍按共同合同，不通过增加路径绕过计算预算。


**小处替换错误生成笔迹**：`detailPatches`可显式给`mode:'replace-ink'`，在底色／细纹合成前以可信原图二维墨差替换本次生成墨迹，源中零墨也有意义；不整框复制参考底色，不改变原低频场或细纹。`role:'gap'`必须搭配此模式，允许真正无墨的同材质参考；`board-end`／`nails`仍须有可见笔触。缺省仍是旧只加深。沿用每块5–64px、16块／合计32项、完整可信来源、目标不重叠、同材质内、当前授权且未保护写入交集与计算预算；不擦改范围外原图，不把前序推断当来源。角色、目标位置及是否应断开仍是人工推断；框错可能擦断长缝、制造台阶或错接，不能由低误差授予通过。页面已采用参数、分析理由与MCP同源，同一严格v1包保存并冷重放；改变使旧审核失效。先看100%／400%及每步露底，专家精确选源不计新手预算。

替换框边出现硬接头时，可显式试`blendPx:1..4`原像素，必要时先试3；仅用于`replace-ink`，宽高各须≥`2*blendPx+3`，保留至少3px不混合核心。距离按本次可写区域计算，包含框边和保护孔：边界保留旧生成墨，短距离平滑转到参考墨，核心保持来源笔迹。它只混合两组本次生成墨，不改变底色／细纹／alpha，不读目标遮挡RGB；旧生成墨仍是推断，不能成为新原图依据。省略仍为旧硬替换，不静默更新旧配方。线心错位、双线和宽暗带不能靠过渡保证解决，须再核100%／400%、每步露底及长缝关系；页面标签、MCP理由和同一v1包保留完整参数。

**诊断接续的当前性**：使用旧分项或疑点坐标前，重核当前确切包／源码及该点的选区、移除、保护和取证成员关系。已排除的旧暗样本不能重复解释当前结果；未获移除的原边仍会保留。新分解须先证明最终输出与当前候选逐像素相等；单项显示仅对应实际写入部分，其余保留图不能冒充该项已重建。局部配方的视觉证据与另一普通工程的保存／冷读证据分别绑定，不混签。

若截面沿路径铺开形成机械直线，可只在必要的guide加 `stroke:'original-segment'`。此时沿 `axis` 至少5px、横跨5–31px、总面积仍≤4096px，路径沿该轴严格单调且可整体反向；折返／同轴重合段拒绝。每个连续可写段使用参考内一段完整原尺寸列，较短参考明确拒绝，不拉长、反射或重复短线填满。参考每列以明暗排序q80去底色，保留窄主线附近最多±6px的原二维起伏与断续；不会按软边变宽就丢整列。旧guide缺省仍使用原截面算法。

原尺寸接缝把相邻木板底色差带成宽墨带时，可在该guide显式加 `paper:'two-sided'`；仅与 `stroke:'original-segment'` 搭配，参考横跨至少9px，其余可信来源、5–31px上限、路径和权限保持。它从参考每列两端各2行原图拟合线性底色，只提取更暗的残差，保留原尺寸列顺序及断续；目标的低频底色与细纹仍独立估计。省略保持旧q80去底色结果，未知值、错误组合或窄框原子拒绝；新增扫描计入原140M预算。两端若含饰边、阴影或其他墨迹，估计仍会失真，必须看参考和结果，不按变亮自动通过。页面标明“两侧底色取墨”，MCP解释依据与限制，同一严格v1包重放。另看实际断口、板头和线心；局部宽墨带减轻不证明底材暗带或隐藏结构已恢复。

原尺寸接缝选择来源相位时，只比较每端外三列的当前可信原图深色差；来源端部与可见原接头的线心在横跨方向最多3px配准，沿段内插该微移。无可信原接头时，手画路径中心及来源相位都属于推断，不把前序补图或保护像素作为原图。原尺寸列保持不等于完整结构恢复：可能将真实断口连上、丢板头、重复笔触、出现台阶，底色暗带也不由本方法解决。相位分数不授予结构或视觉通过。页面已采用路径标明“原尺寸二维接缝”，分析说明用途／限制，确切参考和字段随同一v1包重放；每步露底、100%／400%及空冷读分别核对。

取样和每个参考框必须整块位于可信同材质范围：不透明、未移除、未保护、未显式排除、未经前序推断，并避开后续仍在的物件。整个当前移除范围都不能成为别的分区的取证来源；未列出的家具及阴影仍须补排除。只在实际移除与当前表面交集并扣除保护区写入，路径不会授权修改可见范围或其他底材。失败报告含表面名／ID、参考坐标和原错误，优先回到该局部重新判断参考；不要放宽可信条件来使请求成功。

页面在“分区补底”的“底材类型”选择结构辅助，提供可审阅的“结构辅助JSON”编辑框和 JSON 载入／另存。可先“载入结构辅助到编辑框”，修改后“应用结构辅助并重放”；原图显示已采用的黄色路径和紫色参考框，已采用参数与理由也可展开阅读。JSON 上限64KiB；未应用文本只在编辑框暂存，跨电脑前先成功应用或另存。MCP 继续用最新 `generation` 调 `image_import_set_surfaces`，提交完整清单及同样的 `guided` 字段；不存在只靠文字或定位就采用结构的捷径。重放失败保留原结果，成功后再用 `image_import_analyze_repair`、实际露底图和原图重新审阅。

隐藏底色、细纹、自动连线与显式路径全部属于推断；线参考只能说明笔触来源，不能证明遮挡内真实走向、板头或家具细节。修改方向、路径、参考或理由同样改变输入摘要并使旧审核失效，工作包保存确切输入供冷恢复重放，普通工程不保存整份制作诊断。专家对样图的精确取样、多次调参或密集路径可交付为人工辅助版本，但必须记录实际投入，不能计作“无经验者简单辅助稳定通过”；后者仍按冻结预算独立试做。

真实手绘纹理还须解释参考的角色与长度：断续板缝、成对钉点、板头和装饰不能统称为可重复的“黑线”。整块参考可信只证明未混入禁止取证区域，不证明它适合铺过整条隐藏长缝；短段反复复制会重复钉痕，分段拼接又可能产生跳台。查看接头两侧是否仍为可见原图；前序补底即使像木板，也不是新的原始依据。全底材联合处理须另行验证共同上下文、每步实际写入权限和中间态，不能由最终背景的一张改善图推定已支持。当前整段板面移植及联合明暗研究仍未采用，继续使用实际工具已提供的严格配方，不把私有研究PNG冒充可重放工作包。

接头原图与前序补底的范围可用同一分析的`boundaryEvidence`查看：只统计本次实际可写补区外四邻接一圈，重复邻点仅算一次，先区分画框／材质之外、保护及当前其他移除，再列前序推断、取证排除和仍需核对的原图。它不读取RGB或alpha，未标记原图不自动获得可信颜色／材质身份；有前序推断也不证明接头一定错误。最多六个16px网格内的前序接头定位框，完整类别总数及未列前序像素仍保留，独立于常规24条冲突。每处`producers.step`为原拆出顺序的1基步骤号，不是透明图层顺序；同框可含多个步骤。

页面展开“补区接头依据”，可定位当前补图或对照原图遮挡；MCP布局列同一统计，补图青框标出前序接头。先回看对应前序步骤的露底及可信原图来源，再决定是否需要共同上下文整改；定位和分析不重算、不改范围、不把推断提升为新原图依据，也不自动恢复隐藏板头。统计应使用实际步骤前的来源快照，不能以结束时可变引用冒充；诊断脚本须即时复制需要保留的数组。

图层选择“按下层表面补底”，保存 `repair:'surfaces'` 和非空、无重复的 `repairSurfaceIds`；不能同时携带旧 `fills`。引用列表中靠前的表面优先，同一层的全部表面读取共同的修补前背景，不依次读取前一个表面的输出。所选表面必须覆盖全部实际移除像素，漏一处也拒绝整层；实际写入仍扣除保护范围，表面边界之外和移除范围之外保持。

已有表面可“用当前标注更新范围与取样”，或“把保护范围追加到取证排除”；后者合并保留旧排除，把当前保护标注另存为长期禁止取证范围，也可显式清除。并集仍须通过原蒙版和累计预算，失败保留原表面。删除已被物件引用的表面会拒绝，先调整引用再删除。页面修改与 `image_import_set_surfaces` 都须完整重放成功才采用；共用表面清单改变进入 `inputHash`，旧复核需重新检查裁片和露底。不要因多件共用就沿用旧审核，也不要把家具、阴影或前序未审补底选作新证据。

新增显式 `context` 完整纹理补片限单一底材、移除图框最多25万像素。取样宽高各须比移除图框多4px：算法根据可见且未保护的邻近像素选取一整块原尺寸平移补片，再作保守的低频颜色衔接，不用小块重复／镜像来填满宽洞。缺少可信边界或取样透明时拒绝；不恢复遮挡真相，也不保证板缝自然。旧配方缺少新字段时保持既有结果。

木板小洞可显式试 `structure`（固定 `structure-surface-v1`）：分别处理底色、可见窄缝与干净取样的细纹理；只在两侧线端相近且深度相称时跨洞接续，单侧短线渐隐。保护区不参与任何依据，洞内原颜色不可读。移除图框最多25万像素、取样最多100万像素，有限计算预算，不与 `fills` 混用；底材混合时先分开处理。它不保证还原隐藏板头，可能偏平滑或接线规整；务必检查真实移开画面。数值留出通过不等于纹理或全房间通过，不替换旧模式、不自动授予新手能力。

已知真值对照使用可见干净底材另存参考：先冻结位置、洞形、取样、保护、阈值，再遮洞；生成函数只得到损坏图与配置，输出冻结后才读参考评分。另换洞内颜色检验未偷读，保护／范围外须0变化。规则合成木板检查算法不变量，真实手绘木板检查纹理／板缝；二者分开报告。调试用样本与算法冻结后的留出样本分开，真值误差和实际未知背景视觉不能相互替代。具体本轮椅子案例结论从[主题证据](../archive/workspace-content-validation.md#image-item-workflow-20261112)读取。

阴影是否独立取决于使用目的和原图可辨程度。接触阴影可作为显式辅助层或经说明保留的固定外观；有方向的投影、吊灯光晕和环境烘焙光不得未经判断作为普通家具移动。地毯作为地面覆盖，检查“家具移开露毯、毯移开露地板”的顺序。书籍、棋盘、花瓶等按照预期独立编辑需求选择组合成员，遮挡不可见部分列为推断。

## 审核失效与撤销

审核至少绑定源图、上层输入、选区、裁片来源、算法与参数、候选 PNG、补底、共用表面清单和物理配置的确切内容。换图、修蒙版、换算法、调整补底／取样、改变共用表面或取证排除、修改遮挡顺序或增强候选后，受影响结果回到待审；范围外且完整输入闭包未变 item 的有效证据保留。只改无关 UI 视口不能让已审结果失效。工具根据实际输入闭包验证，不能信任调用方自行填入的“已通过”。

撤销恢复以前的内容并推进代次，旧在途结果仍然过期。恢复较早快照时保全当前工作；应用中的普通工程修改继续按现有保护点、原子事务、revision 与 CAS 执行。跨 session 恢复任务记录，不恢复旧进程承诺、网络请求或授权。未知计费任务保留真实请求 ID，不自动重发。

## 新 session 的恢复动作

1. 从仓库入口读取项目[制作总则](project-creation-workflow.md)、[当前排期](../07-roadmap.md#image-to-project-plan)和本流程，再打开用户指定的工作包或交接目录。只读取与该任务有关的资料。
2. 验证源文件、规范化源、资源及工作记录摘要。列出可用与缺失资料；缺失阻止依赖它的步骤，不破坏现有结果。
3. 读取最新有效断点，展示房间、暂定／实测比例、当前 item、有效审核、待审结果和下一步。历史会话截图仅作证据，不能覆盖任务真实状态。
4. 通过实际工具能力发现读取 schema 和当前代次。重放当前候选并与保存的蒙版／PNG 摘要核对；差异需要新候选和重新审核。
5. 对当前未完成步骤继续工作，保留其他已完成 item。交接前再次导出并冷读，记录最后成功状态及外部依赖。

## “简单辅助也能稳定完成”的开发验证

最低目标是没有这张图处理经验的操作者或新助手，在简短说明和有限纠错下产出能勉强通过视觉初审的 item。通过率要按实际任务报告，不能选择性删除失败，也不能用单次琴房手工精修替代稳定性结论。正式盲测、授权图及用户 P3 继续由09定义。

开发验证先覆盖钢琴、弧形沙发、棋桌椅、植物和直线柜五类。建议在运行前冻结每类两次独立尝试，其中至少一次从新的 session／任务状态开始；提供原图、目标范围、共同流程和工具，不提供前次精确轮廓、调参答案或已完成蒙版。辅助预算为一次目标说明、每个 item 最多两轮定点纠错、每轮最多四笔前景／背景或保留／排除标记；粗范围最多十二个锚点。记录实际笔画、锚点、纠错次数和有效操作时间。若更换此预算，须在开始前写明，不能见结果后放宽。

每次输出均留下原图局部、实际透明 PNG、黑白棋盘底、试移试转、补底、配方／工作包、运行和审核记录。复核者实际打开图像，逐项记“通过／需修改／源图无法判定”，并指出缺陷位置。至少一次断点应停在未完成选区，另一次停在待审候选；重开后继续完成，不能只验证最终 PNG 存在。

只有五类在冻结预算内的两次输出都通过对应视觉检查，才记录“该开发样本组稳定通过”；任何失败保留具体原因与下一步，不能以整体保存／冷读成功替代。需要大量细描、替换原画、直接提供成品蒙版或由熟悉样图的人接管时，结果可保留为人工版本，但该次辅助能力验证失败。开发样本通过不外推异画风成功率，也不替用户签 P3。

## 当前证据边界

原24项琴房裁片是被用户否决的失败对照；既有工程和库导入成功仅证明存取链。已确认问题包括粗糙边缘、蓝毯／地板残留、不自然补底和环境层误分类。不得从旧技术通过恢复其视觉通过状态。实际新增功能、支持范围和本轮自检结论由07及主题台账记录；本流程中的目标字段和阶段只有落到真实 schema、工具、持久化及图像证据后才算实现。
