## 地形正式测量方法与未实测目标

初始交互目标：笔画/控制柄显示响应p95≤100ms；随夹具冻结的≤256展开、24×18m标准岩岛单候选准备p95≤2秒；随夹具冻结的≤256展开、10×8km标准区域图单候选准备p95≤5秒；用户取消到输入恢复≤500ms。标准样本的实际物件/地形/曲线/图符数量和成本随测试夹具冻结，不能预先许诺48个树石再忽略其他成本。准备时间包含实际几何/预算检查，不包含首次缺失素材下载。以上均未实测，不能将Worker启用等同目标通过。

现有普通编辑100ms、保存/恢复/完整包/4K等门槛继续按[09](../09-quality-plan.md)与[34](#doc-34)检查。新增分别测：纯生成、资源准备、完整校验、预览绘制、保护采用和保存；给出总端到端时长，不能仅报告最快子阶段。

正式性能冻结代码、素材、输入、设备、浏览器和构建。至少包含场景小图、场景大范围、区域图和已有大量人工内容上的局部重生成四组；每组三轮、每轮30次固定操作，记录p50/p95/max、长任务、取消、内存与实际拒绝。负载与操作有界且真实，不把保护上限当标准测试大小。

正式测量独占运行，不并行浏览器、构建、单元、诊断或模型任务。诊断profile与正式分布分开；旧视觉v2或完整v1数字不外推到地形v3/v4。

### 2026-10-29：单条历史记录的同事务内容复用

静态调用链发现，选中单条命名/自动快照读取，以及快照改名/删除时，当前工程与历史记录会在同一IndexedDB事务中分别执行严格内容校验和hash。上述路径现接入已有事务级精确内容表：仅当完整规范JSON相同且处于同一事务时复用已成功结果；每条记录仍检查自身封套和声明hash，不同内容或后续事务仍完整重验。许可正文校验与全库预算扫描也改为复用同一UTF-8字节数组完成SHA-256和字节计数，值在单次校验内使用，不持久化。

公开保存、预算扫描、保护CAS、资源绑定、`loadSnapshot`/`loadAutomaticSnapshot`的实际字节/许可装配及事务后的完整工程验证均保留。`listSnapshots`和`listAutomaticSnapshots`继续逐项独立校验，避免一次列表读取同时保留多份唯一的大型规范JSON；这部分是否值得优化需结合当前profile与峰值内存证据决定。

仓库与许可相关定向测试`repository.test.ts`、`image-bytes.test.ts`共27/27，覆盖同事务同内容复用、各次读取事务重新校验、旧hash下历史内容变更拒绝及图片/许可字节完整性；`npm run check:shared`（122个源码模块）和`npm run build`通过。后续同输入复测及本轮规范JSON单次hash的实现与结果见下节。
