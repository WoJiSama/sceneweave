# 项目制作总则

适用于地图生成、已有场景局部编辑、素材和图片item制作。按当前用户目标和实际工具推进，普通工程保存正式内容，任务/草稿/工作包保存本次进度。已完成能力见[功能清单](../completed.md)，未解决问题见[剩余事项](../roadmap.md)。

## 先发现真实能力

仓库助手先读[AGENTS](../../AGENTS.md)。制作时使用`node tools/harness/sceneweave.mjs workflows`读取简短目录，再按`--id`及`--step`、`--schema`或`--effects`查询相关详情。图片MCP独立核对`sceneweave_workflow`与实际tools/list。

<a id="shared-workflow-capability-discovery"></a>
共享流程正文和元数据归[workflows](../../workflows/catalog.json)，应用默认指引归[project-workflow.ts](../../src/shared/ai/project-workflow.ts)。工具schema和权限归执行器，目录不授予新权限。普通应用聊天尚未接线图片执行；没有实际工具或看图能力时准确说明，不能声称已切割、审核或采用。

## 完成一项制作

1. 明确用途、尺寸、范围、已有成果和交付物，核对来源许可、外发条件及预算。
2. 优先现有高层能力形成可审阅候选；先布局/通路/支撑，再材质、布景和氛围。
3. 检查实际几何和资源，再看真实图像。局部修改保留范围外内容、人工移动/删除、锁和秘密。
4. 按已有授权推进修复。连续候选没有改善时停下当前路线，保留可用结果和具体缺口；不降低目标或追加无限尝试。
5. 正式采用沿同一保护、原子事务及撤销链，重检基线、依赖和锁；失败不替换主工程。
6. 保存所需工程/个人库/制作包，从真实保存结果重开，交付可打开文件并简述结果和缺陷。

简单任务只执行有关步骤，不为每一步新增报告或模型请求。缺口先判断属于共享能力、内容制作还是画面取舍，不把实验产生的新依赖自动升为产品需求。

## 任务与接续

已有任务绑定流程ID/版本/摘要、确切输入和最后有效断点。恢复先核对当前定义、实际结果和宿主工具；保留unknown和累计用量，不自动重跑未知计费请求，也不继承旧外发授权。

地图/局部编辑使用现有生成器和有限命令。图片任务按[图片步骤](image-item-workflow.md)保留原像素、选区、推断补底和工作包；切后处理先保全原件，再按实际缺陷选择方法。插值不恢复未知细节。

交付说明实际做成什么、产物位置和未解决部分即可。实现、技术检查、看图和用户签收如实区分；没有运行的测试或没有打开的图像不能写成已通过。具体检查方法见[testing](../testing.md)。
