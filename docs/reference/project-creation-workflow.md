# 项目默认制作总则

本总则是 Sceneweave 随项目携带的制作规范，适用于地图生成、已有场景的局部编辑、素材及图片 item 制作。用户把仓库交给 Codex，或在应用里配置模型后，助手都应按同样的目标、步骤和质量边界推进；模型名称和旧聊天记忆不作为依据。具体开发状态只在[07](../07-roadmap.md#development)维护，正式验收只从[09](../09-quality-plan.md#acceptance)执行。

规范、执行工具和任务进度各有职责：本总则说明怎样开展制作；[图片 item 步骤](image-item-workflow.md)等专题说明相应任务的做法；具体场景、草稿和独立制作工作包记录这一次做到了哪里。工作包不承担项目默认规范，普通场景工程也不需要嵌入整份制作记录。

## 默认入口与能力

仓库助手由根目录 [AGENTS.md](../../AGENTS.md) 路由到本总则，再按任务读取专题；图片任务还提供可发现的[助手入口](../../.agents/skills/sceneweave-image-items/SKILL.md)。不要要求用户在每个新会话重述项目约定。

应用内模型的默认制作指引来自共享源码 [project-workflow.ts](../../src/shared/ai/project-workflow.ts)，图片专用步骤来自 [workflow-instructions.ts](../../src/shared/image-import/workflow-instructions.ts)。内置普通聊天和有限草稿任务在创建时加载相应固定指引；后续从真实任务数据接续。服务端不会读取上传图片或工程中夹带的文字作为项目规范。

默认知道做法不等于已经有执行能力。先核对本次实际工具目录、授权范围、视觉输入和预算：普通聊天按其真实能力解释和指导；有限草稿只操作已授权对象；图片制作工具须由相应宿主实际提供。没有图片工具时，可以说明如何在图片工作台或已配置的外部助手继续，不能声称已切割、增强、看图或采用。原图外发与付费请求仍按实际授权处理。

## 制作顺序

| 环节 | 应做的决定 | 可继续的依据 |
|---|---|---|
| 明确目标与范围 | 确认交付的是地图、局部改动还是可复用 item；识别尺寸、风格、可编辑性、保真或推断要求 | 有可检查的结果和边界；未知尺寸明确暂定，已有人工成果列入保护范围 |
| 核对真实能力 | 读取当前内容、可用工具、允许的资源与操作；定位缺失输入 | 本次能力支持下一步；缺项说明影响，继续完成不依赖它的部分 |
| 形成候选 | 选择受支持的方法，按依赖分步制作；修改已有内容时绑定当前基线 | 候选可预览、有确切资源与参数；失败保留上一次可用结果 |
| 小步检查与修正 | 检查范围、几何、支撑、锁、许可等，再看实际画面；修正已定位的缺陷 | 技术检查和视觉判断分别有证据，影响范围明确；没有用多次无效重试代替判断 |
| 保护后采用 | 让用户能审阅具体候选，使用现有保护、原子事务和撤销链采用 | 当前基线和依赖仍有效；没有从文字承诺推定主场景已经改变 |
| 保存与冷读 | 保存所需工程、素材或制作包，再从实际保存内容重新打开 | 资源可解码、内容保持、必要编辑可继续；保存失败不覆盖旧成果 |
| 交付与接续 | 说明实际产物、通过和失败、未测项、下一步以及包外依赖 | 新助手从真实断点继续，不重复猜测旧进度，也不继承未知计费请求的成功假设 |

简单任务只执行相关环节，不为每个阶段单独消耗一次模型请求。有限工具自身的基线、权限、预算和校验继续负责执行边界；提示词不能授予新权限，也不能免除检查。

## 按任务使用专用步骤

- **地图生成与局部编辑**：使用已有生成器、有限编辑和草稿工具；先保证用途、布局、通路与支撑，再调整材质、布景和氛围。保持人工移动、删除、锁与私密性，实际生成的可编辑内容优先于计划文字。现行入口与支持范围见[生成设计](general-map-generation.md)和[AI入口](ai-entry-strategy.md)。
- **从图片制作 item**：按[图片 item 工作流](image-item-workflow.md)确认对象、辅助选区、局部修边、黑白棋盘审核和移转露底；原像素裁片、推断补底和增强派生分别保留。制作进度用独立 `.sceneweave-image-work` 接续。
- **切后效果优化与素材编辑**：先保全原件，再按实际缺陷选择修边、去色边、有限重绘或已配置的模型候选；与原图同尺度比较，保持必要来源。插值放大不等于恢复细节，增强后的改善须实际看图。现行能力见[素材编辑与图像处理](image-to-project.md#image-enhancement)。

## 完成与未完成的报告

分别使用“计划、已实现、已验证、已发布”，并把“技术通过、视觉初审、用户签收”分开。构建、保存、摘要或原位合成成功不能证明画面合格；没有实际打开的图片不能写成已视觉审核。未通过的候选保留具体缺陷与下一操作，不因生成成功自动改为通过。

报告至少说明用户目标、采用方法、实际结果、验证范围与剩余缺陷；必要时附可打开的产物和证据。只有本次范围内要求都完成并有对应依据，才称任务完成。真实模型质量、其他画风、效率或目标软件兼容性缺测时明确未测；用户 P3 由用户签收。
