# AI入口与地图能力复用方向

2026-11-09用户确认。本文记录设计方向与接口交接；各项实现、自检与待办状态只归[07](../07-roadmap.md#ai-entry-development)，**接口可调用不代表真实模型收益已经通过**。产品范围归[01](../01-product.md#ai-product-direction)，AI权限归[05](../05-ai-and-generation.md#ai-entry-direction)，全部验收归[09](../09-quality-plan.md#ai-entry-acceptance)。

## 1. 决策与目标用户

Sceneweave优先提供可编辑地图、可靠保存与导出，以及可预览、可撤销的修改。下一步暂停扩建通用页面agent，优先把地图能力提供给本地harness，再用少量页面AI辅助验证普通用户收益。完整内置AI独立成图不再作为首个可用版本的前置条件；仍保留为后续能力目标，其历史失败不改记通过。

本地harness指用户在自己机器上运行的agent执行环境。开发者和技术型创作者可用它规划、调用工具和批量制作；普通主持人继续通过页面完成生成、编辑、保存和输出，clone源码不是普通用户使用地图或未来轻量AI的必要步骤。开发期可先在仓库内验证适配器，面向普通用户的安装与分发体验另行实现，不能把开发命令当作已完成的产品入口。

| 继续投入 | 暂缓扩展 | 保留并维护 |
|---|---|---|
| 生成器质量、语义能力接口、完整工程交接、本地harness适配、自然语言填参数试点 | 通用多轮整图agent、更多provider协议与模型矩阵、复杂自主恢复、无限续作与自动切换渠道 | 现有AI任务和草稿、明确授权、诊断、差异审阅、保护采用、撤销、历史与导出；已暴露入口的数据/权限/恢复缺陷仍需修复 |

暂停扩展不等于删除现有入口或旧任务。后续是否调整菜单显著性、标记实验或退役入口，须在对应实现项中明确迁移和成果保全方式。

## 2. 判断依据与限制

林中哨站实测表明，页面链路可以完成请求、工具调用、草稿校验、保护采用及导出，但逐实体构图仍大量消耗在坐标参数、地形支撑和覆盖冲突上。已有一次GLM任务仅留下三个房间；修复后另一次任务在300秒内只留下一个房间和三个地形区块，完整需求未完成。此前修复和中断试跑见[AI台账](../archive/ai-validation.md#authoring-recovery-20261109)；后续成功采用及导出的本机试跑原始记录位于`work/codex-vs-page-ai-20261109/glm-page-2026-11-09T05-33-14/`。本机试验目录被Git忽略，不作为发布附件。

Codex成图过程使用了读源码、脚本制作和多次验证，模型、工具及时间预算也与页面不同。这些样本不能证明本地harness天然更快或某模型更强；工具schema字节减少同样不证明生成提速。新方向的依据是减少模型需要猜测的领域细节、复用已有生成能力，而不是用失败延迟与成功成图时间相除。

当前室内、森林、火山、有限混合已经具有程序化生成入口，但[`domainGenerationCapabilities`](../../src/shared/generation/execution.ts)仍返回`aiTools:[]`。本地生成能力存在不等于模型已经有权调用；首个外部适配以独立、显式授权的[语义能力](#semantic-entry-contract)接入，不扩大既有页面创作或程序化HTTP授权。

## 3. 分工：入口、执行环境与地图能力分别负责

| 层 | 责任 | 与现有实现的关系 |
|---|---|---|
| 页面编辑器 | 当前工程、画布/选区、参数确认、候选预览、诊断、采用、撤销与导出 | 复用现有Workspace及生成模块；保留无模型的完整制作流程 |
| 页面轻量AI | 将自然语言转成当前生成表单支持的结构化参数，标出未支持要求和待确认值 | 首个试点只填写参数草稿，由用户检查后触发现有生成流程；不取得任意工程写权限 |
| 本地harness适配器 | 向agent暴露精确能力、受授权摘要、有限请求和结果；负责本地输入输出交接 | 优先一个薄CLI/SDK适配器；MCP可作为后续包装，不要求同时建设多套入口或新的通用agent框架 |
| 共享地图能力 | 参数解析、布局、真实墙门、地形支撑、路线净宽、物件分布、依赖与预算检查 | 复用共享领域生成器、应用候选和事务；不在适配器内另写一套地图规则 |
| 平台适配 | 资源字节/像素校验、实际渲染、完整包与存储 | 使用现有平台端口；纯共享层仍不依赖DOM，Node入口不能以元数据校验冒充真实图片验证 |

模型负责用途、布局偏好、内容选择和修改意图。程序负责能够确定计算的几何、身份分配、支撑、依赖和约束。高层请求应表达“生成三房间建筑并连接入口”，不要求模型先猜每条墙的ID或逐点拼接道路。

目标流程：自然语言或明确参数 → 能力与输入校验 → 现有生成器 → 带诊断的完整候选 → 页面审阅 → 保存/采用。有限局部修改复用同一条候选链，但只在对应权限和人工保护已接通后开放。

## 4. 第一条交付路径

首先打通一个已支持的林中建筑混合生成样例。范围以现有混合配方能力为准；原林中哨站要求中不支持的营地元素、房间用途或空间约束必须列为缺项，不能缩减要求后声称原题完成。后续领域逐个按实际能力接入，不把一次接通写成全部场景支持。

### 本地harness

1. 用户明确选择本地完整工程或空白输入、固定素材和允许的生成范围；读取能力及公开摘要。
2. agent提交语义参数。适配器返回规范参数、诊断和候选；非法或未知能力明确拒绝，不自动改成底层代码执行。
3. 通过已有资源/渲染端口完成真实校验，输出独立完整工程和预览。新工程交接沿新建/冷读流程；已有工程修改必须另有绑定原基线的提案与依赖闭包，不能将导入整份文件等同于覆盖当前工程。
4. 用户在页面审阅并继续编辑。首次可采用文件往返，后续有实际需求再设计实时连接，不能假设harness能直接读取浏览器IndexedDB。

若适配器暂时不能在Node完成某项像素或渲染检查，可以使用明确的本机浏览器适配步骤，但该检查完成前不能将候选标为可采用。导出包保存完整实体/资源，不能只交seed、截图或自报“验证通过”。

### 页面轻量AI

用户输入需求后，页面展示解析得到的生成参数、采用的默认值、歧义和未支持要求；用户可以改参数，再运行原生成器。更改参数只更新表单草稿，不改当前工程。AI解析失败时保留用户原文和参数草稿，用户可直接填写表单继续。

首个试点不增加自主多轮制作。基于选区的密度/家具调整、实际诊断解释、主持人注记属于后续候选能力，只有前一试点收益成立才考虑扩展；注记与素材仍遵守现有秘密和固定来源约束。

## 5. 接口交接与守卫

以下是共同语义合同；首个最小入口的准确能力和包装见[第8节](#semantic-entry-contract)。其他领域/当前工程修改仍须按[05](../05-ai-and-generation.md#domain-generation-authority)补齐能力协商、授权及累计预算，不能直接把当前程序化服务当作已开放AI工具。

| 交接 | 消费 | 产出与拒绝边界 |
|---|---|---|
| 能力与上下文 | 实际执行端能力、用户明确选择的工程/素材/范围 | 有界能力清单、公开摘要与参数说明；不默认外发GM注记、历史或整包 |
| 生成/局改请求 | 规范参数、确切基线、允许操作、固定资源身份和已登记预算 | 确定性结果或明确错误；高层一次调用仍按实际展开/计算计量，不能借包装或拆批绕额度 |
| 候选 | 真实资源闭包、领域结果、实际读写依赖和诊断 | 精确候选身份、差异、缺项及预览；无效候选保留当前工程，过期基线不能覆盖新编辑 |
| 交付/采用 | 通过全验的完整包或绑定当前工程的候选 | 新工程保存冷读后打开；当前工程保护/CAS后一次采用及撤销；应用层拥有最终提交 |

外部harness的模型账户、计费和会话由所选执行环境管理，Sceneweave不假设订阅包含某API费用，也不承诺跨执行器共享额度。现有16请求/64工具/300秒及unknown规则按原任务继续生效；新适配器不能清零或恢复旧unknown流程。算法计算和最终采用保护仍由项目执行器核算。

本地有完整工程文件不等于同意上传其中全部内容。模型出站内容继续按明确授权过滤，真实图片另行授权，密钥不进入工程或日志。适配器只能保证经自身入口执行的权限边界；若用户给外部agent任意shell/文件访问权，那属于用户选择的本地执行环境，不能宣传为受Sceneweave工具沙箱完全约束。

## 7. 评价与继续条件

开发任务只在[07](../07-roadmap.md#ai-entry-development)排列；开发期做与修改相关的最小自检。正式评价在[09入口比较](../09-quality-plan.md#ai-entry-acceptance)执行，对照参数表单、页面轻量AI和本地harness，记录从需求到同等完成度可编辑地图的时间、人工修正、成功/缺项及实际或未知用量。

基础地图质量由生成器与素材负责；没有收益证据时，页面AI保持实验范围并继续改进基础能力。只有某个窄任务能稳定降低操作或修正成本，才扩展对应入口。完整整图agent的恢复投入另作后续决策，历史真实AI矩阵保留待验，不用小试点或本地脚本成功替代。

## 8. 首个语义入口合同

纯参数及能力owner为[`shared/generation/semantic-request`](../../src/shared/generation/semantic-request.ts)，应用执行owner为[`workspace/semantic-generation`](../../src/application/workspace/semantic-generation.ts)，本地薄包装为[`tools/harness/sceneweave.mjs`](../../tools/harness/sceneweave.mjs)。运行命令归[贡献说明](../../CONTRIBUTING.md#local-map-harness)。能力ID`sceneweave-forest-building@1`与素材选择`builtin-mixed-forest@1`分别标识本入口和固定内容范围，不是新的工程格式或旧AI任务协议。

请求严格为`{capabilityId,target:"new-project",parameters}`；`parameters`共用当前混合表单：`title`、`environment:"forest"`、整数毫米`widthMm/heightMm`（20000–100000）、`seed`、`roomCount`（1–4）、`purpose`、`furniture`和`vegetationMultiplier`（0–2）。所有字段必填且拒绝未知字段。能力表输出同源JSON Schema、规范样例与限制；不支持逐房间用途/空间关系、任意建筑位置或帐篷/篝火，营地只预留活动空地并连接道路。生成报告如实保留家具/植被缺项，不能将本样例写成原完整林中哨站题目通过。

宿主先严格捕获并规范化请求，再将能力ID、素材ID和确切`requestHash`作为独立授权传入；注册预算由宿主选择，模型JSON不能提供授权、路径、资源端口或任意预算数值。应用复用`prepareGenerationIntent → prepareDomainProject`，按实际完整结果、资源和执行耗时检查预算。单次SDK/CLI只新建一个工程，无自动重试或旧任务恢复；若以后增加会话或批量调用，须先提供失败计算也不清零的累计执行账本，不能把多次独立调用冒充同一流程续作。

CLI通过独立回环服务和无用户profile的浏览器提供真实资源/像素与Canvas能力；生成后导出完整包、冷读并渲染玩家PNG。目标目录必须新建，文件以独占方式写入；只有落盘SHA复读、另一页面完整冷导入、工程hash和预览RGBA一致且仍在预算内，`result.json`才标`complete`。失败记录保留，已输出的部分文件不授予成功/采用凭证。默认2048长边、实际引擎、各阶段时长和用量都写入结果；该时长不是正式性能或真实AI成图比较。

页面文字解析复用普通对话任务而非开放生成工具：只发送用户文字及当前生成表单，`context:null`、无工程/图片/创作授权。严格解析完成任务的参数补丁，再以同源schema求得完整参数，展示补默认项、歧义、模型未支持项和固定能力限制。用户确认填入只改表单，原预览/保存按钮仍由用户另行触发；表单已变更的迟到结果不覆盖新输入。原任务与实际用量保留；创建响应未知时按原`clientRequestId`精准只读查询，不依赖最近任务列表，不自动重新调用模型。此恢复需要对应版本的任务服务；旧后端拒绝查询时保留原请求，不以重连创建代替升级。
