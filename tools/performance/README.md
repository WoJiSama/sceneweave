# 性能工具

性能判断与记录方法见[检查方法](../../docs/testing.md#performance)。本目录保留可运行工具和必要基线，不在这里累计历史测量、候选否决或完成报告。工具存在不代表当前性能已经通过。

## 选择入口

| 工具 | 用途 |
|---|---|
| `run-current-formal.mjs` | 当前完整工程的容量/正式性能矩阵 |
| `run-ocean-formal.mjs` | 海洋专项容量和交互；当前海洋会话在使用 |
| `prepare-production-pair.mjs` / `run-production-pair.mjs` | 在隔离副本中准备及运行同输入前后对照 |
| `run-storage-scale.mjs` | 按工程数、历史长度和资源规模拆分保存成本 |
| `run-history-cause-analysis.mjs` | 历史/存储组件的粗阶段归因 |
| `run-content-transaction-analysis.mjs` | 最终写事务、原生事件和缓存诊断 |

具体参数、默认值、所需输入及输出目录规则见相应脚本。运行前核对使用的源码、正常产物和真实输入；对照基线补丁只在隔离目录应用，不反向修改日常工作区。

## 当前完整 v1

先用 `prepare-current-formal.mjs --output ABS --mode capacity` 生成建筑、自然、混合各 500/2000 个完整 Prop 的固定输入。准备过程保存源码与资源 SHA256 清单，严格验证实际字节、像素和许可，并重核输入未漂移；失败或未完成的清单不能用于运行。

用正常 `npm run build` 产物运行 `run-current-formal.mjs --fixtures ABS --output ABS`。默认完整轮数也只记为诊断；确认原会话及其他构建、测试、浏览器没有竞争后，传入 `--exclusive-window "实际确认的独占窗口说明"` 才记录正式测量。参数用于保存实际协调证据，不能代替确认。`--smoke` 只执行少量诊断；`--profile` 为各次领域提交操作（独立编辑、分组采用、拖拽采用及撤销重做）保存 CDP CPU 制品，覆盖提交及保存/显示等待，始终按诊断处理。

每个完整 run 包含字段编辑、实际画布与列表选择、平移缩放、三段各 30 次真实指针移动的独立物件拖拽、采用及撤销、保存冷重开和双受众 4K PNG。拖拽使用相同固定输入，在已知空带内移动 -800mm，再核对完整内容和资源。拖拽帧、视口帧与字段提交分别报告；未测操作不由它们代替。Windows 默认接现有 Working Set/私有提交采样，macOS 使用进程树 RSS；GPU 内存仍未测。

需要安全交接时，启动前传入 `--stop-file ABS`，路径须在冻结的输入、源码、构建和工具目录之外。创建该文件后，运行器在当前有界操作结束、下一个操作开始前停止，保留中断结果及输入复核，并正常关闭自己启动的采样器、浏览器与 HTTP 服务，退出码为 130。不要通过修改冻结输入来请求停止，也不要终止其他会话的进程。

## 测量规则

- 不与其他浏览器、测试或构建并行，保留前后相同设备、输入、操作及采样方法。
- 正常构建与插桩诊断分开；低样本、受干扰及未完整结束的结果如实说明。
- 记录完整保存/重开和PNG一致性，不能删历史、缩小素材、漏资源或省验证来换速度。
- macOS进程树RSS、Windows Working Set/私有提交和页面heap分别报告；缺样为缺样，不记0。
- `baselines/`及`experiments/`保存的补丁不会自动进入产品；使用前先检查补丁仍适用于当前代码。
- 测量输出放忽略目录。修复有实际复现的问题后选择影响范围复验，无需为每个微优化建独立编号台账。
